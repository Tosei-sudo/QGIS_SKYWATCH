# ビューアとの違い・できなかった点

参照実装: Tosei-sudo/browser-image-enhancement `8a8563d`（`usecase/image-viewer`）。段階ごとに追記。

## 段階 1（骨組み）

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| 設定ファイルの形式 | JSON（README に「コメントは書けません」） | JSON と JSONC（`//`・`/* */`・末尾のカンマ） | 指示書どおり。ビューアの `config.json` はそのまま読める |
| 読む項目 | 全項目 | `satelliteCatalogs`・`sensorCatalogs`・`planStores`・`groundStations`・`cloudForecast`・`imageCatalogs`・`observationStores`・`observationVocabulary`・`arcgisPortals` のみ（他は無視、問題にも出さない） | 共用のため |
| サインイン | `arcgisPortals` の OAuth（PKCE、ポップアップ） | QGIS の認証設定（`authcfg`）をサービスごとに選ぶ。`arcgisPortals` は読み込みと検証のみ | QGIS の OAuth2 / ESRI token 認証に任せる |
| `token` と認証設定 | `token` があればそれ、なければサインインのトークン | 認証設定を選んだサービスは `token` を送らない | 二重送信を避けるため |
| 全件読み込み | `resultOffset` で `exceededTransferLimit` が立つ間 | 同じ。加えて、ページが満杯なら次も読む。ページングできないレイヤーは ID を先に読み `maxRecordCount` ずつ取得 | 指示書「`maxRecordCount` を超える件数はページングで全件読む」 |
| 通信 | `fetch`（GET か POST） | すべて form POST（`f=json`）、`QgsBlockingNetworkRequest`（QgsTask 内のみ） | トークンを URL に出さない・QGIS のプロキシと認証に従う |
| ローカル保存 | IndexedDB・localStorage | ユーザープロファイルの `satellite_observation/observations.gpkg`（`observations`・`checked_areas`・`taxonomy`・`taxon_photos`） | 指示書どおり。属性名は Esri と同じ |
| ローカルの分類体系 | localStorage に保存先ごと | `taxonomy` テーブルに `STORE`（保存先の label）と `ROW_KEY` の列を追加 | 1 つのテーブルで保存先ごとに持つため |
| 日時（ローカル） | ms の数値 | GeoPackage の DATETIME（UTC の ISO 8601） | QGIS・ArcGIS Pro で日時として扱えるように |

## 段階 2（撮像計画の中核）

数値の一致は `scripts/compare_viewer/compare.py` で確かめる（ビューアの `imaging-plan.ts` を esbuild で束ね Node で実行し、同じ条件をプラグインの core で計算して突き合わせる）。7 ケース（ISS の 1 週間・6 地点、サンプル 2 機の 14 日、条件の絞り込みと地上局、面の組み合わせ、優先度と地点の集約、撮像モード、架空の 20 機の 1 週間）で機会の件数・時刻・角度・被覆・組み合わせのパスはすべて一致し、差は 0（時刻 0.000 s・角度 0.00000°・被覆 0.000%）。

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| SGP4 | satellite.js 7.1.0 | `sgp4`（2.27、C++ 版）。なければ同梱の純 Python 版（`ext/sgp4`、同じ 2.27 の Python 実装） | 指示書どおり。どちらも WGS72・同じ結果 |
| 太陽位置・恒星時・座標変換 | satellite.js の `sunPos`・`gstime`・`eciToGeodetic` | 同じ式を Python に移植（`core/plan/orbit.py`） | 外部の暦ファイルを使わず閉域で動かすため（Skyfield は不要） |
| 速さ（20 機 × 7 日 × 1 地点） | 約 0.2 秒 | `sgp4`（C++）あり: 約 0.2 秒。同梱の純 Python 版: 約 3 秒 | 純 Python の SGP4 が遅いため。1 秒以内は `sgp4` を入れた場合だけでよい（2026-10-27 に決定） |
| 計算の実行 | Web Worker（ダイアログを閉じると停止） | QgsTask（ステータスバーに進捗、そこかドックの「取消」・Esc で取消） | QGIS の作法 |
| 衛星カタログの読み込み | 1 回の問い合わせ（上限を超えたら「先頭 n 機のみ」） | 全件をページングで読む | 段階 1 の Esri クライアントの方針に合わせた |
| 1 つの面の狙う点 | OpenLayers の `getInteriorPoint` | QGIS の `pointOnSurface` | 面の内側の点の選び方が少し違う。点・複数地物・セル（面積の標本）は同じ |
| 面のセル | OpenLayers の `intersectsCoordinate` | 同じ格子、内外判定は自前の偶奇判定（穴を除く） | 境界上の点の扱いだけ異なりうる |
| 対象の選び方 | 選択中の地物・各レイヤー・地図でクリックした地点 | 同じ。「選択中の地物」はアクティブレイヤーの選択。地点は「地図で指定」を押してから地図をクリック | QGIS では地図のクリックを他のツールと取り合うため、明示的にツールを切り替える |
| 地図の表示 | OpenLayers のオーバーレイ | ラバーバンドとキャンバス上の文字（プロジェクトにレイヤーを足さない） | 計画を開いている間だけの表示のため |
| 衛星名の表示 | 衛星の点の上 | 衛星の点の右 | シーンと重なりにくくするため |
| レイヤーとして追加 | Polygon か MultiPolygon（地物ごと） | すべて MultiPolygon・WGS84 のメモリレイヤー。`time` で時系列コントローラーが効く | QGIS の 1 レイヤー 1 形状型のため |
| 並べ替えの文字列 | `Intl.Collator('ja', {numeric: true})` | 数字を数として比べる自然順（それ以外は文字コード順） | ICU の日本語照合順は使わない。かなと漢字の並びが異なりうる |
| CSV | BOM 付き UTF-8・CRLF | 同じ列・同じ書式。ローカル時刻は OS のタイムゾーン | — |
| ショートカット | ダイアログ内の Esc で閉じる | ドックにフォーカスがあるときだけ Ctrl+Enter で計算、Esc で取消 | 指示書どおり |
| 右クリックの「ここを撮像計画」 | 地図の右クリックメニュー | 同じ（QGIS の地図の右クリックメニューに追加。その地点を対象にして計算） | — |
| 3D 表示 | あり | なし | 移植しない（2026-10-27 に決定） |
| 段階 4 以降の機能 | 保存と追跡・通知と予定表・雲量予報・ペア・再訪間隔・移動目標 | 段階 4・5 で追加（下の表） | 段階分けのため。地上局（`groundStations`）がある場合の「受信見込み」は中核が求めるので、段階 2 から一覧・CSV・レイヤーに出る |
| 同梱 sgp4 の変更 | — | NumPy 2.5 で非推奨になった `.shape` への代入を `reshape` に置き換え（2 か所） | 警告をなくすため。計算は同じ |

## 段階 4（保存・追跡、予定・通知、雲量予報、地上局、ペア、再訪間隔マップ）

数値比較（`compare.py`）にステレオペア・干渉ペアと再訪間隔マップの 2 ケースを足し、9 ケースすべて一致（ステレオ 400 組・干渉 19 組の衛星・時刻・交会角・垂直基線、再訪間隔 25 セルの回数・平均間隔・最長の待ち）。

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| 保存した計画 | 「保存した計画」ダイアログ | 「保存した撮像計画」ドック（メニュー・ツールバー、撮像計画ドックの「保存した計画…」から開く）。一覧・撮像の表・地図の色分け・「撮像を確認」・「計画を削除」（2 回押し）は同じ | QGIS の作法。通信はすべて QgsTask |
| 撮像の状態の変更 | 表の行ごとの選択欄 | 撮像を選び、表の下の「状態」で変更 | 表の中の選択欄は Qt では扱いにくいため |
| 撮れた画像を開く | ビューアで画像を開く | 画像カタログで画像 ID を探し、`fields.source` の値をラスターレイヤーとして追加（http(s) は `/vsicurl/`、ほかはローカルパス）。観測記録と同じ `image_layer()` で開き、画像 ID と撮像日時（時系列）をレイヤーに付ける | 認証の要る画像は、画像のサーバーに「設定…」で選んだ QGIS の認証設定の ID だけをソースに書いて開く（トークンはプロジェクトファイルに残さない）。token しかないカタログは、QGIS の認証設定（API ヘッダー `X-Esri-Authorization: Bearer …`）を作って選ぶ |
| 撮像前の通知 | ブラウザ（localStorage）に保存し、ビューアを開いている間 20 秒ごとに確認。通知センター（「通知」とアプリのバッジ）に出す | QgsSettings に保存し、QGIS の起動中 20 秒ごとに確認。メッセージバー（「移動」で撮像範囲へ）とログ（「撮像計画」タブ）に出す | QGIS には通知センターがないため。デスクトップ通知は使わない点は同じ |

| 地上局 | 受信見込みの列 | 段階 2 で対応済み（中核・一覧・CSV・レイヤー） | — |
| ステレオ・干渉ペア | 表示の切り替えと条件の入力欄 | 同じ。ペアの行を選ぶと 2 回目の撮像範囲に「2」を付け、「範囲へ移動」は 2 回目も含める | — |
| 再訪間隔マップ | Web Worker で格子のセルを計算。144 セル以下ならすべてのセルに最長の待ちを表示 | QgsTask。36 セル（6 × 6）以下ならすべて、それより多いときは選んだセルだけに表示 | キャンバス上の文字は縮尺で縮まず重なるため |

| 「詳細条件」の行の表示 | — | 折りたたみを開くと、当てはまらない行（優先度・雲量予報）を隠し直す。優先度は折りたたんでいても効く | 段階 3 で見つけた不具合（開くと隠した行が出る・折りたたむと優先度が効かない）の修正 |

## 段階 5（移動目標撮像計画・衛星パス）

数値はビューアと突き合わせ済み（`scripts/compare_viewer` の moving-ships・satellite-track-moment・satellite-track-week。時刻・角度・被覆・誤差円の中心と半径・軌跡の位置が一致）。

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| 移動目標の読み込み元 | 任意のレイヤー、または移動体フィード（AIS の WebSocket など）の航跡 | 任意のポイントレイヤーのみ（マルチポイントは最初の点） | 指示書どおり、フィードは初版の対象外 |
| 属性の自動判定 | mmsi・timestamp・cog・sog・heading などを名前で判定 | 同じ表（`NAMES`）。日時型の属性は UTC のミリ秒として読む。文字列の時刻は時差なしなら UTC | — |
| 「移動目標撮像計画」 | ダイアログ（モーダル） | メニューの「移動目標撮像計画…」から開くダイアログ（モードレス）。項目・既定値（72 時間・6 時間・0.5 km・0.5 km/時・10%）は同じ | 地図を触りながら使えるようにするため |
| 存在予測を追加 | 1 つの一時レイヤー（円と予測航跡が混在） | グループ「存在予測 …」に 2 つのメモリレイヤー: 「存在予測」（円、`time` で時系列コントローラーが効く）と「予測航跡」（線）。日付変更線で分割 | QGIS の 1 レイヤー 1 形状型のため |
| 計画の計算 | Web Worker で 1 段目、メインスレッドで 2 段目 | 両方とも QgsTask（取消可） | QGIS の作法 |
| 位置の誤差の列 | 「最後の AIS 報告から …」 | 「最後の報告から …」 | AIS 以外の報告も読むため |
| 選んだ回の誤差円 | 地図に円 | 同じ（オレンジの破線） | — |
| 衛星パス | ダイアログ（地図と 3D 表示） | 「衛星パス」ドック（地図のみ） | 3D は移植しない（2026-10-27 に決定） |
| 衛星パスの衛星 | 撮像計画と同じカタログ・サンプル | 同じ（撮像計画ドックが読んだカタログを共有。未読なら読み込む）。色は衛星の一覧の各衛星の前に表示 | — |
| 衛星パスの計算 | メインスレッド | QgsTask（7 日 × 多数の衛星でも画面が止まらない） | 指示書どおり |
| 衛星パスのレイヤー | 1 つの一時レイヤー（線と面が混在） | グループ「衛星パス …」に「撮像可能範囲」（面）と「地上軌跡」（線）。衛星ごとに軌跡と同じ色で分類表示 | QGIS の 1 レイヤー 1 形状型のため |
| 撮像可能範囲の表示（左右に見られ最小角 0） | 「20〜20°・左右」のように最大角が 2 回出る | 「20° 以下・左右」。レイヤーの最小オフナディア角も 0 | ビューアの不具合とみて直した（2026-10-27 に決定。下の「参照実装側で見つけた点」） |

## 段階 6〜8（観測記録・分類体系の編集・報告書・Python API）

中核（流れ・継続・同一候補・2 点・確認範囲・CSV・報告書・撮像日時）はビューアのテスト（observations・observation-extras・taxonomy）を移して確認済み。

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| 画面 | ダイアログ（下部のタブ） | 「観測記録」ドック・「分類体系の編集」ドック | QGIS の作法 |
| キー（R・L・A・1〜9・Alt+1〜5・PageUp/Down・Esc） | パネルと地図の上で効く | ドックにフォーカスがあるときだけ。地図のクリックで記録フォームが開くとフォーカスはドックへ移る | 指示書どおり |
| 画像 | ビューアで開いた画像 | プロジェクトのラスターレイヤー。選んだ画像は QGIS の選択レイヤーに連動 | — |
| 画像 ID | カタログの ID、なければファイル名 | レイヤーの `satobs/imageId`（カタログから開いたもの）、なければファイル名 | — |
| カタログ画像の開き方 | トークン付きで取得 | `qgis_io/obs_images.py` の `image_layer()`: URI には `authcfg` だけを入れ、トークンを入れない。トークンしかないカタログは QGIS の API ヘッダー方式の認証設定（`X-Esri-Authorization: Bearer …`）で | プロジェクトファイルに認証情報を残さない（2026-10-27 に決定、撮像計画側と共通） |
| 撮像日時の読み取り | GeoTIFF・NITF をブラウザで読む | ローカルのファイルは GDAL のメタデータ。URL（`/vsicurl/`）の画像はメタデータを読まず、レイヤーの時刻かファイル名 | 撮像日時のための通信を増やさない（2026-10-27 に決定） |
| 手で入れた撮像日時 | 開いている間だけ | ファイルのある画像はレイヤーのプロパティ（`satobs/imageTime`）としてプロジェクトに保存。ファイルなしの画像は保存先ごとに QgsSettings | — |
| ファイルなしの画像の一覧 | ブラウザ（localStorage） | QgsSettings（保存先ごと） | — |
| 記録者 | 入力した名前、なければ ArcGIS のサインイン名 | 入力した名前（QgsSettings）、なければ保存先の認証設定のユーザー名 | 指示書どおり |
| Esri への保存 | `await` で待つ | QgsTask で順に実行（終わると一覧と地図を更新）。ローカルはその場で | 指示書どおり |
| 印のドラッグ | OpenLayers の Translate | 地図ツールで、記録の印を押したまま 3 ピクセル以上動かすと移動 | — |
| 地図の印 | ベクターレイヤー | キャンバスアイテム（プロジェクトには何も足さない） | — |
| レイヤー化 | 一時レイヤー 3 つ | メモリレイヤー 3 つ（記録・確認範囲・流れ）。記録と確認範囲は `image_time`、流れは `first`〜`last` で時系列コントローラーが効く | — |
| 報告書の地図 | 地図を記録の範囲に合わせて描く | キャンバスのレイヤーを QgsMapRendererParallelJob で記録の範囲に描き、印を重ねる（1400 × 900、JPEG） | — |
| 報告書の印刷 | ブラウザの印刷 | QPrinter（印刷ダイアログ）と「PDF 保存」。印刷版は Qt の HTML の都合で集計の 3 つの表が横に並ばず縦に並ぶ | QTextDocument は CSS グリッドに非対応 |
| 参考写真（URL） | サムネイルを表示 | 自動では取得せず「URL を開く」ボタン（クリックで既定のブラウザ）。ファイルの写真と data: の画像はサムネイル | 設定したサービス以外へ勝手に通信しないため |
| 分類ツリーのドラッグ | 行の上端・下端 25% で前後、中央で下位 | Qt の落とし位置（行の間で前後、行の上で下位、余白で大分類） | Qt のツリーの作法 |
| スクリプト | `viewer.addObservation` など（JavaScript、書き込みは実行ごとに確認） | `plugin.api.add_observation` など（snake_case、日時は datetime・ミリ秒・文字列）。確認はしない | 本人がコンソールで実行するため |

## 画像カタログ・新着画像の通知（指示書の改訂で段階 2 に追加）

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |

## 画像補正（色調補正）

参照: `packages/browser-image-enhancement`（補正の計算・DRA・生値の引き伸ばし）と、ビューアの補正パネル（`openlayers/enhance-control.ts`・`enhanced-geotiff.ts`）。

数値比較（`scripts/compare_viewer/compare_enhance.py`）: カラー・透明あり・白黒・かすんだ画像の 4 枚 × 補正 33 通り（各補正の単体、DRA 3 方式と RGB 連動、露出のあとの DRA、彩度を挟む連鎖、シャープとその前後の補正、シャープ 2 回、プリセット 6 種、強制グレー）と、16bit の引き伸ばし 4 通り（埋め値・外れ値・ノーデータ・標準偏差）の計 136 ケースが一致。画像の 131 ケースのうち 130 ケースは全画素が同じで、1 ケース（かすんだ画像の「露出のあとの DRA」）だけ、丸めの境界にちょうど乗る入力値 1 つが 1 階調ずれる（`Math.pow` と NumPy の `power` の最後の桁の差）。16bit の黒・白の値は 1e-12 以内（相対 1e-15）で一致。

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| 計算の場所 | WebGL2（GPU、float32）。なければ Web Worker と WebAssembly | NumPy（CPU、float64）。画面の画素だけ。前後の点処理は表引きと丸めにまとめる（ライブラリと同じ方式） | QGIS 付属の numpy だけで動かすため。結果は JS 版（float64）と同じ |
| スライダーへの追従 | 即時（GPU で描き直すだけ） | 止めてから 0.15 秒後に地図を描き直す。1600×1200 px の 16bit 画像（4 コア）で点処理 5 つが約 0.16 秒、＋彩度 0.19 秒、衛星画像プリセット（DRA＋シャープ）0.48 秒、鮮やか 0.59 秒 | CPU のため。描く範囲を横帯に分けてスレッドで並列に処理（帯の上下にシャープの余白を付けるので結果は同じ） |
| 操作の場所 | 地図の右上の補正パネル | 「画像補正」ドック（アクティブなラスターレイヤーが対象） | QGIS の作法 |
| スライダー | 露出・明るさ・コントラスト・ガンマ・レベル（黒・白・中間）・色温度・彩度・シャープ（量・半径） | 同じ並びに、シャドウ・ハイライト・色かぶりを追加 | プリセット「やわらか」の補正をスライダーで扱えるように |
| スライダーのない補正 | パネルに読み込むと捨てる | 残して後ろに付け、「スライダー外の補正: トーンカーブ」のように表示 | `imageRules`・スクリプトで付けた補正を消さないため |
| 補正をかける画像 | 開いた画像すべて | 「補正」をオンにしたレイヤーだけ | QGIS 標準の表示を勝手に変えないため（2026-10-27 に連絡） |
| DRA の統計 | 表示範囲のタイル | 表示範囲を最長 512 px で読み直して統計（地図を動かすたび、1 回の描画で 1 回）。印刷レイアウトでは地図キャンバスの表示範囲の統計 | 描画が複数の部分に分かれても同じ範囲で引き伸ばすため |
| 16bit・float の DRA なしの引き伸ばし | 画像全体の 2〜98 % | 同じ（画像全体を最長 512 px で読んで統計） | — |
| シャープのタイル境界 | 隣のタイルを余白に | 描く範囲の周りを余白の分だけ広く読む（結果は全体を一度に処理したときと同じ） | — |
| 拡大時の補間 | 元の値を補間してから補正 | 補正した色を QGIS のリサンプリングで補間 | QGIS の描画の順序（レンダラーのあとにリサンプラー） |
| 保存 | プロジェクト（.ivproj）の `pipeline` | レイヤーのカスタムプロパティ `satobs/enhance`（バンド・補正・範囲の固定）。補正は同じ `{"version": 1, "ops": [...]}` | プロジェクトに入る |
| プラグインなしで開いたプロジェクト | — | QGIS 標準のマルチバンドカラー（1 バンドなら単バンドグレー）、同じバンドと生値の引き伸ばし | プロジェクトに独自のレンダラーを書くと、プラグインなしでは読めないため |
| QGIS のシンボロジー画面 | — | 補正中のレイヤーはレンダラーの種類が不明として表示される。そこで別のレンダラーを適用すると補正は外れる | Python のレンダラーは QGIS のレンダラー一覧に登録できないため |
| 段階 2 以降 | `imageRules`・ヒストグラム・単バンドの着色・2 時期の重ね・パンシャープン | 未（順に追加） | 段階分け |

## 新規スクラッチレイヤーのテンプレート

参照: `layer-templates.ts`・`new-layer-dialog.ts`・`temp-layers.ts`（`designFields`・`parseCodes`）。標準のテンプレート 8 種・`layerTemplates` の読み方・設計の検査の文言はビューアと同じ（`tests/test_layer_templates.py` にビューアのテストを移植）。

| 項目 | ビューア | プラグイン | 理由 |
| --- | --- | --- | --- |
| 入口 | 「ツール」→「新規レイヤー…」 | 「レイヤー」→「レイヤーを作成」の QGIS 標準「新規一時スクラッチレイヤー…」の下と、プラグインのメニューに「新規スクラッチレイヤー（テンプレート）…」。標準の画面にも「テンプレート」欄を足し、選ぶとこの画面に切り替え | QGIS 標準の画面にはエイリアス・制約・既定値を入れる口がないため、別の画面で作る |
| ジオメトリ「指定なし（作図ごとに選択）」 | あり（「注記」テンプレート） | なし。指定なしのテンプレートはポイントで開き、その旨を表示 | QGIS のレイヤーは 1 種類のジオメトリのため |
| 属性の「詳細」 | 行ごとに開閉 | 表の列（既定値・文字数の上限・最小・最大・候補値）。型に関係のない欄は灰色で入力不可 | Qt の表で一覧しやすいため |
| 候補値・範囲・必須 | ビューアの属性テーブルで選択・検査 | QGIS の「値マップ」「範囲」ウィジェットと、非 NULL 制約・式の制約（強制） | QGIS の属性フォームで同じ働き |
| 日付型 | 日時（ms） | 日時（QDateTime）。既定値は `2026-10-17`（UTC の 0 時）・`2026-10-17 09:30`（端末の時刻）・時差付きを読む | ビューアの `new Date()` に近い読み方 |
| 座標系 | 「詳細設定」の書き出しの既定（初期値 WGS84） | レイヤーの座標系（初期値はプロジェクトの座標系、なければ WGS84） | QGIS のメモリレイヤーは座標系を持つため |
| 保存したテンプレート | ブラウザ（localStorage） | ユーザープロファイルの `QgsSettings`（`satellite_observation/layer_templates`、`layerTemplates` と同じ JSON） | — |
| 作った層の保存 | ブラウザ・プロジェクト（.ivproj） | QGIS のメモリレイヤー（プロジェクトを閉じると地物は消える。残すときは「エクスポート」か「レイヤーを固定化」） | QGIS 標準のスクラッチレイヤーと同じ扱い |
