サブメニューのあと（区切り線の下）に「イベント」「担当と個人設定…」「ツールバーのボタン…」「ドックのレイアウト」「ドックを初期位置に戻す」「接続と表の点検…」「監査ログ…」「使い方（ヘルプ）…」「Python API リファレンス…」「設定…」を直接置く（設定ファイルの指定は「設定…」だけなので、すぐ届く所に）。並びは `plugin.py` の `MENU_GROUPS` で決まる。

## 使い方（ヘルプ）

一般の利用者向けの手引き（日本語）。メニュー「使い方（ヘルプ）…」（QGIS の「ヘルプ ▸ プラグイン」とツールバーにも）で開く。

- 中身: はじめに・最初にすること（担当と個人設定・設定ファイル・接続と表の点検）・画面のつくり・画面つきの手順書・どの担当でも使う操作（ドック・一覧のビュー・画像カタログ・場所へ移動・イベント）・撮像計画の担当・観測記録の担当・画像判読・キーボードショートカット・困ったとき・サーバーにつながらないとき・用語。設定ファイルの書き方や Esri のテーブルなど管理者向けのことはこの README に書き、ヘルプには書かない
- 画面: 左に目次（見出し）、右に本文。上の欄で検索すると、当たった所をすべて黄色にして最初へ移動（Enter で次へ。「n / m 件」）、当たりのない見出しは目次から隠す。緑のリンク（「観測記録」など）はそのドック・画面を開く。「ブラウザで開く」で同じページを PC のブラウザで（印刷・拡大に）
- ページは 1 つの HTML ファイル `mikage/help/index.html`。外部のファイル・フォント・スクリプトを使わないので閉域でもそのまま見える。QGIS の中では QTextBrowser で表示するため、HTML と CSS は簡単なもの（`h2`・`h3` に `id`、表・箇条書き）だけ。`mikage:open/<メニューの文字>` のリンクはヘルプ画面の中でだけメニューの項目を開く（ブラウザでは何もしない）
- 書くのは `mikage/help/src/` の節ごとのファイル（`010-start.html` …、名前の順につなぐ）。直したら `python3 scripts/build_help.py` で `index.html` を作り直す（テスト `test_docs.py` が食い違いを見つける。2026-11-20 に 1 ファイルから分けた）。2 つのブランチがともにヘルプを直して `index.html` がぶつかったら、どちらかを取ってからこのスクリプトを流し直す
- 「画面つきの手順書」（`#howto`）は、よくある 3 つの作業（画像を探して記録し分担を完了する・撮像を依頼して計画に入ったか確かめる（レイヤーからまとめて取り込むところも）・撮像計画を計算して出し採否を入れる）を画面の写真で追う。2026-11-22 に細かくした: 大きな手順（`h4`「1. 画像を探す」）の中を 1 操作ずつの小さな手順（`p.step`「1-1. …」）に分け、小さな手順ごとに写真 1 枚（赤枠はなるべく 3 か所まで）。各手順書の最初に「始める前に」の表（担当・使うボタンのアイコン・流れ）とツールバーの写真、選択肢・一覧の列・フォームの項目は表、操作のあとの画面は緑の「こうなれば OK」（`p.ok`）、つまずきやすい所は黄色の対処（`p.note`）。写真は `mikage/help/images/`（PNG 約 70 枚、幅 760 ピクセルまで、1 枚 200 KB 未満。ボタンのアイコン `btn-*.png` は文中に置く）。ヘルプ画面は写真が横にはみ出さない幅（1120 × 760）で開く
- 写真だけの段落は `<p class="pic">` にする。QTextBrowser は body の行の高さ（160%）を写真だけの行にもかけるので、そのままでは写真の下に写真の高さの 6 割ほどの空白ができる。QTextBrowser は CSS の `@media` より後ろの規則を読まないので、新しい規則は `@media` より前に書く（どちらもテストが確かめる）
- 写真は `scripts/help_shots/make_shots.py` で撮り直せる（QGIS の Python で `python3.12 scripts/help_shots/make_shots.py`）。仮想画面（Xvfb、96 dpi）で本物の QGIS を起動し、モックサーバー（`scripts/mock_esri`）につないで手順どおりに操作しながら撮り、押す所に赤い枠と番号を描いて `mikage/help/images/` に書く（全部で約 5 分）。開いた一覧（範囲・優先度・グループの ▼）は画面ごと撮る（`shots_lib.shoot_screen`）。見本の画像・背景地図はその場で作る（ネットにつながなくてよい）。要るもの: qgis・python3-qgis・xvfb・fonts-noto-cjk・fonts-open-sans・qttranslations5-l10n（確認の画面のボタンを「はい」「いいえ」にする。ないと Yes・No で写る）・pngquant（なくても可。ファイルが小さくなる）。古い写真は残らないので、全部撮り直すときは先に `mikage/help/images/` を空にする。画面の並びやボタンの名前を変えたら撮り直し、本文の番号（①②…）と写真の番号が合っているかを見る。`--flows obs,request,plan,check,layer` で一部だけ（layer はレイヤーからの取り込み。台帳に依頼が増えるので最後に）、`--raw <フォルダ>` で加工前の写真も残す
- 機能を足したり変えたりしたら、一般の利用者に関わる所はヘルプも直す。テスト（`tests/test_qgis_help.py`）は、ページ内のリンク先の見出し、`mikage:open/` のリンクがメニューにあること、どこでも効くキー（`ui/shortcuts.py` の `GLOBAL`）がすべて載っていること、外部への参照がないこと、手順書の写真がすべてそろって（使われない写真もなく）ヘルプ画面で読み込めることを確かめる

- ツールバー「MIKAGE」に出すボタンは担当（「担当と個人設定…」でチェックしたもの）で変わる
  - 撮像計画の担当: 撮像計画・衛星パス・移動目標撮像計画・雲量マップ・撮像依頼・撮像計画ファイル出力・撮像予定・地点ごとの撮像予定・画像カタログ・イベント・背景地図
  - 撮像を依頼する人: 撮像依頼・撮像予定・地点ごとの撮像予定・画像カタログ・背景地図（計算・書き出しのボタンは出さない）
  - 観測記録の担当: 画像カタログ・通知・画像補正・観測記録・AI結果・分類体系の編集・イベント・通報文の作成・分担・引き継ぎメモ・背景地図・スワイプ比較・位置ずらし・クイック幾何補正
  - 画像判読: 画像カタログ・通知・画像補正・影から高さ・スペクトル・観測記録・移動体・変化抽出（2 時期）・自動位置合わせ・背景地図・スワイプ比較・位置ずらし・クイック幾何補正
  - AI 学習の担当（2026-11-15）: 画像カタログ・物体検出（AI）・AI結果・教師データセットの作成・観測記録をピクセル座標で書き出す・アノテーション変換（点→矩形）・アノテーション変換（教師データセット）・AI 学習（物体検出）・背景地図
  - 判読練習の指導者（2026-11-22）: 判読の練習の問題を作る・判読の練習の成績・判読の練習・画像カタログ・画像補正・観測記録・分類体系の編集・背景地図
  - 管理者（2026-11-15）: 接続と表の点検・監査ログ・設定
  - 担当を 2 つ以上: チェックした順（画面の並び）に各担当のボタンを足していく（同じボタンは 1 回）
  - 担当なし: これまでの並び（ドック 18 個・移動目標撮像計画・背景地図・スワイプ比較・位置ずらし）
  - どれも最後に「使い方（ヘルプ）…」「ツールバーのボタン…」
- メニュー「ツールバーのボタン…」で、今の担当のボタンを自分用に選ぶ。今の担当で使うメニューの項目から、チェックで出す・外す、ドラッグか「上へ」「下へ」で並べ替え。「担当の標準に戻す」で選んだものを忘れる。担当で使わない項目は、自分用に選んであっても出さない
- 自分で選んだボタンは担当の組み合わせごとに覚える（担当を変えるとその担当のボタン、戻すと前に選んだボタン。「撮像計画の担当 ＋ 管理者」は「撮像計画の担当」とは別）。保存先はユーザープロファイルの QGIS 設定（`mikage/toolbarButtons`）
- 担当ごとの標準は `ui/toolbar_buttons.py` の `ROLE_SETS`（項目はメニューの文字で書く）

## 文で操作（`command`）

ツールバー「文で操作」の欄に、したいことを文で書いて Enter（2026-11-21。tsudo「生成AIに指示してある操作をするみたいなことをやれたらいいな…〇〇システムの〇〇日のオーダーファイルを出力してとか」→ 検討 →「この方針で 17 操作すべて」）。読み取った操作と値をカードに出し、カードのボタンを押すまで何もしない。

- **出るとき**: 設定ファイルの `textAssist.tasks.command` にモデルがあり、使う人が「担当と個人設定…」で「生成 AI の機能」を入れたとき（[文章の手伝い](observations.md#文章の手伝い小さな生成-aitextassist)）。ツールバーは QGIS のツールバーとして動かせる
- **操作を選ぶ**: 文の言葉が 1 つの操作だけを指していれば（「オーダーファイル」「撮像予定」「通報」など）モデルを使わずにその操作（すぐ出る）。どれにも当たらないか 2 つ以上に当たるときは、生成 AI に操作の一覧（今の担当で使える画面で、設定ファイルに要るものがあるものだけ）から 1 つ選ばせる。欄をクリックしたときにモデルを読み込んで一覧を読ませておくので、Enter から 1 秒ほどで出る（3B、4 コアの CPU。読み込みとあわせて最初だけ十数秒）。合う操作がなければそう出し、カードで選べる
- **値を読む**: システム（`requestExports` のコード・名前。「Aシステム」「B系」「全システム」）、日付・期間（「明日」「来週月曜」「11/25」「先週」「直近30日」「今月」。計画の操作は先を、画像・記録の操作は前を見る）、場所（地名テーブル `namedAreas` の名前、`geocoders`、「35.3, 139.6」）、衛星（衛星カタログの名前・別名・シリーズ）、画像検索の衛星・種別（下記）、画面（メニューの項目）は、モデルでなくプラグインが文から読む。読めない値は空のまま（推測しない）。要る値（計画ファイルの対象日、地点、画面、衛星パスの衛星）が空のうちはボタンを押せない。カードで操作も値も直せる（操作を選び直すと値を文から読み直す）
- **できる操作**（ボタンを押すとすること。書き出し・取り込み・照合・登録・送信は、開いた画面のボタンで、いつもの確認のあと）:

  | 操作 | すること |
  |---|---|
  | 計画ファイル出力 | 「撮像計画ファイル出力」を開き、対象日とシステムを入れて「計算」 |
  | 撮像予定 | 「撮像予定」にその日（とシステム）を表示 |
  | 結果ファイル取込 | 「撮像予定」でそのシステムの結果ファイルを選ぶ画面を出す |
  | 照合 | 「計画と実績の照合」を期間を入れて開く（読むだけ） |
  | 年間上限 | 「年間撮像上限」をその年で開く |
  | 画像検索 | 「画像カタログ」で場所（なければ地図の表示範囲）と期間、衛星・種別があればそのセンサーで検索 |
  | 衛星パス | 「衛星パス」でその衛星を選び、その日（なければ今）を描く |
  | 地点の撮像予定 | 「地点ごとの撮像予定」にその地点を足す |
  | 撮像計画 | 「撮像計画」でその地点を対象にし、期間を入れて「計算」 |
  | 新着の監視 | その地点の「新着画像を監視」の画面を開く |
  | 観測記録の書き出し | 「観測記録のエクスポート」に文の条件（期間・地名・大分類・確度・有無）を入れて開く |
  | 引き継ぎメモ・通報 | 「引き継ぎメモ」「通報文の作成」を開く |
  | 依頼の作成 | 新しい撮像依頼の画面を開き、文を「依頼文から下書き」に入れる（そのタスクがあるとき） |
  | 障害情報 | 「衛星の障害情報」の登録画面に衛星と文を入れて開く |
  | 移動 | 地図をその場所へ移動 |
  | 画面を開く | 上にないほかの画面（メニューの項目）を開く |

- **画像検索の衛星・種別**（2026-11-25。tsudo「画像検索の文から生成AIでやるけん、衛星の種別も拾えないかな」）: 文の衛星（衛星カタログの名前・ID・[別名](plan.md#衛星名の対応表satellitealiases)・シリーズ名）と、画像カタログのセンサーの名前そのもの（`WV03`。衛星カタログにないシリーズ「ICEYE」も）を読み、なければ種別（[`satelliteKinds`](plan.md#衛星の種別satellitekinds) の名前と `words`。既定は「SAR」「レーダー」「合成開口」→ SAR、「光学」「可視」→ 光学、「IR」「赤外」「熱赤外」「サーマル」→ IR。2026-11-26）を読む（どれもプラグインが読み、モデルは操作を選ぶだけ）。カードの「衛星・種別」（、区切りで直せる）の右に、画像カタログで選んでいるカタログのセンサー（`fields.sensor` の値の一覧。設定を読んだときに読む）のうち当たるものを出す。ボタンで、そのセンサーを「詳細条件 ▸ センサー」に「、」区切りで入れて検索（書いていなければセンサーを空にして全センサー）。
  - センサーと衛星の対応は計画と実績の照合と同じ（同じ名前・別名、`WorldView-3 PAN` のような続き、`OPT` → `OPT2`）。どの衛星にも当たらなければ、名前のシリーズ（`ICEYE-X31` → ICEYE）の衛星
  - 種別は衛星カタログの `fields.kind` から（[衛星の種別](plan.md#衛星の種別satellitekinds)）。種別のない衛星・カタログにない衛星のセンサー、シリーズに 2 つ以上の種別があるセンサーは種別不明としてどの種別にも入れず、カードに「種別のわからない n は含めない」（マウスを置くと名前）。センサーの名前が種別の `match` に当たれば（TerraSAR-X）その種別
  - 衛星の名前と種別を両方書いたら、その衛星のセンサーのうちその種別（か種別不明）のもの。当たるセンサーがなければカードにそう出し、ボタンは押せない。カタログがセンサーの一覧を返さないときは、衛星の名前はそのまま、種別は使えない。センサーの属性がないカタログでは絞らない（カードに出す）
- **記録**: ボタンで行った操作は監査ログ（`command`）に、文・操作・選び方・値を残す
- **苦手なこと**（2026-11-21、本物の sarashina2.2 3B と Qwen3 8B で確かめて）: 「出力して、そのあと照合も」のような 2 つ以上の操作、「先月いちばん未撮像が多かったシステムは」のような数えたり比べたりする質問は 3B も 8B もできない。1 つずつ頼む。数えたり比べたりする質問は、`dataChat` があれば [データに質問](analysis.md#データに質問datachat) に渡す（「何件」「どこが多い」「？」などの質問の形で、言葉で決まる操作がないとき）

## ドックの配置

- 初期位置は 3 つのタブのまとまり。撮像系（撮像計画・衛星パス・撮像依頼・撮像計画ファイル出力・撮像予定・雲量マップ）は右、カタログ系（画像カタログ・通知・画像補正・影から高さ・スペクトル・ダッシュボード・データ分析）は左、記録系（観測記録・分類体系の編集・移動体・AI結果・イベント）は右の下段。タイムラインの「地点ごとの撮像予定」は地図の下
- 最初に開いているのは「画像カタログ」と「撮像計画」だけ。ほかはメニューかツールバーから開く（QGIS が前回の配置を覚えていれば、そちらが優先）
- 浮かせたドックが画面外にある場合（モニターを外したあとなど）、開いたときに元の場所へドッキング
- メニュー「ドックを初期位置に戻す」で、すべてのドックを初期位置のタブに戻す。開いているドックは開いたまま
- メニュー「ドックのレイアウト」で、開くドックと配置を作業ごとに名前を付けて保存し、ワンクリックで切り替え（例:「観測記録の担当」「撮像計画の担当」）
  - 「現在の配置を保存…」: 開いているドック、タブのまとまりと前面のタブ、左右・上下の位置と大きさ、浮かせたドックの位置を保存。同じ名前は置き換え
  - 保存したレイアウトを選ぶと、その配置に切り替え（レイアウトにないドックは閉じる）。最後に使ったものにチェック
  - 初めから「撮像計画の担当」「撮像を依頼する人」「観測記録の担当」「画像判読」「AI 学習の担当」「判読練習の指導者」の例がある（担当と同じ名前。管理者は自分のドックがないので例もない）。同じ名前で保存すると置き換わり、それを削除すると例に戻る
  - 「撮像を依頼する人」（2026-11-15）: 依頼を登録して計画に入ったかを見るだけの人向け。右に撮像依頼・撮像予定（タブ）、下に地点ごとの撮像予定。撮像計画・撮像計画ファイル出力は開かない
  - 「AI 学習の担当」（2026-11-15）: 左に画像カタログ、右に AI結果
  - 「判読練習の指導者」（2026-11-22）: 左に画像カタログ・画像補正、右に観測記録・分類体系の編集（問題の画像と、正解にする記録）
  - 担当で使わないドック（例: 撮像を依頼する人の「観測記録」）は、レイアウトにあっても開かない
  - 「ファイルへ書き出し…」「ファイルから読み込み…」で JSON にして別の PC や担当者と共有。QGIS のパネルやツールバーは変えない
  - 保存先はユーザープロファイルの QGIS 設定（`mikage/dockLayouts`）

## 最初の設定（担当と個人設定）

- プラグインを初めて入れたとき（その QGIS ユーザープロファイルで初めて起動したとき）だけ「最初の設定」画面が出る。プラグインの更新では出ない（プロファイルにプラグインの設定がすでにあれば、この画面ができる前から使っていた人として出さない）
- 選ぶもの
  - 担当（2026-11-15 からチェックボックス。いくつでも）: 撮像計画の担当・撮像を依頼する人・観測記録の担当・画像判読・AI 学習の担当・判読練習の指導者・管理者。チェックした担当で使う機能だけをメニュー・ツールバー・ドックのボタンに出す（[担当と使える機能](#担当と使える機能userroles)）。初めは何もチェックしていない（どれも選ばなければ、管理者の機能のほかはすべて出る）
  - 「チェックした担当のドックで開き直す」（既定オン）: 担当と同じ名前の「ドックのレイアウト」のドックを開く。2 つ以上なら合わせて開く（左右・下のそれぞれで、1 つ目の担当のまとまりにほかの担当のドックをタブで足す。同じドックは 1 回）。オフか、担当を選ばないときは、ドックは今のまま（担当で使わないドックだけ閉じる）。担当にカーソルを置くと開くドックが出る
  - ドックの開き方: 「メイン画面に連結（タブでまとめる）」か「別ウィンドウで表示」。別ウィンドウでは、ドックごとに独立したウィンドウになり（閉じているドックも、開くとウィンドウで出る）、メイン画面の右寄りに少しずつずらして並べる。別のモニターにも置ける。このあと「ドックのレイアウト」の例や「ドックを初期位置に戻す」も別ウィンドウで開く（浮かせた位置ごと保存したレイアウトはその位置）
  - 個人の設定: 記録者名（既定はユーザー名、環境変数 `USERNAME`。[観測記録](observations.md)）、観測記録のクリック数（1〜4 点）、カーソル位置の表記（10進・度分秒・MGRS・UTM）、生成 AI の機能（2026-11-21。初めは使わない。「使う」を入れると文章の手伝いと文で操作のボタンが出る。設定ファイルにモデルの割り当てがなければ選べない。[文章の手伝い](observations.md#文章の手伝い小さな生成-aitextassist)）。「設定ファイルの指定・接続の認証…」で「設定…」も開ける
- 「あとで」で閉じても次からは出ない。メニュー「担当と個人設定…」でいつでも選び直せる
- 保存先はユーザープロファイルの QGIS 設定（`mikage/firstSetupDone`・`roles`・`rolesPending`・`docksFloating`、ほかは各項目の既存のキー）。担当は設定ファイルに [`userRoles`](#担当と使える機能userroles) があれば Esri の表にも保存（別の PC でも同じ担当）。2026-11-15 より前に 1 つ選んでいた担当（`mikage/role`）は、その担当にチェックした扱い

## 担当と使える機能（`userRoles`）

一人ひとりが自分の担当（いくつでも）を「最初の設定」「担当と個人設定…」でチェックし、その担当で使わない機能はメニュー・ツールバー・ドックのボタン・キー・プロセシングのツールに出さない（2026-11-15。一般の利用者に管理用の機能を出さない、観測の担当に計画のシステム入力を出さない、など）。担当は自分で選ぶ（運用の手間を減らすため。管理者の承認は要らない）。

- **権限ではない**: 見せないだけ。本当に書き込みを許す・断るのはサーバー側（ArcGIS の認証と各サービスの権限）。プラグインの Python API（`plugin.api`）からは担当に関係なく呼べる
- どの担当もチェックしないとき: 管理者の機能のほかはすべて出す（担当を入れる前と同じ。管理者の機能だけ出なくなる）
- 担当で使わない機能をヘルプのリンクなどから開こうとしたときは開かず、メッセージバーに「担当「…」の機能です」と出す。ドックのボタンを押せる状態で担当を外したときも、ドックの下の欄に同じ文
- どの担当にも書いていない機能（画像カタログ・撮像計画・衛星パス・雲量マップ・画像補正・影から高さ・スペクトル・イベント・データ分析・背景地図・物体検出（AI）など）はだれにでも出る

| 担当（表の値） | その担当で出る機能（ほかの担当の機能は出ない） |
| --- | --- |
| 撮像計画の担当（`PLANNER`） | 撮像を依頼する人の機能と、撮像計画ファイル出力・年間撮像上限…・撮像予定の採否（採用・不採用・不明に戻す・結果ファイルの取り込み・要求外を追加・削除）・衛星の障害情報の新規・編集・復旧・削除 |
| 撮像を依頼する人（`REQUESTER`） | 撮像依頼の新規・編集・削除・一括編集・レイヤーから取り込み、撮像計画の「臨時依頼を作成」、依頼グループ…の新規・編集・上へ・下へ・削除（一覧はだれでも）、衛星・システムの障害情報…（見るだけ） |
| 観測記録の担当（`OBSERVER`）・画像判読（`INTERPRETER`） | 観測記録（ドックとそのキー）・自分の記録…・分類体系の編集・分類体系の取り込み…・通報文の作成…・通報記録の確認…・観測記録のエクスポート…・観測記録の一括取込み…・分担…・引き継ぎメモ…・検出結果を DB へ転記…・AI結果（観測記録へ取り込み・正・誤検出）・画像カタログの「ファイルなしで記録」 |
| AI 学習の担当（`TRAINER`） | AI結果（確認結果で追加学習…）・教師データセットの作成…・観測記録をピクセル座標で書き出す…・アノテーション変換（点→矩形）…・アノテーション変換（教師データセット）…・AI 学習（物体検出）…（プロセシングの同じツールも） |
| 判読練習の指導者（`INSTRUCTOR`。2026-11-22） | 判読の練習の問題を作る…・判読の練習の成績…と、観測記録の担当の機能（記録を正解に取り込むため） |
| 管理者（`ADMIN`） | 接続と表の点検…・監査ログ…・Python API リファレンス…・サーバ処理…（プロセシングの GP ツールも）・ArcGIS Web マップの「ポータルに保存」（JSON ファイルへの保存はだれでも）・観測記録の「この PC の記録を消去…」・「設定…」の設定ファイルの指定の変更（最初に指定するのはだれでも） |

- 分類体系の編集と分類体系の取り込み（表から）は観測記録の担当の機能（記録の種別の分類なので、記録する人が変える。観測記録ドックの「詳細」からも開く）。AI結果のドックは観測記録の担当と AI 学習の担当の両方に出る
- 担当と機能の対応は `core/roles.py` の `ROLES`・`FEATURES`（機能はメニューの文字か、ドックのボタンのキー）

保存先:

- この PC: ユーザープロファイルの QGIS 設定（`mikage/roles`。次の起動ですぐ同じメニューになる）
- Esri: 設定ファイルの `userRoles`（[`TBL_USER_ROLE`](../admin/esri-tables.md#tbl_user_role担当)、編集可）に、[`editTracking`](../admin/operations.md#作成者更新者の記録edittracking) と同じユーザー名（既定は環境変数 `USERNAME`）で 1 担当 1 行。チェックしたときに書き、外した担当の行は消す。プラグインが知らない値の行（新しい版の担当など）はそのまま
- 起動するたびに（QGIS の起動後、裏で）その人の行を読んで使う。管理者が表の行を直せば、次の起動からその担当になる。別の PC でも同じ担当
- 表に書けなかったとき（サーバーに届かない・表がない）はこの PC の担当で動き、次の起動でもう一度送る（それまで表は読まない）。メッセージバーに理由。表が読めないときも担当は外さない（この PC の担当のまま）
- `userRoles` がなければこの PC にだけ保存（あとで書けば、次の起動でそれまでの担当を表に送る）

```jsonc
"userRoles": "https://gis.example/arcgis/rest/services/MIKAGE/FeatureServer/26"
// 属性名を変えたとき: { "url": "…", "fields": { "user": "USER_NAME", "role": "ROLE_NAME" }, "where": "…" }
```

## 練習モード（`training`）

本番のサーバーから切り離して練習用のデータで動く MIKAGE（2026-11-22）。新しく来た人の練習、使ったことのない機能を試すとき用。メニューの一番上の「練習モード」（「練習モードを始める」「チュートリアル…」「判読の練習…」「練習データを最初に戻す…」「練習モードを終える」）と、「最初の設定」の「この設定で、まず練習」から。担当に関係なくだれにでも出る。同じメニューの「判読の練習の問題を作る…」「判読の練習の成績…」は判読練習の指導者の機能（本番の MIKAGE で使う。設定ファイルに組織の問題の表があるときだけ出す）。

練習モードだけで動く別のプラグイン **MIKAGE 練習版**（`mikage_training`、2026-11-26）も同じコードから作れる（`scripts/build_zip.py --training-only`）。QGIS を起動すると自動で練習モードに入り、終えられない。作り方・配り方・ちがいは [導入と設定の「MIKAGE 練習版」](../admin/install.md#mikage-練習版練習モードだけの別のプラグイン--training-only)、使う人向けはヘルプの「MIKAGE 練習版（練習モードだけのプラグイン）」

- **練習用のサーバー**: Esri のモック（`mikage/core/training/server.py`。開発用の `scripts/mock_esri` の中身をプラグインに移したもの。Python の標準ライブラリだけ）を QGIS の中のスレッドとして 127.0.0.1 だけで動かす。外の PC からは届かない。閉じたネットワークでも、ArcGIS Enterprise が止まっていても練習できる。ポートは前回と同じもの（使われていれば空いているもの。データの URL はそのポートに書き直す）
- **見本**: 東京湾・横須賀（`mikage/core/training/sample.py`。使い方（ヘルプ）の手順書の写真と同じデータ）。画像 6 枚（光学 4・SAR 2）、衛星 4 機、観測記録と分類体系、撮像依頼と依頼グループ、地名、通報の条件・ジオフェンス・地名・国、イベント、備考の単語集。画像（1600 px）と背景地図（`basemap.tif`）は初めて始めたときに作る（`mikage/qgis_io/training_images.py`。数秒〜十数秒）。日付は作った日に合わせる。始めるときの画面の「練習データを今日の日付で作り直す」（作ってから 7 日以上で最初から入る）か「練習データを最初に戻す…」で作り直す
- **本番から読む台帳**（`training.fromProduction`、既定ですべて）: 読むだけの台帳は、本番の設定ファイルにあれば本番のものを使う（`mikage/core/training/masters.py`。組織の実際の分類や衛星で練習できる）。書き込む表（観測記録・撮像依頼・撮像予定・分担・通報・イベントなど）と画像カタログは練習用サーバーのまま。本番の設定ファイルにない台帳は見本のもの。本番の画像カタログのうち `mode` が `training`（練習モードだけ）・`both`（両方）のものは、`fromProduction` にかかわらず見本のカタログの後ろに出す（組織の練習用設定ファイルのときも。[画像カタログの mode](images.md#練習モードだけ本番だけ両方mode)）
  - `satellites`（衛星）: `satelliteCatalogs`・`sensorCatalogs`・`satelliteAliases`・`groundStations` と、その衛星を発注する `requestExports`（撮像計画ファイルの `folder` は練習用のフォルダーに書き換える）
  - `taxonomy`（分類体系）: `observationVocabulary` と、本番の 1 番目の `observationStores` の `taxonomy`・`taxonomyTable`・`kinds`・`activities`・`confidences`（練習用の観測記録の表に付ける）。練習中は「分類体系の編集」が使えない（「（練習モードでは本番の分類体系を読むだけ）」）
  - `places`（地名）: `geocoders`
  - `eventKinds`（イベントの種類）: `events.kinds`
  - `glossary`（備考の単語集）: `glossary`
  - 本番の設定ファイルから何かを読むときは、本番の `signIn`（サーバーのドメインごとのサインイン）も練習用の設定ファイルに写す。本番の設定ファイルからの相対パス（`./` `../`）は書き直す。本番の設定ファイルが URL で、いま読めていなければ前回読めたものを使う
- **置き場所**: QGIS のユーザープロファイルの `mikage/training/`（人ごと）。練習用サーバーのデータ（`server/`）、練習用の設定ファイル（`config.training.jsonc`。始めるたびに書き出す。本番の URL・フォルダーは入らない）、ローカルの観測記録（`observations.gpkg`）、送信待ち（`offline_work.sqlite`）、地名の控え・開いた画像の履歴・サムネイル、出力（`出力/`: 撮像計画ファイル・通報のファイル）
- **本番に書き込まない仕組み**: 練習中は設定ファイルとローカルのファイルを練習用に切り替える（`qgis_io/settings.py` が練習中は練習用の場所を答える。切り替えは設定ファイルを読み直すときと同じ道）。練習用の設定ファイルには `userRoles` も `auditLog` もなく、地理院の地名検索（インターネット）も入れない（本番から読む地名に地理院が入っていれば、それは使う）
  - 担当: 練習中だけ切り替えられる（この PC だけ）。始めるときにユーザープロファイルの `mikage/roles`・`rolesPending`・`role`・`plan_reminders`・`request_export_folder` を `mikage/training/saved` に取っておき、終えると戻す。練習中に QGIS が落ちても、次の起動で戻す（`mikage/training/active`）。練習で選んだ担当が本番の `userRoles` に送られることはない
  - 監査ログ: 本番の監査ログに「練習モードを始めた」「終えた」（種類 `session`、`training-start`・`training-end`）だけを残し、その間は何も記録しない
  - 通報のメール: メールソフトを開かず、作ったメールの中身（宛先・件名・本文）を画面に出す
  - 使えないもの: 「設定…」「サーバ処理…」「ArcGIS Web マップを開く…」「ArcGIS Web マップとして保存…」「移動体（AIS・ADS-B）」（メニューの文字の後ろに「（練習モードでは使えません）」）
  - 地図: 始めると新しいプロジェクトになり、練習用の背景地図だけが入る（本番のレイヤーを地図に残さない）。いまのプロジェクトに保存していない変更があれば、先に保存するか聞く。練習用のプロジェクトは保存を聞かない。終えると練習の前のプロジェクトを開き直す
- **見た目**: 地図の上の橙色の帯（右に「チュートリアル」「判読の練習」「練習データを最初に戻す…」「練習モードを終える」）、ステータスバーの右端の「練習モード」、ドックの名前の後ろの「【練習】」（別ウィンドウにしたドックも）、QGIS のウィンドウ名の前の「【練習モード】」
- 画面の並び・列の順番・ツールバーのボタンなどの個人設定は本番と共通（練習で整えた画面をそのまま本番で使える）
- QGIS を閉じると練習モードも終わり、次に開くときは必ず本番。練習データは次の練習まで残る
- **チュートリアル**（段階 2、`mikage/ui/tutorial_guide.py`・`tutorial_courses.py`）: 練習モードの中で、使い方（ヘルプ）の「画面つきの手順書」と同じ操作を 1 つずつ案内する。メニューの「チュートリアル…」・帯の「チュートリアル」・始めるときの画面の「始めたら、チュートリアル…を選ぶ」（初めて始めるときは入っている）から。練習モードでないときは先に練習モードを始める
  - コース: 「はじめての MIKAGE」（8。だれでも）、「画像を探して記録し、担当を完了する」（19。観測記録の担当）、「撮像を依頼して、計画に入ったか確かめる」（16。撮像を依頼する人）、「たくさんの場所をまとめて依頼する（レイヤーから取り込み）」（4。撮像を依頼する人。練習用の場所のレイヤー「見たい岸壁（練習）」を地図に入れる）、「撮像計画を計算して出し、採否を入れる」（8。撮像計画の担当）。手順の番号・名前・言葉は手順書（`mikage/help/src/040-howto.html`）と同じ。コースの一覧は自分の担当のコースが先
  - 案内の窓（QGIS の上に出る小さな窓。QGIS のダイアログが開いていても隠れない）が手順を言い、押す所・見る所を赤い枠（手順書の写真と同じ赤）で囲む。画面がそうなったら（ドックが開いた・検索が終わった・記録が増えた・採否が入ったなど）「できました」と出て次の手順へ。読むだけの手順は「次へ」。「やって見せる」でその手順を MIKAGE がする（`scripts/help_shots/scenario.py` で手順書の写真を撮るのと同じ操作）。「戻る」「手順書で見る」、ドックを閉じたときの「…のドックを出す」

- **判読の練習**（段階 3、`mikage/core/training/exercises.py`・`results.py`・`sample_exercises.py`・`tables.py`・`authoring.py`・`grades.py`、`mikage/ui/exercise_run.py`・`exercise_screens.py`・`exercise_map.py`・`exercise_authoring.py`・`exercise_grades.py`）: 画像の判読の問題を解いて、経験者が確かめた答えと照らし合わせる。メニューの「判読の練習…」・帯の「判読の練習」から（練習モードでないときは先に始める）。答えるのは観測記録ドックのいつもの操作（クリック記録・種別と活動・入力点数で測る・前の画像の記録を継続・消失）
  - 問題の種類と採点する項目: 「見つける」（範囲の中の対象をすべて記録。見つけたか・種別・活動、範囲の中で対象の種別の、答えにない記録は「誤り」）、「見分ける」（印のものの種別・活動）、「測る」（印のものの長さ・幅・向き。始めると入力点数を 3 点にし、終えると戻す）、「変化を見つける」（前の画像の記録を出しておき、来た・継続・消失）。形式は「練習」と「試験」（1 回だけ。ヒントなし。制限時間で自動提出）

  - **組織の問題**（段階 3 の 2、`tables.py`）: 判読の練習の指導者が、組織の実際の画像で問題を作る。問題は [`TBL_TRAINING_EXERCISE`](../admin/esri-tables.md#tbl_training_exercise判読の練習の問題)（範囲のポリゴン 1 つで 1 問。種類・指示文・画像・対象の種別・難しさ・制限時間・練習か試験・合格点・この問題だけの採点の決まり・コースと順番・対象の担当・出すか）、正解は [`TBL_TRAINING_ANSWER`](../admin/esri-tables.md#tbl_training_answer判読の練習の正解)（モノ 1 つで 1 点。種別・活動・長さ・幅・向き・変化・配点・位置の許容・必須か加点か・解説・参考写真）。指導者が本番の MIKAGE の「判読の練習の問題を作る…」で書く（ArcGIS Pro・Portal で入れてもよい）。「判読の練習…」を開くたびに読み直す（指導者が足した問題がすぐ出る）。正解のない問題・使えない行は出さず、メッセージバーに理由を出す（`ACTIVE` が 0 の作りかけは黙って出さない）
  - 組織の問題の画像: `IMAGE_ID` は練習用の画像カタログで探し、なければ本番の画像カタログ（`imageCatalogs` の `fields.id` のあるもの）で引いて開く（読むだけ。本番の `pathMappings` も使う）。`IMAGE_SOURCE` はファイルか URL を開く（ファイルのパスは画像カタログと同じく `pathMappings` で読み替える）
  - 結果の送信: `training.exercises.results` があれば、提出 1 回で [`TBL_TRAINING_RESULT`](../admin/esri-tables.md#tbl_training_result判読の練習の結果) に 1 行足す（練習モードの中で本番に書き込むのはこれだけ。答え合わせの画面に「結果を組織の表に送りました。」）。送れなかったら、その PC の結果に「まだ送っていない」と残し、次に「判読の練習…」を開くときに送り直す。解いた人（`USER_NAME`）は作成者の 4 属性と同じ利用者名（本番の `editTracking`）。試験の 1 回だけと何回目は、この表の本人の行とその PC の結果を合わせて数える（ほかの PC で受けた試験も済み）
  - 練習中の記録: 観測記録ドックを練習用の別のローカルの記録「判読の練習」（`mikage/training/exercise_records.gpkg`。問題を始めるたびに空にする）に切り替える（`ObservationDock.use_store`）。種別の選択肢は練習用の観測記録の分類体系（本番から読んでいれば本番のもの）。答えの種別がその分類体系にないときは、ある所まで上の分類で採点する（`fitted`）。解いている間は「AI結果」ドックに結果を出さない（`AiResultsDock.withhold`。答えが分かるため）。画像は画像カタログから開く（開いた画像の履歴の「前回と同じファイルで開きます」は聞かない）
  - 窓: 問題の窓は地図の右上（練習モードの帯の下）、答え合わせの窓は QGIS の右（ドックの上）。範囲と答えの場所は、窓に隠れない地図の部分に合わせて出す（`exercise_map.free_part`・`fit_into`）
  - 採点（`score`）: 答え 1 つの点（既定 10）を、その答えに当てはまる項目で `weights` の割合に分ける。記録と答えは近い順に 1 対 1 で結ぶ（許容: 答えの `tolerance`、なければ `tolerance` と 長さ × `toleranceByLength` の大きい方）。種別は同じ（か細かい）1・1 つ上 0.5・いちばん上 0.2。測るは許容の中で満点、その 3 倍で 0。点数 = 100 × 得た点 ÷ 必須の答えの点 − 誤り × `extraPenalty`（0〜100）。必須でない答え（加点）は見落としても引かない。`passScore` 以上で合格
  - 結果: `mikage/training/exercise_results.json`（この PC だけ。1 回の提出で 1 件。練習データを最初に戻しても残す）。答え合わせの画面（点数・項目ごとの点・答え 1 つずつの結果と解説、地図の輪と ×）、「これまでの結果…」（解いた問題と、取り違えやすい種別の組み合わせ）
  - **問題を作る**（段階 3 の 3、`authoring.py`・`ui/exercise_authoring.py`）: 担当「判読練習の指導者」（`INSTRUCTOR`）の「判読の練習の問題を作る…」。本番の MIKAGE で使う（練習モードの間は使えない。本番の表に書くため）。組織の問題の一覧（作りかけも）から「新しい問題…」「編集…」「コピーして作る…」「練習の一覧に出す／作りかけに変更」「削除…」（正解も消す。解いた人の結果は残す）
    - 編集の画面は QGIS の右側に開いたまま（タブ「問題」「正解」「採点の決まり」。左の地図を触れる。編集中は一覧を隠し、閉じると戻す。地図で見るときは編集の画面に隠れない所に出す）: 題名・指示文・種類・画像（「観測記録ドックの画像」でいま選んでいる画像。画像カタログで開いた画像は ID、そうでなければファイル）・変化を見つける問題の前の画像・範囲（「範囲を描く」で地図に角をクリック、「いまの地図の範囲」）・対象の種別・形式（練習か試験）・制限時間・合格点・難しさ・コースと順・対象の担当・答え合わせで正解と解説を見せるか・練習の一覧に出すか
    - 正解: 「観測記録から取り込む…」で、その画像の範囲の中の観測記録（経験のある判読者の記録）を選んで取り込む（種別・活動・長さ・幅・向き、メモは解説に。変化を見つける問題は、前の画像にあったモノは継続、消失の記録は消失、ほかは来た）。すでに正解にある所（10 m 以内）は印なしで出す。「地図で足す」は地図をクリックした所に足す（Esc か右クリックで終わり）。表で種別・活動・長さ・幅・向き・変化・配点・必須か加点か・位置の許容・解説を直し、「参考写真…」でファイルを付ける。正解は地図に番号付きの赤い輪で出す
    - 採点の決まり（この問題だけ。空欄は組織の既定）: 位置の許容・誤りの減点・長さと幅の許容・向きの許容・配点の割合（見つける・種別・活動・測る・変化）・種別の部分点（一つ上の分類・大分類だけ）・向きの前後を問うか（`SCORING` に JSON で書く。ほかのキーはそのまま残す）
    - 保存: 足りないものがあれば書かずに理由を出す（題名・画像・正解・前の画像・測る問題の長さなど・変化）。範囲の外の正解・対象の種別でない正解・範囲なし・作りかけは書いたうえで知らせる。問題の行は足すか直し、正解の行は `OBJECTID` で直す・足す・消す（作成者の 4 属性は MIKAGE のいつもの書き込みと同じ）。新しい問題の ID は `EX-20261122-153012`
    - 「練習モードで試す」: 保存してから練習モードを始め、その問題をみんなと同じように解く（作りかけでも。結果は残さず、組織の表にも送らない。試験も何回でも）
  - **成績**（段階 3 の 3、`grades.py`・`ui/exercise_grades.py`）: 「判読の練習の成績…」で、結果の表（`training.exercises.results`）のみんなの結果を読む。コース・期間（この 30 日・90 日・1 年・すべて）を選び、一人一問の最高点（外すと最新の点）を、人（行）× 問題（列。番号、試験は「（試）」）の表で出す。合格は緑・不合格は赤・まだは —。右端は進み具合（合格した問題 / コースの問題）。下に取り違えの多い組み合わせ（正しい種別 ＼ 答えた種別の回数。答えの下の細かい種別は正しい扱い）と指導のヒント（よく取り違える組み合わせ・合格の少ない問題・見落としの多い種別）。「CSV に書き出す…」で表を CSV に（人ごとに問題の点・合否・回数と、進み具合）。見本の問題の結果は `EXERCISE_ID` に `見本:sample-find` のように書き、組織の問題と分ける
  - テスト: `mikage/tests/test_exercise_scoring.py`（採点）、`mikage/tests/test_qgis_exercises.py`（見本の問題を人と同じ操作で解いて満点・見落としと誤り・試験）、`mikage/tests/test_training_tables.py`（組織の表の読み取り・結果の行）、`mikage/tests/test_qgis_org_exercises.py`（組織の問題を解いて結果を送る・送り直す・ほかの PC で受けた試験・本番のカタログやファイルの画像）、`mikage/tests/test_training_authoring.py`・`test_training_grades.py`（問題の読み書き・保存の前の確かめ・観測記録から正解・成績の表と取り違え）、`mikage/tests/test_qgis_exercise_authoring.py`（本番のカタログの画像の観測記録から問題を作って書き、直して書き、練習モードで試す・一覧から出す・消す・成績の画面）

設定ファイル（`training`）:

| 書き方 | 内容 |
| --- | --- |
| なし・`true` | 内蔵の見本で練習 |
| `false`（`{ "enabled": false }` も） | 練習モードを出さない |
| `{ "fromProduction": false }` | 衛星・分類体系なども含めて見本だけで練習する。`["satellites", "taxonomy"]` のように名前を並べると、それだけ本番から読む（既定 `true` = すべて） |
| `{ "config": "練習用の設定ファイル" }` | 内蔵の見本の代わりに、組織の練習用サービス（SDE 上の練習用の表・実際の画像など）を指す設定ファイルで練習する（パスか URL。相対パスはこの設定ファイルのフォルダから）。練習用サーバーは動かさない。ローカルのファイル・担当・監査ログ・メールの扱いは内蔵の見本と同じ。その設定ファイルには本番の表を書かないこと |
| `{ "exercises": { "exercises": "URL", "answers": "URL", "results": "URL" } }` | 判読の練習の組織の問題（[`TBL_TRAINING_EXERCISE`](../admin/esri-tables.md#tbl_training_exercise判読の練習の問題)）・正解（`TBL_TRAINING_ANSWER`）・結果（`TBL_TRAINING_RESULT`）の表。問題と正解の表は必須、`results` を書かなければ結果はその PC だけ。`token` は 3 つの表のトークン（QGIS の認証設定があればそちら） |
| `{ "scoring": { … } }` | 判読の練習の採点のしかた（組織の基準。書かないキーは既定のまま）。キーは `tolerance`（位置の許容 m、既定 50）・`toleranceByLength`（大きなものは長さ × これ、0.5）・`weights`（項目の割合 `find` 50・`kind` 30・`activity` 10・`measure` 10・`change` 50）・`kindCredit`（種別の部分点 `exact` 1・`parent` 0.5・`top` 0.2）・`extraPenalty`（誤り 1 件の減点、5）・`lengthTolerance`（長さ・幅の許容 %、15）・`headingTolerance`（向きの許容 度、15）・`headingEitherEnd`（向きを前後どちら向きでも可に、false）・`passScore`（合格点、70）。まちがった書き方は読み込みの問題に出して、その値は既定のまま |

"training": { "config": "\\\\fileserver\\mikage\\config.training.jsonc" }

## 一覧のビュー（列・並べ替え・絞り込みの保存）

ドックの一覧はどれも、見出しの右クリックのメニューで列の表示・非表示と順番を変えられる。その並びは一覧ごとに覚え、次に QGIS を起動しても同じ。

- 右クリックした列を「この列を左へ」「この列を右へ」「この列を先頭へ」「この列を末尾へ」（隠した列は飛ばす）
- 列の名前のチェックで表示・非表示（すべては隠せない）
- 標準では隠れている列もある（撮像依頼・撮像予定・撮像計画ファイル出力・計画と実績の照合の「メモ」。2026-11-24 tsudo「通常は非表示で」）。チェックすると出て、その一覧で覚える。前から並びを覚えている一覧・保存済みのビューでも隠れたまま始まる
- 「列の表示と順番…」: 全列の一覧でチェックと「先頭へ」「上へ」「下へ」「末尾へ」をまとめて変えて OK。「標準に戻す」で全列をプラグインの順番に（標準で隠れている列は隠す）
- 「標準の表示に戻す」: 全列をプラグインの順番で表示（標準で隠れている列は隠す）
- 見出しのドラッグでも並べ替えられる。設定ファイルに `"columnDrag": false` と書くとドラッグでは動かず、メニューだけで並べ替える（読み直した時点で開いている一覧にも効く）

対象: 画像カタログ・観測記録（この画像・モノ・分類のタブごと、モノの流れ）・撮像依頼・撮像計画（機会・再訪間隔）・衛星パス・撮像予定・撮像計画ファイル出力・イベント（イベントと項目のタブごと）・AI結果・通知（新着画像・監視条件・通報）・移動体、ダイアログの「通報」の通報記録・「分担と引き継ぎ」・「計画と実績の照合」。データ分析の結果の表は SQL の列の順なので対象外。

一覧の横の「ビュー」ボタンで、今の見え方を名前を付けて保存し、あとで 1 回で切り替える。

| 一覧 | ビューに入るもの |
| --- | --- |
| 画像カタログ | 列の表示・並び、並べ替え、検索の条件（カタログ・範囲の種類・撮像日・詳細条件・未着手のみ）。一覧を検索済みなら選んだときに検索し直す |
| 観測記録 | タブごとの列の表示・並び、大分類の絞り込み |
| 撮像依頼 | 列の表示・並び、区分・状態・依頼グループの絞り込み（状態・依頼グループはチェックしたものすべて） |

- 「ビュー」の中身: 保存したビュー（選ぶと切り替え）、「今の表示を名前を付けて保存…」、「「名前」に上書き保存」、「ビューの削除」、「列の表示・順番」、「列の表示と順番…」、「標準の表示に戻す」（全列をプラグインの並びで表示。標準で隠れている列は隠す）
- 保存先はこの PC の個人の設定（QgsSettings `mikage/listViews/<一覧>`）。設定ファイル・プロジェクトには書かないので、人ごとに違ってよい
- 列は見出しの名前で覚えるので、設定ファイルで列が増えたり減ったりしても残りの列はそのまま

## キーボードショートカット

よく使う操作にキーを割り当ててある。どのキーも QGIS の「設定 ▸ キーボードショートカット…」に名前付きで並ぶので（「観測記録」「撮像計画」などで検索）、そこで変更・解除でき、変更は QGIS が覚える（`ui/shortcuts.py`）。

どこにフォーカスがあっても効くキー（地図で点を打っている最中も）。QGIS 3.34 本体・Processing・Python コンソールが使っていない Ctrl+Alt の組み合わせにしてある。

| キー | 操作 |
|---|---|
| Ctrl+Alt+O | 観測記録ドックを開く（前面に出してフォーカス） |
| Ctrl+Alt+I | 画像カタログを開く |
| Ctrl+Alt+K | 撮像計画ドックを開く |
| Ctrl+Alt+Q | 撮像依頼ドックを開く |
| Ctrl+Alt+N | 新着画像（大きな画面）と地図の切り替え |
| Ctrl+Alt+PageDown ／ PageUp | 観測記録: 次の画像 ／ 前の画像（撮像日時の順） |
| Ctrl+Alt+E | 観測記録: 記録（クリック記録）の開始・終了 |
| Ctrl+Alt+D | 観測記録: 地図の印の表示・非表示（「印」の「非表示」と元の表示を切り替え） |

そのドックにフォーカスがあるときだけ効くキー（文字・数字キーがほかの入力の邪魔をしないように）。

| ドック | キー | 操作 |
|---|---|---|
| 観測記録 | PageDown ／ PageUp | 次の画像 ／ 前の画像 |
| 観測記録 | R | 記録の開始・終了 |
| 観測記録 | 1〜9 | 活動の n 番目を選ぶ（分類） |
| 観測記録 | Alt+1〜5 | 同一候補の n 番目を選ぶ |
| 観測記録 | Enter（テキスト欄・クリック記録中の地図）、Ctrl+Enter（ドック内のどこでも） | フォームの記録・更新、確認範囲の記録（地図にフォーカスがあっても効く。フォームが開いていなければ QGIS のキーのまま） |
| 観測記録 | Esc | 最後の点の取消・入力の終了（クリック記録中は地図にフォーカスがあっても効く。ドラッグ中の記録は元の位置のまま） |
| 観測記録 | L | 入力点数の切り替え（1 → 2 → 3 → 4 点） |
| 観測記録 | A | 確認範囲の記録 |
| 観測記録 | H | 地図の印の表示・非表示 |
| 観測記録 | S ／ G | 見本で記録の「連続」／「並べる」の開始・終了 |
| 観測記録 | Backspace | 連続・並べるで最後に記録したものの取り消し（地図にフォーカスがあっても効く。Ctrl+Z も） |
| 観測記録 | ＋ ／ − | 並べる: 1 列の数を増やす ／ 減らす（地図にフォーカスがあっても効く） |
| 撮像計画 | Ctrl+Enter ／ Esc | 計算 ／ 中止 |
| 分類体系の編集（一覧） | Alt+↑↓ ／ Insert ／ Delete | 並べ替え ／ 下に追加 ／ 削除 |

## 入力の初期値の記憶

- 前回の入力を次の入力の初期値にする。ユーザープロファイルの `QgsSettings`（`mikage/last_inputs/…`）に人ごとに残し、設定ファイルには書かない
- 撮像依頼: 新しい依頼は、最後にフォームで保存した依頼の区分・達成条件・繰り返し・優先度・種別・観測方向・軌道方向・時間帯（時刻も）・衛星シリーズ・衛星・センサー・モード・角度・分解能・雲量・優先するシステム・依頼者から始まる（名称・期間・範囲・状態・メモは毎回空から）。点の範囲の一辺も
- 撮像計画・衛星パス: 選んだ衛星（一覧に新しく出た衛星は前回の選択どおり）と、期間・オフナディア角・日照条件・太陽高度・入射角・軌道・向き・雲量・地物ごと・優先する値・目標・集約・最初の機会のみ（衛星パスは表示・前後の時間・オフナディア角・日照条件・時刻表示）。変えたときに残す
- 観測記録の種別・活動・確度（保存先ごと）は従来どおり
- 報告書の題名・分類・確度・内容、移動目標撮像計画の予測の長さ・間隔・誤差の広がり、検出結果の転記先、地点の監視のカタログ、新規スクラッチレイヤーのテンプレート・作図開始、AI結果の確信度の下限・並び・確認不要の確信度、影から高さの吸着
- 前回の値が選べなくなっていたら（カタログから消えた衛星、設定から消えた転記先など）、その項目はフォームの既定のまま
- 覚えた値は「設定…」の「入力の初期値」→「覚えた値を消去」でまとめて消せる（観測記録の種別・活動・確度も）。開いているフォームは今の値のまま、次に開くフォームから既定値
