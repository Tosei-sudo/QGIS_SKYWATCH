# 地図・レイヤー

背景地図・スクラッチレイヤー・ArcGIS Web マップ・座標・外部からの図形・起動時のレイヤー。（[README](../../README.md) から機能ごとに分けた説明。）

## 背景地図

- ツールバーの「背景地図」（メニューでは「地図・レイヤー ▸ 背景地図」のサブメニュー）で、なし・地理院 標準・地理院 淡色・地理院 写真・地理院 ベクトル・OpenStreetMap・OpenStreetMap（Esri ベクトル）を切り替え。表示中のものにチェック
- 一覧はビューアと同じ `config.json` の `baseMaps`（書くとこの一覧で置き換え）。`type` は `xyz`・`mvt`・`style`・`esri`、書かなければ URL から判断。相対 URL は設定ファイルの場所が基準
- 背景地図はプロジェクトのいちばん下のレイヤー 1 枚。切り替えると差し替え、「なし」で削除。ほかのレイヤーはそのまま
- `defaultBaseMap` があれば、空のプロジェクトで起動したときと新規プロジェクトで表示。このときはプロジェクトを「変更あり」にしない（ほかのプロジェクトを開く・新規プロジェクト・QGIS を閉じるときに「現在のプロジェクトを保存しますか」と聞かれない）
- 閉域では `baseMaps` を社内のタイルに書き換え（既定の一覧はインターネットの地図）。読み込めない背景地図はメッセージバーに理由
- ArcGIS の VectorTileServer で認証が要るものは「設定…」でそのサービスの認証設定を選択（`token` はレイヤーに書かない）

## 新規スクラッチレイヤー（テンプレート）

- 「レイヤー」→「レイヤーを作成」の「新規一時スクラッチレイヤー…」のすぐ下と、プラグインのメニュー「地図・レイヤー」に「新規スクラッチレイヤー（テンプレート）…」
- 「テンプレート」から選ぶと名前・ジオメトリ・属性が入り、そこから自由に変えて「作成」。テンプレートは標準（空のレイヤー・航跡〔生存圏計算用〕・調査地点・目標・物体・関心区域・被害状況・経路・測線・注記）、設定ファイルの `layerTemplates`（「組織の設定」、書き方はビューアの README と同じ）、「テンプレートとして保存」で残したもの（「保存済み」、ユーザープロファイルの `QgsSettings`）
- 属性ごとに名前・エイリアス・型（文字列・整数・小数・日付）・必須・既定値・文字数の上限・最小・最大・候補値（`1=住宅, 2=店舗`）。作るとメモリレイヤーに、エイリアス、必須は非 NULL 制約、候補値は「値マップ」ウィジェットと制約、範囲は「範囲」ウィジェットと制約、既定値は属性の既定値として入る
- 「ほかのレイヤーの属性をコピー…」で開いているベクターレイヤーの属性・ジオメトリ・座標系をひな形に（地物はコピーしない）
- 「作成後すぐ地図に作図開始」で、編集を始めて「地物を追加」の状態に
- 「航跡（生存圏計算用）」の属性名は「移動目標撮像計画…」の自動対応に合うので、描いたらそのまま存在予測を計算できる
- QGIS 標準の「新規一時スクラッチレイヤー」の画面にも「テンプレート」欄が付き、選ぶとこの画面に切り替わる

## ArcGIS Web マップ

メニュー「地図・レイヤー」の「ArcGIS Web マップを開く…」「ArcGIS Web マップとして保存…」で、ArcGIS Online・Enterprise のポータルの Web マップ（バージョン 2.x）をそのまま開き、QGIS のプロジェクトを Web マップとして書き出す。QGIS 本体は ArcGIS のサービスを 1 つずつ開けるが、Web マップのアイテムは開けない。

- 開く: アイテムのページ（`…/home/item.html?id=…`）、Map Viewer の URL、REST の URL、または 32 桁のアイテム ID（ポータルを選択）。JSON ファイルからも開ける。非公開のアイテムは「認証設定」で QGIS の認証設定（OAuth2・ESRI token など）を選ぶ（ポータルごとに記憶し、そのポータルのホストと、ArcGIS Online なら `*.arcgis.com` のサービスにだけ使う）
- 読めるレイヤー: フィーチャー（定義式・シンボル・ラベル・ポップアップの属性名も）、マップ・イメージ・タイルのサービス、ベクタータイル、WMS（名前ごとに 1 レイヤー）、WMTS、WFS、Web タイル、地図に保存されたフィーチャーコレクション（メモリレイヤーに）。グループは平らにして、表示・不透明度・縮尺の範囲を引き継ぐ。読めないもの（KML・CSV・シーンなど）は理由とともに一覧
- Web マップ名のグループをレイヤーパネルの一番上に作って並べ、初期表示範囲へ移動し、ブックマークを追加（グループは Web マップ名）。背景地図は設定ファイルの `baseMaps` に同じものがあれば「背景地図」で切り替え、なければグループの一番下にレイヤーとして追加
- 保存: レイヤーパネルの順に、サービスのレイヤーはサービスとして、ファイル・メモリのベクターレイヤーはフィーチャーコレクション（5,000 件まで）として書き込む。シンボル（単一・分類・段階のシンプルな点・線・面）とラベル（属性 1 つ）は Web マップの形に変換。画像ファイルなど書き込めないものは理由とともに一覧。表示範囲・背景地図・ブックマークも書き込む
- 「JSON として保存…」でファイルに、「ポータルに保存…」で新しいアイテムとして（開いたアイテムへの上書きも可、確認あり）

## 座標・地名へ移動

- ツールバー「座標・地名へ移動」の入力欄に座標を入れて Enter（か「移動」）で、その地点へ移動して青い丸の印を付ける。読める表記はビューアと同じ: 緯度経度（`35.6812, 139.7671`、`35°40'52"N 139°46'1"E`、`北緯35度40分52秒 東経139度46分1秒`、`354052N 1394601E`、`lat 35.68 lon 139.77`、`POINT(139.77 35.68)`、全角も可）、MGRS（`54SUE8843349290`、精度は任意）、UTM（`54N 388433 3949290`）
- 設定ファイルに `geocoders` があれば地名・住所も入れられ、打つ途中で見つかった場所が欄の下に並ぶ（↑↓と Enter かクリックで移動）。種類はビューアと同じ `gsi`・`nominatim`・`arcgis`・`features`（Esri の地名レイヤー。`field` を配列にすると複数の属性で探す: `["PLACE_NAME", "PLACE_NAME_KANA", "PLACE_ALIAS"]` なら地名・読み・別名のどれかに含まれれば見つかり、先頭の属性が地名として並び、読みや別名で見つかったときは「読み: よこすかこう」のように合った属性（レイヤーのエイリアス）と値が横に出る。読みはひらがな・カタカナどちらで打っても探す。同じ地名・同じ位置は 1 件にまとめ、打った文字で始まるもの・短いものから並べる）・`csv`（名前・緯度・経度の列がある CSV。設定ファイルからの相対パス可）。`geocoders` がなければ地名は検索せず、入力が外へ送られることはない
- カーソル位置の WGS 84 座標をステータスバーの右に表示。表記（10進・度分秒・MGRS・UTM）は地図の右クリックの「ステータスバーの表示」か、表示の右クリックで切り替え
- 地図の右クリック「緯度経度・MGRS・UTM のコピー」で、その地点の座標をコピー

## 外部から図形を受け取る（AutoMap など・`shapeReceiver`）

ブラウザ拡張機能 AutoMap の「MIKAGE に送る」、リンク、この PC のプログラムから送られた点・線・面を、レイヤーグループ「受け取った図形」の一番上に一時レイヤーとして追加し、地図をそこへ移動する。レジストリに書き込めない環境でも使えるよう、URL スキームではなく QGIS の中の小さな HTTP サーバーで受け取る（新しいライブラリは使わない）。

- **待ち受け**: この PC の中だけ（`127.0.0.1`、既定のポート `47631`）。ほかの PC からは届かず、Windows ファイアウォールの確認も出ない。QGIS が起動していないとき・ポートがふさがっているとき（MIKAGE の入った QGIS をもう 1 つ開いている、ほかのプログラムが使用中）は受け取れず、AutoMap が「MIKAGE に接続できない」と表示する（理由は QGIS のログのタブ「MIKAGE」）
- **表示**: 1 回の送信ごとに、点・線・面の種類ごとのメモリレイヤー（名前は送信元が付けた `name`、種類が混ざるときは「…（点）」「…（線）」「…（面）」）。ラベル（`label`）があれば地図に表示し、GeoJSON の属性（文字・数）は属性テーブルに残る。点 1 つならその点を中心に `zoom`（既定 14、ビューアと同じ）、点だけならその範囲（`zoom` より寄らない）、線・面ならその範囲へ移動。QGIS のウィンドウを前に出し（Windows ではタスクバーの点滅になることがある）、メッセージバーに「〇〇 から図形 n 個を受け取り…」と送信元を表示。監査ログには `receive` として送信元・個数・レイヤー名を記録
- **送り方**（パラメーターはビューアのリンクと同じ `geom`・`line`・`polygon`・`geojson`・`label`・`name`・`color`・`zoom`。座標は緯度経度・度分秒・MGRS・UTM、WKT（`SRID=3857;` も）、GeoJSON）:
  - `POST http://127.0.0.1:47631/show` に JSON（`{"geojson": {…FeatureCollection…}, "name": "…"}`、`geojson` はオブジェクトのままでよい）かフォーム（`geom=35.68,139.77&label=東京駅`）。答えは JSON（`{"ok": true, "count": 2, "layer": "…", "errors": []}`）。AutoMap はこの方法
  - `GET http://127.0.0.1:47631/show?geom=35.6812,139.7671&label=東京駅`（ブラウザで開く・ほかのプログラムからリンクを開く）。結果は短いページで表示
  - `GET /status` で待ち受けているか（`{"app": "MIKAGE", "ok": true}`）
- **受け取る相手**（ほかは 403 で何もしない）: `origins` に合う送信元（既定 `chrome-extension://*` = ブラウザ拡張機能。Web ページは拡張機能の送信元を名乗れない）、この PC のプログラム（`Origin` も `Sec-Fetch-*` もない要求: curl・PowerShell・Python など）、人が開いたリンク（アドレスバー・ブックマーク・ほかのアプリから開いたリンク）、`origins` にあるサイトのページのリンク。Web ページの画像・スクリプト・フレーム・fetch からの要求は受け取らない（開いたページが勝手に地図へ図形を置けないように）。`Host` が `127.0.0.1`・`localhost` 以外の要求（DNS リバインディング）も受け取らない
- **中身の点検**: 値はデータとしてだけ読み、ファイルや URL を開くことはない。1 つの値は 20 万文字まで（POST の本文は 8 MB まで）、図形は 1 回 1000 個まで、頂点は合わせて 10 万点まで、緯度経度の範囲外は読まない（ビューアと同じ）。読めなかった値は理由をメッセージバーと答えに出し、読めたものだけ表示
- **社内の Web ページから送るとき**: そのページの送信元を `origins` に足す（`"origins": ["chrome-extension://*", "https://intra.example.jp"]`。`*.example.jp` も可。`*` だけ・`https://*` は不可）。Chrome 142 以降はページから `127.0.0.1` への fetch に「ローカル ネットワークへのアクセス」の確認が出るので、管理者がポリシー `LocalNetworkAccessAllowedForUrls` にそのサイトを入れておく。拡張機能（AutoMap）は `host_permissions` があるので確認は出ない（Chrome 142〜143 の一部では拡張機能でも止まる不具合があり、そのときは同じポリシーに `chrome-extension://<拡張機能の ID>` を入れる）
- **1 台の Windows に複数人がログインする（リモートデスクトップのサーバー）とき**: `127.0.0.1` は全員で共有なので、最初に QGIS を開いた人のポートになる。こうした PC では `"shapeReceiver": false` にするか、利用者ごとに設定ファイルを分けて `port` を変える

```jsonc
"shapeReceiver": {
  "enabled": true,                       // false で待ち受けない（"shapeReceiver": false だけでも可）
  "port": 47631,                         // 1024〜65535。AutoMap の設定「MIKAGE」の送信先と合わせる
  "origins": ["chrome-extension://*"]    // 受け取る送信元。拡張機能を AutoMap だけにするなら "chrome-extension://<ID>"
}
```

## 起動時のレイヤー

設定ファイルの `layers`（ビューアの「起動時に読み込むレイヤー」）を、QGIS を空のプロジェクトで起動したときと「新規プロジェクト」のときに追加する。上に書いたものが下になる。メニューの「地図・レイヤー ▸ 設定ファイルのレイヤーを追加」でいつでも追加でき、「設定…」の「起動時と新規プロジェクトで、設定ファイルのレイヤー（layers）を追加」で止められる。

| type | QGIS での開き方 |
| --- | --- |
| `cog` | GDAL（URL は `/vsicurl/`） |
| `file` | GeoJSON などは OGR、Shapefile の .zip は `/vsizip/`、画像・GeoTIFF は GDAL。相対パスは設定ファイルの場所から |
| `wms`・`wmts`・`xyz` | WMS プロバイダー（WMTS の `matrixSet` 省略時は GoogleMapsCompatible、XYZ の `#name=`・`zmin`・`zmax` も読む） |
| `wfs`・`ogc-features` | WFS・OAPIF プロバイダー（`filter` はレイヤーのフィルター） |
| `esri` | フィーチャーサービスは ArcGIS フィーチャーサーバー、マップ・イメージサービスは ArcGIS マップサーバーのプロバイダー |
| `wcs`・`ogc-coverage` | WCS プロバイダー・GDAL の OGCAPI ドライバー |
| `ogc-tiles` | XYZ のタイル（ベクタータイルはベクタータイルレイヤー） |

起動時と新規プロジェクトで自動で追加したときは、プロジェクトを「変更あり」にしない。QGIS は自分の起動処理で新規プロジェクトを作り直したり、ほかのプロジェクトを開く・新規プロジェクト・閉じるときに変更があれば「現在のプロジェクトを保存しますか」と聞くが、プラグインが足しただけのレイヤーでは聞かない（自分でレイヤーを足すなど変更すれば今までどおり聞く）。「設定ファイルのレイヤーを追加」で追加したときは自分の操作なので「変更あり」になる。

最初は非表示にしたいレイヤーには `"visible": false` を書く（このプラグインだけが読む項目。ビューアは読まない）。レイヤーは追加されるが、レイヤーパネルのチェックが外れた状態になり、チェックを入れるまで地図に描かない。書かないか `true` なら今までどおり表示する。「設定ファイルのレイヤーを追加」で追加したときも同じ。

```jsonc
"layers": [
  { "type": "xyz", "url": "https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg#name=写真" },
  // 追加はするが、最初はチェックを外しておく
  { "type": "esri", "url": "https://gis.example/arcgis/rest/services/Ports/FeatureServer", "layer": "0", "visible": false }
]
```

読み込みは QgsTask の中で行い、開けないレイヤーはメッセージバーに理由を出して残りを追加する。サービスの認証は「設定…」で選んだ認証設定を使う。
