# 解析・処理

データ分析・QGIS の式の関数・測地線の道具・サーバ処理。（[README](../../README.md) から機能ごとに分けた説明。）

## データ分析

ツールバーかメニュー「解析・処理 ▸ データ分析」で開く、高度な利用者向けのドック。設定ファイルでつないだ Esri の表（画像カタログ・外部 AI の結果・観測記録・イベントと紐付け・通報記録・撮像依頼台帳など）と、プロジェクトに追加したレイヤー・テーブルを結合して集計する。例:「モデル X の外部 AI 結果がある画像を出し、画像・クラスごとに件数を数える」。

属性テーブルの強化ではなくドックにした理由: QGIS の属性テーブルは 1 レイヤーで、結合も 1 対 1 なので「1 枚の画像に AI 結果が多数」を数えられない。外部 AI の結果のように、プロジェクトのレイヤーになっていない Esri の表も多い。プラグインは表ごとの URL・トークン・属性の役割を知っているので、結合のキーを候補に出せる。結果は「レイヤーとして追加」で QGIS に戻せるので、属性テーブル・地図・ダッシュボードはそのまま使える。

- 表の一覧: Esri の表は README の「Esri 側のテーブル定義」の名前（`TBL_IMAGE_CATALOG`・`TBL_AI_RESULT` …。同じ種類が 2 つ以上あれば `TBL_AI_RESULT_2` …）、プロジェクトのレイヤーはレイヤー名（空白や記号は `_`）。列は属性名のまま。型・役割（imageId など）・エイリアスも表示する。ダブルクリックで名前を SQL に入れる。「一覧を更新」でレイヤーと列を読み直す
- 読み込み条件…: 表を読むときの条件。Esri の表は WHERE 句（サーバー側で絞るので速い）、プロジェクトのレイヤーは QGIS の式。設定ファイルの `where` があれば両方を満たす行を読む。表ごとの上限（既定 100,000 行）を超えたら中止する（黙って切らない）
- かんたん集計: 基にする表、結合（つなぐ表・ある行だけ／なくても残す・キー。キーは役割から候補を出す。例: AI 結果の画像 ID と画像カタログの画像 ID、紐付けとイベント、通報記録と観測記録、観測記録の `NAMED_AREA_OBJECTID` と地名のポリゴンの `OBJECTID`）、条件（WHERE 句。基の表が `t0`、結合した表が `t1`…）、グループにする列、集計（件数・異なる値の数・合計・平均・最小・最大）、並び（多い順・上位 N 件）から SQL を作る
- SQL: SQLite の SELECT 文をそのまま書ける（WITH・JOIN・GROUP BY・CASE・ウィンドウ関数など）。`:名前` は実行時に入力する値（ドックに入力欄が出る）。日時は「YYYY-MM-DD HH:MM:SS」（この PC の時刻）の文字なので `date(ACQ)` や `ACQ >= '2026-11-01'` が使える。列 `SHAPE` で形状（WGS 84 の WKT）を読む（SQL に `SHAPE` と書いたときだけ読む）
- サーバーでの絞り込み: 読む行と列を減らすため、集計は PC のまま、次のことを Esri にも任せる（かんたん集計でも、手で書いた SQL でも）。どれも「サーバーが返すものが SQL に要るものより多いことはあっても少ないことはない」ものだけで、結果は変わらない。サーバーが受け付けなければ、その表はこれまでどおり読み込み条件だけで読む。Esri の表は Oracle 上の ArcSDE を前提に条件を書く（Oracle では空文字が NULL・LIKE は大文字小文字を区別・文字の並び順が SQLite と違うことがある）。実行後の「読んだ表」に表ごとに何をしたかが出る（例: `TBL_AI_RESULT 320 行（サーバーで絞り込み: 条件・列 4/12）`、`TBL_IMAGE_CATALOG 310 行（サーバーで絞り込み: 結合キー 320 件・列 3/25、キャッシュ（2 分前））`）
  - 列: SQL が読む列（SQLite に空の表で SQL を解釈させて調べる）とオブジェクト ID だけを読む。`SELECT *` なら全部。SQL の誤りはこのとき分かるので、表を読む前にエラーを出す
  - 条件: WHERE と、結合の ON を括弧の外の AND で分け、1 つの表の列だけを見る部分をその表の WHERE にも入れる（`:名前` は入力した値）。送るもの: 数値の比較・`IN`・`BETWEEN`、`IS [NOT] NULL`、文字の `=`・`IN`・`LIKE`（NOT の中は除く。英字のあるパターンは `UPPER(列) LIKE 'ABC%'`。SQLite の LIKE が a–z の大文字小文字を区別しないため）、日時と `'YYYY-MM-DD…'` の比較（PC は手元の時刻の文字、サーバーは時刻なので、前後に 1〜2 日の余裕をとった `TIMESTAMP` で送る）と、その AND・OR・NOT。送らないもの: 文字の大小比較・`<>`・`NOT IN`（Oracle の並び順・NULL の扱いが違うことがある）、空文字 `''`、関数・計算・副問い合わせ、文字と数値の比較、2 つの表にまたがる部分、括弧の外に OR があって分けられない条件。部分の中の AND で送れないところは省いて送る（残る行が増えるだけ）。LEFT JOIN（なくても残す）の右の表には、その表の行がないとき（列がすべて NULL）に成り立たない部分と、その結合の ON の部分だけを入れる。表の別名のない列は、その列を持つ表が 1 つだけのときにその表の列とみなす
  - 結合キー: Esri の表は件数をサーバーに尋ねて少ない順に読み、先に読んだ表のキーの値だけで次の表を読む（`IMG_ID IN (…)`、500 件ずつ。数値のキーが多いときは、範囲 `KEY BETWEEN 最小 AND 最大` のほうが問い合わせが少なければ範囲）。内部結合（ある行だけ）と WHERE の `a.X = b.Y` はどちら向きにも、LEFT JOIN は残す側から右の表の向きだけ。表を全部読むより問い合わせが少ないとき（または全部だと表ごとの上限を超えるとき）に使う。キーが 1 件もなければその表は読まない
  - 使わないとき: SQL を読み取れない形（`WITH`・`UNION`・`RIGHT`/`FULL`/`NATURAL JOIN`・FROM の副問い合わせなど。このときも列は絞る）、同じ表を 2 回使う結合（自己結合）や副問い合わせにも出てくる表、`rowid` を読む表
  - キャッシュ: 同じ表への同じ問い合わせは、`analysisCacheMinutes` 分（既定 5 分、0 で使わない）のあいだメモリの答えを使う（同じ分析を何度も実行したり、同じ表の分析を続けたりしても読み直さない）。サーバーが表の最終更新日時を返す表（`editingInfo`）はそれが変われば読み直し、プラグインがその表に書き込んだときも読み直す。ほかの人の編集は最長でその分数だけ遅れて反映される。「一覧を更新」で捨てる。PC のディスクには書かない
- 読み込み計画: 「実行」の隣のボタン。実行する前に、表ごとに読む順・サーバーの件数・送る WHERE・結合キー・読む列・キャッシュの有無・送らない条件とその理由を別のウィンドウに出す（「コピー」で貼れる）。表のデータは読まない（レイヤーの情報と件数だけ尋ねる）
- 実行（Ctrl+Enter）: SQL に出てくる表だけを読み、Python 標準の SQLite（メモリ上）で集計する。Esri には読み取り（query）しかしない。SQL も読み取り（SELECT）以外は実行しない（ATTACH・PRAGMA・書き込みは不可）。新しいライブラリは使わない。メモリ上の内部情報を返す関数（`fts3_tokenizer`）やファイル・拡張を扱う関数（`load_extension`・`readfile` など）も呼べず、1 つの値は 100 MB まで。`:名前` の値は SQL に埋め込まず別に渡す（バインド）。読み込み条件（Esri の WHERE 句）は括弧で囲んで設定ファイルの `where` と AND するので、括弧を閉じて抜ける条件（`1=1) OR (1=1`）・`;`・コメントは使えない（画像カタログの検索の「追加条件」も同じ）。CSV 保存とクリップボードへのコピーでは、= + - @ で始まるセル（列名も）の前に ' を付けて表計算ソフトの数式にしない
- 結果: ドックの表（5,000 行まで表示）、「CSV 保存…」（UTF-8 BOM 付き、数式に見える値は先頭に `'`）、「コピー」（タブ区切り、Excel に貼れる）、「レイヤーとして追加」（`SHAPE` の列があれば地図のレイヤー、なければ表）
- 分析の保存: 「保存」「名前を付けて保存…」で、分析（SQL・かんたん集計の選択・入力した値・読み込み条件）をプロジェクトファイルに保存する（プロジェクトを保存すると残る）。設定ファイルには書かない。「例」は設定ファイルの表から作る（外部 AI の結果: モデルを指定して画像・クラスごとの件数、モデル・クラスごとの件数と画像の数／観測記録: 種別ごとの件数／イベント: 種類ごとの項目の数）

### 保存した分析をプロセシングのツールに

プロジェクトに保存した分析は、処理ツールボックスの「MIKAGE ▸ 保存した分析」に分析の名前のツールとして並ぶ（ドックの「処理ツールで開く…」でも開く）。保存・削除・別のプロジェクトを開くとツールの一覧も変わる。

- 入力: SQL の `:名前` ごとの文字の欄（既定は最後に入れた値）と、詳細設定の「1 つの表から読む上限」
- 出力: 結果のレイヤー（`OUTPUT`。一時レイヤーのほか GeoPackage・CSV などのファイルにも出せる。`SHAPE` の列があれば地図のレイヤー）と行数（`ROWS`）
- バッチ処理（値を変えて何度も）、グラフィカルモデラー（ほかのツールとつなぐ）、スクリプトの `processing.run(api.analysis.algorithm_id("名前"), {"model": "yolo", "OUTPUT": "/tmp/out.gpkg"})` で使える
- Esri の表を読む分析は、処理ツールボックスのダイアログ・モデラー・バッチ処理から実行する（Esri への通信はバックグラウンドだけ。Python コンソールから `processing.run` すると理由を出して止まる）。プロジェクトのレイヤーだけの分析はどこからでも動く

Python からは `api.analysis`（`tables`・`set_sql(text)`・`set_value(name, value)`・`run(then)`・`explain(then)`（読み込み計画の文）・`result`・`save(name)`・`load(name)`・`add_layer()`・`csv_text()`・`algorithm_id(name)`・`open_processing(name)`）。

## QGIS の式の MIKAGE 関数

フィールド計算機・ラベル・スタイル（ルール・データ定義）・式による選択・仮想フィールドで使える関数。式ビルダーのグループ「MIKAGE」に説明つきで出る。

| 関数 | 返すもの |
| --- | --- |
| `mikage_record_count(画像ID[, 種別])` | その画像の記録の件数（在のみ・削除を除く。種別を渡すとその分類と下位だけ） |
| `mikage_object_names(画像ID[, 種別])` | その画像に記録したモノの名前の配列（`array_to_string(…, '、')` で文字に） |
| `mikage_last_seen(モノ)` | モノ（ID か名前）を最後に確認した画像の撮像日時 |
| `mikage_last_activity(モノ)` | そのときの活動 |
| `mikage_kind_level(種別, 階層)` | 種別の 1 つの階層（1 が大分類、-1 が最も下） |
| `mikage_place(図形)` | 図形（線・面は内側の点）を含む地名のポリゴンのうち最も小さいものの名前 |
| `mikage_places(図形)` | 図形を含む地名の配列（小さい順） |

例: 画像カタログのレイヤーのラベルを `"IMG_ID" || ' (' || mikage_record_count("IMG_ID") || ' 件)'`、ルールで `mikage_record_count("IMG_ID") = 0`（未記録の画像）。

- 記録は観測記録ドックで選んでいる保存先から読んだもの（式のたびに Esri に問い合わせない。地図の描画中も待たない）
- 地名は設定ファイルの `alertReports.namedAreas`（なければ `observationExports.namedAreas`）を、[地名・国の控え](observations.md#地名国の控え)から引く（通報・エクスポートと共通。レイヤー全体は読まない）。控えにない場所（1 度四方のマス）は最初 NULL で、裏でそのマスを読み終わると地図を描き直す（フィールド計算機・式で選択はもう一度実行）。どの地名にも入らないときも NULL
- レイヤーの CRS は式のコンテキストから読み、WGS 84 に直して比べる

## 測地線バッファ・正距方位での重心

メニュー「解析・処理」の「測地線バッファ…」「正距方位での重心…」（Processing ツールボックスの「MIKAGE」にも）で、アクティブなベクターレイヤーを WGS 84 楕円体上で処理する。QGIS 本体の「バッファ」「重心」はレイヤーの座標系の単位で計算する（経緯度のレイヤーなら度、Web メルカトルなら高緯度ほど伸びた距離）のに対し、こちらは座標系によらず地上の m で計算する。

- 測地線バッファ: 距離（m、負でポリゴンを縮小）・円弧の細かさ・線の端（丸・平ら・四角）・融合。点の丸いバッファは本当の測地線の円、線とポリゴンは地物ごとにその中心の正距方位図法で拡張して戻す
- 正距方位での重心: 地物の中心の正距方位図法で重心を求めて戻す。ポリゴンは面積、線は長さ、点は等しく重み付け。パートごと・重心が外に出る形は内側の点、も選べる

## サーバ処理

メニューの「解析・処理 ▸ サーバ処理…」で、ArcGIS のジオプロセシングサービス（GPServer）や OGC API – Processes のサーバの処理を、QGIS の Processing のアルゴリズムとして実行する。QGIS 本体にはどちらも呼び出す仕組みがない。

- サービスは設定ファイルの `gpServices` から選ぶか、GPServer・GP タスク・OGC API のトップページ・`/processes`・1 つの処理の URL を入れて「取得」。処理を選んで「開く」（タスクや処理の URL なら読み込むとすぐ開く）
- 非公開のサービスは「認証設定」で QGIS の認証設定を選ぶ（サービスごとに記憶）。設定ファイルの `token` も、そのサービスにだけ使う
- 処理は Processing の「MIKAGE › サーバ処理」のアルゴリズムになり、入力（文字・選択肢・数値・距離と単位・真偽・日時・地物・表）を Processing のダイアログで入れて実行。地物はどのベクターレイヤーからでも送れ、Esri には Web メルカトルの Esri JSON、OGC には WGS 84 の GeoJSON で送る
- ジョブは完了まで追跡（進行とメッセージを表示、取り消すとサーバ側も取り消し）。結果の地物はメモリレイヤー、画像はラスターレイヤー、ジョブの結果の地図はマップサービスのレイヤーとして追加し、値とリンクはログに表示
