# AI

物体検出・クリック抽出・AI 学習・AI結果。（[README](../../README.md) から機能ごとに分けた説明。）

## AI（物体検出・クリック抽出）

ビューアと同じ ONNX のモデルで、画像から物を見つけてポリゴンにする。QGIS 本体にはない。モデルはプラグインに入っていない（設定ファイルの `aiModels` か、ONNX ファイルを指定）。

- ツールバーかメニュー「AI ▸ 物体検出（AI）…」（Processing の「MIKAGE」にも）: レイヤー・モデル・範囲・解析の画素の大きさ（0 で元の解像度。地図の表示から始まる）を選んで実行し、見つかった物を `class`・`class_id`・`score`（回転矩形なら `angle`）と画像の情報（`image`・`image_id`・`image_time`・`model`・`detected_at`・`note`）付きのポリゴンレイヤーにする。読めるモデルはビューアと同じ（YOLOv8/11 の検出・回転矩形・セグメンテーション、YOLOX、RT-DETR、Detectron2 など。入力の大きさとクラスはモデルの情報から読み、`aiModels` の値が優先）。レイヤーは表示のとおり（補正・スタイル込み）に描いて解析し、大きい範囲は区切って重なりを付けて解析する。詳細設定で確信度・重なり（IoU）・タイルの重なり・クラスの絞り込み
- メニューの「AI ▸ クリック抽出（AI）」（地図ツール）: Segment Anything（SAM・MobileSAM など）のエンコーダーとデコーダーで、クリックした物の輪郭を描く。Shift+クリックで同じ物に足す点、Alt+クリックで除く点。地図の左上のパネルで、モデルの選択・「元に戻す」・「レイヤーにする」（一時レイヤー「AI 抽出」）。表示を動かすと次のクリックで描き直して解析する
- `aiModels`: ビューアと同じ形。検出は `{"label", "url", "task", "inputSize", "classes", "mean", "std", "channels", "format", "maxDetections", …}`（プラグインだけの `kinds` で、観測記録へ取り込むときのクラス → 種別の対応も）、SAM は `{"label", "encoder", "decoder", "inputSize", "mean", "std"}`。`url`・`encoder`・`decoder` は URL か、設定ファイルからの相対パス・絶対パス。URL のモデルは初回に読み込んでプロファイルの `ai_models` に保存する（「設定…」の認証設定を使う）
- メニューの「AI ▸ 検出結果を DB へ転記…」: AI のレイヤー（`class` の属性があるポリゴン・ポイントのレイヤー）の地物を、設定ファイルの `detectionOutputs` の Esri フィーチャーレイヤーへ書き込む。属性は役割ごとの対応（画像ID・ファイル名・撮像日時・検出日時・転記日時・クラス・クラス番号・確信度・モデル・状態・経度・緯度・面積・長辺・短辺・向き・備考）で、型に合わせて変換。状態はモデルのまま（AI）・人が直した（修正: 形かクラスを変更）・人が加えた（手動）。新しい地物は追加、転記後に変えた地物は更新、残りは送らない（何を送ったかはレイヤーに記録し、プロジェクトと一緒に保存）。「選択中の地物だけ」も可。ポイントのレイヤーへはポリゴンの中の点を送る。`detectionOutputs` の形はビューアと同じ（`{"label", "url", "fields": {役割: 属性名}, "statusValues", "constants"}`。プラグインだけの `aiResults` はビューアでは無視。ビューアの `token` はプラグインでは使わない（問題の一覧に出る。サインインは `signIn`））。転記した結果はドック「AI結果」でほかの人も確かめられる（[AI結果](#ai結果外部aiプラグイン内の物体検出)）
- 実行に `onnxruntime` が要る。Windows 版の zip（下の「導入」）には同梱。ほかは QGIS の Python に入れる: OSGeo4W シェルで `python -m pip install onnxruntime`、macOS は `/Applications/QGIS.app/Contents/MacOS/bin/python3 -m pip install onnxruntime`、Linux は `python3 -m pip install onnxruntime`。GPU 版（`onnxruntime-gpu`・`onnxruntime-directml`）を入れれば GPU で動く

## AI 学習（物体検出）

ビューアにはない機能。観測記録（または点・ポリゴンのレイヤー）を教師に、QGIS の中で物体検出のモデルを学習して ONNX で保存する。保存したモデルは「物体検出（AI）…」でそのまま使える。追加のライブラリは不要（QGIS 付属の NumPy だけで学習。通常の zip でも Windows 版でも同じ）。ネットワークは自作で 2 種類: 「高精度」（既定。残差ブロックとバッチ正規化の ResNet 型の本体、1/32 から 1/4 へ戻る FPN、クラスと枠の分離ヘッド、枠はセルからの距離で GIoU 損失、スコアは IoU を学ぶ品質フォーカル損失）と「軽量」（最初の版の小さなネットワーク）。どちらも CPU で学習し、重みの移動平均（EMA）・拡大縮小・回転・反転・明るさの揺らぎで学習する。

- ツールバーかメニュー「AI ▸ AI 学習（物体検出）…」（Processing の「MIKAGE」にも）: 学習する画像（複数可）・教師データ・クラス・バンド・エポック数などを選んで実行。保存したモデルは「物体検出（AI）」のモデルの一覧に「学習済み: 〈ファイル名〉」で並ぶ（詳細設定で外せる）。「学習に使った枠」を出力すると、教師の枠をポリゴンで確認できる
- 教師データ「観測記録」: 観測記録パネルで開いている保存先の記録のうち、各画像の記録（画像 ID が同じもの。消失・削除済みは除く）。枠の大きさは、記録の長さ（2 点で測った m）と向き（3 点・4 点で測った幅があればその幅、なければ分類体系の全幅 / 全長の比） → 分類体系の諸元の「全長」「全幅」 → 詳細設定の既定の大きさ（m）の順。向きが分からなければ、どの向きでも収まる正方形。その画像の確認範囲は「範囲内はすべて記録済み」とみなし、記録のない所を背景として学習する（種別を指定した確認範囲は、学習するクラスがすべてその配下のときだけ）
- 教師データ「ベクタレイヤー」: 点・ポリゴンのレイヤーとクラスのフィールド（空なら `class`・`KIND`・`種別` を探す）。ポリゴンは外接矩形、点は分類の諸元（なければ既定の大きさ）の正方形。`image_id` の属性がある地物はその画像だけに使う（「物体検出（AI）」の結果を手で直したレイヤーをそのまま教師にできる）。「選択した地物のみ」も可
- クラス: 分類体系の種別（`船舶 > 支援船 > 〇〇級`）。分類の深さを指定すると上位にまとめる（1 で `船舶`、2 で `船舶 > 支援船`）。対象の種別（カンマ区切り）を指定するとその配下だけ。分類の名前・別名・英名だけの値（`〇〇級`）も分類体系から種別に直す。検出結果の `class` も種別なので、そのまま観測記録に取り込める
- バンド: 空なら表示のまま（RGB。補正・スタイル込みで「物体検出（AI）」と同じに描く）。番号を指定するとバンドの値で学習する: `4` で単バンド、`1,2,3,4` や `1-4` でマルチバンド。値は学習した画素の平均・標準偏差で正規化し、その値をモデルに保存。「物体検出（AI）」はこのモデルでは表示ではなくバンドの値を読む（バンドが足りない画像は実行しない）
- 追加学習: 「追加学習の元のモデル」にこのプラグインで学習した ONNX を指定すると、その重みから学習を続ける。新しい種別はクラスとして後ろに追加（以前のクラスの番号は変わらない）。入力の大きさ・モデルの大きさ・バンドと正規化は元のまま。以前のクラスを忘れないよう、以前の画像も一緒に指定すると効果的。学習の履歴（日時・画像・クラスごとの件数・検証の結果）はモデルのメタデータ `satobs` に積み上がる
- ネットワーク: 「高精度」（既定）か「軽量」。1 回の更新は軽量が高精度の 2/3 ほどの時間。合成画像（船・航空機・車両と紛らわしい白点、学習 32 枚・評価 12 枚、入力 256・バッチ 8）での比較: 最初の版（軽量、600 回更新、約 11 分）は mAP50 0.652・mAP50-95 0.329、軽量に新しい学習法（1000 回、約 19 分）は 0.932・0.507、高精度（600 回、約 17 分）は 0.961・0.598。`scripts/ai_bench/bench.py --arch res|fpn4` で再現できる
- 学習の進め方: 物体のある所の周り（入力の 1.5 倍の範囲）と確認範囲から無作為な範囲を読み、毎回ランダムな位置で切り出し、0.75〜1.33 倍の拡大縮小・90° 回転・反転・明るさとコントラストの揺らぎを加える。重みは移動平均を保存。15 %（詳細設定）を検証に取り分け、mAP50-95 が最もよいエポックの重みを保存（ログに mAP50・mAP50-95・適合率・再現率）。中止するとそこまでの結果を保存
- 目安: 入力 256・モデル「小」・バッチ 8 で、1 回の更新が CPU で 0.3〜1 秒。1 エポックは最低 20 回の更新。小さな物体は画素を小さく（拡大）、入力の 9 割を超える物体は学習から外れるので画素を大きく

### 教師データセット（カタログにない画像と注釈）

カタログにない画像とその注釈（アノテーション）を、学習に使う「教師データセット」にまとめる。データセットは画像と注釈のファイルの場所（絶対パス）と対応を書いた小さな JSON（`*.json`）で、画像は複製しない。

- メニューの「AI ▸ 教師データセットの作成…」（Processing の `mikage:make_dataset` にも）: 画像のフォルダーと、注釈のフォルダー（空なら画像と同じ）または全画像の注釈ファイルを指定して、保存先の JSON に書く。下のフォルダーも含める（既定）。保存先に既存のデータセットを指定すると追記（フォルダーごとにグループ、同じ画像は追加しない）
- 注釈の形式（「自動」でファイルから判定）: YOLO（画像ごとの `.txt`、`class cx cy w h` の割合。8 値の OBB も可。クラス名は `classes.txt`・`obj.names`・`data.yaml` から、なければ欄で指定）、DOTA（`.txt`）、Pascal VOC（`.xml`、`robndbox` も可）、COCO（全画像で 1 つの `.json`、`file_name` で対応）、ベクタ（GeoJSON・GeoPackage・Shapefile など地図座標。画像ごと、または全画像で 1 つ。クラスのフィールドは空なら `class`・`種別` などを探す）。回転した枠は外接する枠で学習
- 画像と注釈の対応: 同じ名前のファイル。`images/train/a.tif` と `labels/train/a.txt` のような YOLO の並びも対応する。注釈のない画像は除く（「背景として含める」で、何もない画像として学習）
- クラスの対応: `ship=船舶, plane=航空機 > 輸送機` のように、注釈のクラス名を分類体系の種別に。書かない名前はそのまま種別（分類の名前・別名でも可）。その後は観測記録と同じく、分類の深さ・対象の種別で学習するクラスが決まる
- 「AI 学習（物体検出）」の「教師データセット」でデータセットの JSON を選ぶ（複数のフォルダーは 1 つのデータセットに追記してまとめる。Processing のスクリプトからは `;` 区切りで複数も可）。地図上の画像（カタログの画像と観測記録など）と一緒にも、データセットだけでも学習できる。データセットの画像は「すべて注釈済み」とみなし、注釈のない所を背景として学習する。画素は画像のまま（地図上の位置がある画像なら「画素の大きさ」も適用）。見つからないファイルは警告して除外。学習の履歴には「データセット「名前」」と画像名が残る

### アノテーション変換（点→矩形）

点のアノテーション（1 クリックで印を付けた物）を、物の向きに合わせた長さ × 幅の矩形にする。学習の枠は「どの向きでも収まる正方形」より背景が少なくなり、回転矩形（DOTA・YOLO OBB）の教師データにもなる。

- メニューの「AI ▸ アノテーション変換（点→矩形）…」（Processing の `mikage:points_to_boxes`）: 点のレイヤー（観測記録のレイヤー・検出結果・任意の点）と画像を選び、ポリゴンのレイヤーにする。元の属性に `box_length_m`・`box_width_m`・`box_heading`（度、北から時計回り）・`box_size_from`・`box_dir_from`（どこから決めたか）を加える。点以外のポリゴンはそのまま
- メニューの「AI ▸ アノテーション変換（教師データセット）…」（`mikage:dataset_points_to_boxes`）: 「教師データセットの作成」の JSON を読み、点を矩形にした新しいデータセットを書く。YOLO・DOTA・VOC・COCO では幅・高さが「点とみなす大きさ」（既定 2 画素）以下の枠（YOLO の `w = h = 0` など）を点とみなし、画像ごとの DOTA（`.txt`）に書く（ほかの枠はそのまま）。ベクタの点は GeoPackage のポリゴンに（向き・長さ・幅の属性も使う）。注釈は保存先の横の「〈名前〉_labels」フォルダー。クラス名とクラスの対応は元のまま、画像は複製しない。地図座標のない画像（PNG など）は「画素の大きさ（m）」で m を画素に（0 なら長さ・幅を画素で解釈）
- 向き: 点の属性（`heading`・`HEADING`・`heading_deg`・`向き`。2 点入力の観測記録の向き）→ 点のまわりの物の輪郭の最小の回転矩形の長辺（前後は区別しないので 0〜180°）→ 分からなければ「向きが分からない点」（外接する正方形／北向き／変換しない）
- 輪郭の求め方: 「SAM」（既定。`aiModels` の SAM か、エンコーダーとデコーダーの ONNX。「クリック抽出（AI）」と同じモデル）、「簡易（明るさのしきい値）」（モデル不要。点の周りを大津の方法で明暗に分け、点の側の塊。暗い海の明るい船など）、「画像を見ない」（属性と入力値だけ）。点のまわり（物の長さの 4 倍、長さが分からなければ 200 m 四方）を SAM の入力（1024 画素）に描いて解析するので、小さな物も拡大して見る。近くの点は同じ解析を使い回す。輪郭が範囲の半分を超える・範囲を横切るときは輪郭なしとする
- 長さ: 点の属性（`length_m`・`長さ`）→ 「クラスごとの長さ」（`船舶=120, 車両=5`。分類の上位の名前でも可）→ 「長さ（m）」→ 0 なら輪郭の長辺
- 幅: 点の属性（`width_m`・`幅`。3 点・4 点入力の幅）→ 「幅の決め方」: 輪郭の縦横比 × 長さ（既定）／輪郭の実測／長さ × 比率（既定 0.25）／入力値（m）。輪郭がなければ長さ × 比率
- 枠の中心は輪郭の中心に合わせる（詳細設定で外せる。属性の向きを使った点は動かさない）
- 変換したレイヤーは「AI 学習（物体検出）」の教師「ベクタレイヤー」に、データセットは「教師データセット」にそのまま使える

### 観測記録をピクセル座標で書き出す（2026-11-27）

観測記録を、生画像の画素での回転矩形（中心 x・y、長さ、幅、角度、4 隅）として GeoJSON（EPSG:4326）に書き出す。外部の学習環境・ツール用（tsudo「観測記録を、生画像上のポリゴン(つまり、ピクセル座標と幅、長さ、角度)として出力するツールをAI関連の中に」「GeoJSON(EPSG4326)で欲しい」）。

- メニューの「AI ▸ 観測記録をピクセル座標で書き出す…」（Processing の `mikage:records_to_pixel_boxes`）: 画像（開いている画像、複数可）・対象の種別・長さを測っていない記録の扱い（分類体系の全長・全幅、なければ既定の大きさで書く／書かない）・保存先。書いたファイルは地図に追加（枠だけの黄色の線）
- 画素: 画像ファイルのフル解像度の画素、左上が原点、x は右・y は下。記録の PIXEL_X・PIXEL_Y（IMAGE_FILE がその画像のファイルのとき）をそのまま中心に使うので、位置ずらし・クイック幾何補正の上で記録したものも生画像の画素。ない記録（古い記録）は記録の経緯度をいまの画像の配置で画素に（`position_from`: 「記録時の画素」／「記録の経緯度」）
- 形: 記録の長さ・向き・幅（なければ諸元・既定。`size_from`）の地上の矩形の 4 隅を、いまの画像の配置で画素に移し、記録の位置からのずれとして中心に足す。後ろの辺の中点→前の辺の中点を長さの向きとし、4 隅を囲むその向きの矩形にする（画素が地上で正方形でない SAR などでは地上の長方形が平行四辺形になるため）。向きの分からない記録は、地上で max(長さ, 幅) の円を囲む画像の縦横にそろえた矩形（`angle` は null）
- 角度 `angle`: 前（2 点入力の後端→前端）の向き、画像の上（−y）から時計回りの度（0〜360）。`corners_px` は 4 隅の `[x1, y1, …, x4, y4]`、画像で見て後ろ左・前左・前右・後ろ右（時計回り、DOTA と同じ回り）
- ポリゴン: 画素の 4 隅を画像ファイル自身の位置情報（`shift_io.SOURCE` のファイル。位置ずらし・クイック幾何補正の前）で経緯度に（tsudo の選択「生画像の位置情報で置く」）。外周は RFC 7946 に従い反時計回り。位置情報のない画像は geometry が null（画素だけ）
- 属性（この順）: `obs_id`・`image_id`・`image_file`・`cx`・`cy`・`length_px`・`width_px`・`angle`・`corners_px`・`length_m`・`width_m`・`heading`（記録の向き）・`kind`・`object_id`・`object_name`・`size_from`・`position_from`・`image_name`・`image_width`・`image_height`・`image_time`（UTC）・`activity`・`confidence`・`satellite`・`recorded_by`・`lon`・`lat`（記録の位置）。ファイルの最上位の `mikage` に形式（`mikage-pixel-boxes`、版 1）・作成日時・画像の一覧（大きさ、位置情報の有無）・数値の意味
- 書かない記録: 消失・不可・数量 2 以上・削除済み・対象外の種別・画像の上で位置が求まらないもの。確認範囲は書かない。「AI 学習（物体検出）」は変わらず観測記録と確認範囲を直接読む

## AI結果（外部AI・プラグイン内の物体検出）

ほかの AI の処理系が Esri フィーチャーサービスに書いた結果と、プラグインの「物体検出（AI）」で見つけた物（自分のレイヤーと、だれかが「DB へ転記」した結果）を、画像ごとに表示し、選んだものを観測記録に取り込む。ビューアにはない（ビューアの AI は書き出しの「DB へ転記」だけ）。

- 転記した検出結果（2026-11-09 から）: 設定ファイルの `detectionOutputs` の転記先（[`TBL_DETECTION`](../admin/esri-tables.md#tbl_detection検出結果の転記先)）も `aiResultSources` と同じようにその画像の結果を読む。一人が検出して転記した結果を、ほかの人がそのまま確かめて取り込める（ビューアから転記した結果も）。読むのは `fields` の `imageId`（必須。ないものは読まない）・`class`・`score`・`model`・`detectedAt`・`length`・`width`・`note` の属性。種別はプラグイン内の検出と同じ（`aiModels` の `kinds` → 分類体系 → クラス）。一覧の出どころと一時レイヤー「AI検出結果 〈転記先〉（〈画像ID〉）」は転記先の `label`（`aiResultSources` と同じ名前なら「（転記先）」を付ける）。取り込んだ記録の出どころは `AI検出`、AI結果のレイヤーは転記先の `label`、AI結果ID は転記先の `OBJECTID`（[出どころの列](#取り込んだ記録の出どころ)）。`aiResultSources` と同じ URL の転記先と、`"aiResults": false` を書いた転記先は読まない。表の形は変えない（ビューアと共通）
- 自分で転記した結果は一度だけ: 自分の検出レイヤーから転記した結果は、転記先の行を出さずにレイヤーの行だけを出す（一覧の件数の後に「転記先の n 件は自分の検出レイヤーで表示」）。転記後にレイヤーの行を取り込むと、出どころは転記先の行（`label` と `OBJECTID`）になる。どちらから取り込んでも（誤検出にしても）もう一方も「済」（「誤」）になる。転記の前にレイヤーから取り込んだ記録・誤検出は、転記したときに転記先の行へ付け替える（開いている画像の記録。2026-11-27）。付け替える前のもの（別の PC で転記したときなど）は、転記先の行の検出日時（`detectedAt`。秒まで）と記録の位置（転記先の輪郭の中。ポイントは 2 m 以内）・誤検出の確認範囲で同じものとみなす

- プラグイン内の検出: 「物体検出（AI）」を実行して検出結果のレイヤーがプロジェクトに入ると、ドック「AI結果」にその画像（`image_id`）の結果が出る（`aiResultSources` は不要）。地図のレイヤーは検出結果のレイヤーそのもの（複製しない）で、一覧と選択が連動する。レイヤーでクラスを直す・誤検出を消す・輪郭を直すと一覧に反映され、その内容で記録する。検出した画像（またはその検出レイヤー）をアクティブにすると、その画像の結果に切り替わる。種別は `aiModels` のそのモデルの `kinds`（`{"boat": "船舶"}`）→ 分類体系の同じ名前・別名・英名の分類（このプラグインで学習したモデルはクラスが分類体系の種別）→ クラスのまま。取り込んだ記録の出どころは `AI検出`、AI結果のレイヤーは検出レイヤーの名前、AI結果ID は地物 ID で、同じ検出（検出日時が同じ）の同じ地物は二度は取り込まない。長さ・幅はポリゴンの最小の回転矩形の長辺と短辺、継続の自動判定も外部AIと同じ（下記）
- ドック「AI結果」（観測記録と同じ右側のタブ）: 画像カタログから画像を開くと、設定ファイルの `aiResultSources` の各レイヤーから、その画像 ID の結果を読んで（手で開いたカタログ外の画像はファイル名を画像 ID として。Web の背景地図などは対象外）一覧と地図に出す（結果があればドックを表示）。カタログから開いた別の画像をアクティブにすると切り替わり、前の画像の結果レイヤーは消える（一度読んだ画像は読み直さない。「最新を取得」で読み直す）。結果のレイヤーはその画像のすぐ上（画像がグループの中ならそのグループ）に入る（2026-11-26。画像カタログの「前の画像を閉じる」で画像を閉じると、その画像の結果のレイヤーも、「物体検出（AI）」の結果のレイヤーも一緒に外れる: [画像カタログ](images.md)）
- 結果はポイントでもポリゴンでもよい（ライン・マルチポイントも可）。レイヤーは出どころごとに一時レイヤー「外部AI結果 〈名前〉（〈画像ID〉）」で、クラスと確信度のラベル付き。「確信度の下限」より低い結果は一覧と地図から除く
- 一覧と地図の選択は連動。「選択を観測記録へ取り込み」「未取り込みをすべて取り込み」で、その画像の観測記録（ポイント）として記録する。ポイントはその位置、ポリゴンは内側の点で、長さと幅は最小の回転矩形の長辺と短辺（m。`length`・`width` の属性があればそちら）。種別は `kind` の属性 → `kinds` の対応 → クラスの順、名前は `name` の属性（なければ分類の名前）。出どころ（`外部AI`）・AI結果のレイヤー（`label`）・AI結果ID（`fields.id`、なければ `OBJECTID`）・確信度・モデル・検出日時を記録の AI の列に書き、同じレイヤー・ID の記録がある結果は「済」として二度は取り込まない。備考には結果の `note` の属性だけを入れる（AI のことは書かない）
- 取り込みには、その画像が観測記録の画像一覧にあること（開いていること）が要る。保存先は観測記録ドックで選んでいる保存先
- 確認優先（能動学習）: 「並び」が「確認優先（確信度の低い順）」（既定）なら、未取り込み・誤検出でもなく確信度が「確認不要の確信度」（既定 0.80、1.01 ですべて）未満の結果を「要確認」として、確信度の低い順に先頭に並べる（確信度のない結果はその後、確認不要の結果、取り込み済み、誤検出の順）。「次の要確認へ」で最も低い結果を選んで表示、「正（記録して次へ）」で観測記録に記録、「誤検出（次へ）」でその周り（結果の枠より 2 割・5 m 以上広い矩形、ポイントは 20 m 四方）を確認範囲（すべての種別）として記録し、どちらも次の要確認へ進む。誤検出の確認範囲は出どころが `AI誤検出` で、AI の列に結果のレイヤー・ID・確信度などが入る（備考は空）。その確認範囲を削除すると取り消し。確認の結果はそのまま「AI 学習（物体検出）」の教師データ: 記録は物体、誤検出の確認範囲はその周りを必ず背景として学習する（ほかの確認範囲の背景は無作為に選ぶ）。「確認結果で追加学習…」は、この画像と、検出に使った学習済みモデル（「学習済み: …」のとき追加学習の元）を入れて学習のダイアログを開く。並びと確認不要の確信度は前回の値を覚える
- 継続の自動判定（既定。`aiContinuation` で変えられる）: 未取り込みの結果ごとに、前後の画像のモノ（観測記録ドックの白抜きの印）と 1 対 1 で照らし合わせ、一覧の「継続」列に出す。近い（`continueRadius` m 以内か長さの半分以内）・分類が同じか上下・長さの差 30% 以内・ほかに紛らわしいモノがない、のすべてを満たすと「継続: 〈名前〉」が選ばれた状態になり、取り込むとそのモノの継続として記録する（継続の判定 `AI_CONTINUATION` に `自動継続`）。`candidateRadius` m 以内だが確かでないもの（近いモノが複数・分類表にないクラス・同じ大分類の別の分類・長さが違う）は「新規（候補あり）」で、列のリストから選ぶと継続として記録（継続の判定に `選択継続`）。大分類が違うもの（船舶と航空機）は候補にしない。クラスが分類体系にないとき（`kinds` で対応づけていない `ship` など）は、近さと長さだけで候補にする
- 取り込みと誤検出には、観測記録（確認範囲）の層に AI の列（`SOURCE`・`AI_LAYER`・`AI_RESULT_ID`・`AI_SCORE`・`AI_MODEL`・`AI_DETECTED_AT`、観測記録は `AI_CONTINUATION` も）が要る。ない層では「列 … を追加」と出して止める［E704］（[Esri 側のテーブル定義](../admin/esri-tables.md#tbl_observation観測記録)）
- 継続として記録するときの種別は前のモノの種別（AI の種別がそれと同じか下位ならそちら）、活動・長さ・向きは AI 結果になければ前のモノのもの。位置は AI 結果の位置
- 継続の判定は設定ファイルの `aiContinuation`（下記）で変えられる

```jsonc
"aiResultSources": [
  { "label": "船舶検出（外部）",
    "url": "https://example.com/arcgis/rest/services/AI/FeatureServer/0", // ポイントかポリゴンのレイヤー
    "fields": {
      "imageId": "IMAGE_ID",      // 必須。画像カタログの画像IDと同じ値の属性
      "id": "DET_ID",             // 結果ID（なければ OBJECTID）
      "class": "CLASS", "score": "SCORE", "model": "MODEL", "detectedAt": "DETECTED_AT",
      "name": "NAME", "kind": "KIND", "activity": "ACTIVITY", "length": "LENGTH_M", "heading": "HEADING", "width": "WIDTH_M", "note": "NOTE"
    },
    "where": "STATUS <> 'rejected'",       // 画像 ID の条件に AND で足す
    "minScore": 0.3,                       // 確信度の下限の初期値（0〜1。百分率の値は 100 で割る）
    "kinds": { "ship": "船舶", "plane": "航空機" }, // クラス → 種別
    "activity": "停泊", "confidence": "推定",       // 結果にないときの活動・確度（確度は保存先の段階にあるときだけ）
    "continuation": { "rules": [{ "label": "外形の中", "centerInRecord": true }] }, // この出どころだけの継続の判定（下記。書いたキーだけ aiContinuation より優先）
    "continueRadius": 50,                  // 古い書き方: これより近い（m）前後の画像のモノは確かなら自動で継続（0 で自動にしない）
    "candidateRadius": 300,                // 古い書き方: これより近い（m）ものを継続の候補に（0 で照合しない）
    "maxResults": 2000 }
]
```

### 取り込んだ記録の出どころ

AI の結果から取り込んだ記録は、どの AI のどの結果から来たかを備考でなく列に持つ（2026-11-27。tsudo「AIのどのレコードからかも識別したい」「備考の役割を無くそう」）。備考は人が書く欄で、プラグインは AI の印を書かず、読まない。

| 列（役割） | 中身 |
| --- | --- |
| `SOURCE`（`aiSource`） | `AI検出`（プラグイン・ビューアの物体検出、転記した検出結果、似たものを探す）・`外部AI`（`aiResultSources`）。人の記録は空。誤検出の確認範囲は `AI誤検出` |
| `AI_LAYER`（`aiLayer`） | 結果のある表・レイヤー（転記先・外部 AI の `label`、転記していない検出結果は検出レイヤーの名前） |
| `AI_RESULT_ID`（`aiResultId`） | その表での結果の ID。`AI_LAYER` と 2 つで AI のどの行かが決まる |
| `AI_SCORE`・`AI_MODEL`・`AI_DETECTED_AT` | 結果の確信度（0〜1）・モデル・検出日時 |
| `AI_CONTINUATION`（`aiContinuation`） | 継続として取り込んだときの判定（`自動継続`・`自動継続:〈ルール名〉`・`選択継続`）。観測記録だけ |

- 観測記録ドックの一覧の「出どころ」列に `AI検出 0.87` のように出る（指すとモデル・確信度・レイヤーと ID・継続の判定）。記録を開くと入力欄の「備考」の下に「出どころ」の行が出る（AI の記録だけ。直せない）
- 記録を人が直しても出どころは変わらない（その結果から作った記録のまま）。手で「継続」した記録は人の記録（出どころは空）
- 二重取り込み・誤検出・AI 学習の「必ず背景にする範囲」は、この列だけで判定する。前からある記録の備考の印 `[AI:…]` は読まない（列へ移す SQL は [docs/arcgis-setup.md](../arcgis-setup.md#観測記録に-ai-の出どころの列を足す)）
- 書き出し（`aiSource`・`aiLayer`・`aiResultId`・`aiScore`・`aiModel`・`aiDetectedAt`・`aiContinuation`。標準の CSV・JSON では末尾）、通報の項目、レイヤーとして追加、データに質問、ダッシュボードのビュー `VW_OBS_RECORD` でも使える

### 継続の判定（aiContinuation）

AI結果のどれを前後の画像のモノの続き（継続）として自動で記録するかを、ルールで決める（2026-11-26 から）。外部 AI（`aiResultSources`）・転記先（`detectionOutputs`）・プラグイン内の検出・「似たものを探す」のすべてに効く。出どころごとに変えたいときは `aiResultSources` の `continuation` に同じ形で書く（書いたキーだけ優先し、ほかは `aiContinuation` のもの）。書かなければ、これまでどおりの判定（50 m 以内か長さの半分以内・分類が同じか上下・長さの差 30% 以内・紛らわしいモノがない。候補は 300 m 以内）。

- `rules`: 自動継続のルールの配列。1 つのルールの中の条件はすべて満たす（AND）。ルールはどれか 1 つに当てはまれば自動継続（OR）。上から順に見て、最初に当てはまったルールの名前を「継続」列（「継続: 〈名前〉（〈ルール名〉・12 m・同じ分類）」）と備考（`[自動継続:〈ルール名〉]`）に出す。ルールには位置の条件（`near`・`centerInRecord`・`recordInAi`・`overlap`）が 1 つは要る
  - `label`: ルールの名前（省略すると条件から「重心が外形の中・同じ大分類」のように）
  - `near`: 記録の位置からの距離（m）以内。長さのあるモノは長さの半分まで広げる
  - `centerInRecord`: AI の重心（ポリゴンの重心。ポイントはその位置）が、記録の外形の中。外形は 3 点・4 点入力で幅まで測った記録の長さ × 幅 × 向きの矩形で、幅のない記録は当てはまらない
  - `recordInAi`: 記録の位置が AI のポリゴンの中（点だけの記録向け）。ポイントの結果は、長さ・幅・向きの属性があればその矩形
  - `overlap`: AI のポリゴンと記録の外形の重なり率（重なった面積 ÷ 2 つを合わせた面積、IoU）がこの値以上（0〜1）。両方に外形があるときだけ
  - `kind`: 種別の一致。`same`（同じ分類）・`related`（同じか上下）・`sibling`（同じ大分類）・`any`（見ない）。省略すると見ない（分類体系にないクラスも可）が、大分類が違うもの（船舶と航空機）は `any` でない限り継続にも候補にもしない。`same`・`related`・`sibling` では分類体系にないクラスは当てはまらない
  - `lengthGap`: 長さの差（長い方に対する割合、0〜1）の上限。どちらかに長さがなければ見ない
  - `headingGap`: 向きの差（°）の上限。どちらかに向きがなければ見ない
  - `minScore`: AI の確信度の下限（0〜1）。確信度のない結果は見ない
- `candidateRadius`: これより近いもの（か長さの 2 倍以内）を「新規（候補あり）」に出す（m、既定 300）。0 でルールに当てはまるものだけ
- `unique`: 既定 `true`。ほかに紛らわしいもの（同じモノに当てはまる別の結果、同じ結果に当てはまる別のモノ）があれば候補止まり。`false` では、当てはまるもののうち最も確からしい組を自動継続にする（同じモノを 2 つの結果が継続することはない）
- `false` と書くと照合しない（「継続」列は出ない）。`aiResultSources` の `candidateRadius: 0` も同じ（これまでどおり）
- 設定ファイルを固定（`config.lock`）した zip では、管理者が決めたルールがそのまま使われる

```jsonc
"aiContinuation": {
  "rules": [
    { "label": "外形の中", "centerInRecord": true, "kind": "sibling" },     // AI の重心が記録の外形の中で、同じ大分類
    { "label": "AIの範囲の中", "recordInAi": true, "kind": "related", "minScore": 0.6 }, // 点だけの記録が AI のポリゴンの中
    { "label": "近くて同じ分類", "near": 50, "kind": "related", "lengthGap": 0.3 }    // これまでの判定と同じ
  ],
  "candidateRadius": 300,
  "unique": true
}
```
