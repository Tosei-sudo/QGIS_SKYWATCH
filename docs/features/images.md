# 画像カタログ・通知

画像の検索・表示と、新着画像の通知。（[README](../../README.md) から機能ごとに分けた説明。）

## 画像カタログ

「画像カタログ」ドックで `imageCatalogs` の画像を検索する。範囲（既定は表示範囲。「範囲を描く」で地図に多角形を描いて「描いた範囲」も。クリックで頂点、ダブルクリックか右クリックで確定、Esc で取消。描いている途中の形も地図に出る。描いた範囲は「保存…」で名前を付けて保存し、あとで「保存した範囲」から選べる（下記））、「レイヤー」でベクターレイヤーを選ぶとその地物の形そのもの（外接矩形ではなく。ポリゴンは結合、ラインはライン、ポイントは複数点として。「選択地物のみ」も可）と重なる画像）、撮像日時、フリーワード（下記）、「詳細条件」で登録日時・システム登録日時・センサー（「、」で区切って複数も。どれかのセンサー: `IN`。2026-11-25、[文で操作](screen.md#文で操作command)の「SAR画像」がここに SAR のセンサーを入れる）・角度の上限・方位角・SQL。日時は日付だけ（その日いっぱい）か、時刻つき（`2026-11-09 10:30`。分の単位、秒まで書けば秒の単位。右の欄は `12:00` と時刻だけなら左と同じ日）。時刻はこの PC の時刻（一覧の日時と同じ）で、ソースの `timeZone` は日付の属性と同じく反映する。文字列の日時の属性は値を 1 件読んで同じ書き方（`T` か空白、オフセット）で比べる。

- 「フリーワード」: カタログの `fields.keywords` に書いた属性（文字列の属性。1 つなら文字列、複数なら配列）と画像 ID（`fields.id`。`keywords` に書かなくても常に対象。2026-11-18）のどれかに、入力した語を含む画像を探す（部分一致）。空白（全角も）で区切ると、すべての語を含む画像（語ごとにどれかの属性に含めばよい）。大文字・小文字、ひらがな・カタカナ、全角・半角（`ＥＶ０１` と `ev01`）は区別しない。欄で Enter を押しても検索。`fields.keywords` も `fields.id` もないカタログでは欄を出さない。欄の薄字に対象の属性（`columns` か役割の見出し、なければ属性名）
  - 問い合わせは語ごとに `(UPPER(属性) LIKE '%語%' ESCAPE '\' OR …)` を AND でつなぐ。語は値として扱う（`'` は二重に、`%`・`_`・`\` はエスケープするので「50%」は 50% という文字だけに合う）。10 語・1 語 100 文字まで。数値・日付の属性は対象にしない（すべてそうなら理由を表示）
  - 「この条件で監視…」の監視条件・「類似画像の検索」・「ビュー」にもフリーワードが残る
- 「保存した範囲」（2026-11-19）: 「描いた範囲」で描いたら、横の「保存…」で名前を付けて保存する。範囲を「保存した範囲」にすると、保存した範囲を新しい順に選べ、選んだ範囲は地図に緑の破線で出る（地図に見えない場所ならそこへ移動）。横の「編集」で「範囲へ移動」「名前の変更…」「削除…」。同じ名前で保存すると確認してから置き換える
  - 保存先は自分の PC の QGIS のユーザー設定（`mikage/catalog/savedAreas`。「ビュー」と同じく人ごと・PC ごと。設定ファイル・プロジェクト・Esri には書かない）。300 件まで（超えると古いものから消える）。座標は WGS 84
  - 「ビュー」は選んだ保存範囲も覚える。「この条件で監視…」では保存した範囲を「描いた範囲」として渡す（監視は範囲の写しを持つので、あとで保存範囲を消しても監視は変わらない）
  - `LIKE '%…%'` は属性インデックスが効かないので、件数の多いカタログでは撮像日や範囲と一緒に使う

```jsonc
"imageCatalogs": [
  { "label": "衛星画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0",
    "fields": { "id": "IMG_ID", "sensor": "SENSOR", "source": "PATH", "keywords": ["NOTE", "AREA_NAME", "IMG_ID"] },
    "columns": [{ "field": "NOTE", "label": "備考" }, { "field": "AREA_NAME", "label": "地域" }] }
]
```

- 「画像 ID で開く」（ドックのいちばん上）: 画像 ID を貼って Enter で開く。開いた画像の履歴にあれば下の確認から、なければ `fields.id` のあるカタログ（選んでいるカタログが先）に `IMG_ID IN ('…')` で問い合わせ（タスクで）、一覧から開くのと同じに開く。画像ファイルのないカタログ（`imageFiles: false`）ならファイルなしで記録。どのカタログにもなければその旨を表示。空白・読点で区切って複数貼ったときは先頭の 1 つ
- 開いた画像の履歴（この PC、2026-11-18）: 画像カタログ・新着画像のカード・イベント・計画のどこから開いても、画像 ID・カタログ・ファイルの場所（フォルダならその中で見つかったファイルと開いたファイル）・カタログの属性を QGIS のプロファイルの `mikage/opened_images.json` に記録する（新しい順、カタログと画像 ID ごとに 1 件、最近の 300 枚。パスはこの PC のものなので共有しない）
  - 同じ画像を「画像 ID で開く」「最近開いた画像」から開くと、カタログに問い合わせず確認「前回のファイルで開く」を出す（毎回）。カタログ・前回開いた日時・場所と、フォルダならファイルの一覧（前回開いたものにチェック、それぞれ「あり」「なし」）。Enter（「開く」）でチェックしたファイルを開く。「カタログで探し直す」は履歴を使わずカタログを画像 ID で引く。ファイルが見つからないときも、カタログで探し直す
  - 「最近開いた画像」ボタン: 履歴の新しい 20 件（画像 ID・撮像日時・センサー・ファイル数）。「画像 ID で開く」欄の補完にも履歴の画像 ID
- 分担（[`assignments`](observations.md#分担と引き継ぎメモassignmentshandover)）を設定していると、一覧の最後の列「分担」に画像ごとの状態: 「未着手」（誰も担当にしていない）・「作業中（名前）」「保留（名前）」・「完了（最後に完了にした人）」。検索の後と、ドックを表示している間は 1 分ごとに読み直す。検索ボタンの横の「未着手のみ」で、未着手の画像だけを一覧に出す（読み込み前の行も隠す）
- 一覧は新しい順で、見出しのクリックで並べ替え（空の値は常に最後。選んだ行はその画像についていく）。地図に全件のフットプリント（青）と選んだもの（橙、画像 ID 付き）。「地図で選択」を押すとフットプリントのクリックで選べる（Ctrl・Shift で追加）
- 1 回の検索で読むのは新しい順に `maxResults` 件（既定 500）。該当がそれより多いと状況欄に「1234 件中 新しい 500 件」と出て、一覧の下の「続きを読む（次の 500 件）」で次の（古い）画像を一覧に足す（全部読むとボタンは消える）
  - 続きは検索したときの範囲と条件のまま（検索の後に地図を動かしたり条件を変えたりしても、元の検索の続き）。足した画像も今の並べ替えの順に入り、選んだ行・スクロールの位置はそのまま。分担の列は足した画像の分も読み直す
  - 「類似画像の検索」でも候補の続きを読み（状況欄に「類似画像 12 件（候補 2000 件中 新しい 500 件から）」）、読んだ候補全体で似ている順に並べ直す。イベントから開いた画像の一覧などは検索ではないので出ない
  - サービスの `maxRecordCount`（1 回の応答の上限。ArcGIS の既定は 1000 か 2000）が `maxResults` より小さくても、上限ごとに分けて（`resultOffset`）`maxResults` 件まで読む。並びは撮像日時（なければ登録日時）の新しい順、同じ時刻はオブジェクト ID の大きい順なので、続きで画像が抜けたり重なったりしない（検索の後に新しい画像が登録されて同じ画像がもう一度来たときは 1 回だけ出す）
  - 並べ替えか件数指定（`supportsPagination`・`supportsOrderBy`）のできない古いサービスは、1 回の応答の分だけ読んで手元で新しい順に並べ、「続きを読む」は出ない
- ボタンは幅に合わせて折り返して並び、その下に「前の画像を閉じる」「開いた画像へ移動」「投影法を画像に合わせる」「向き」「フットプリント」が 1 行に 1 つずつ並ぶ（2026-11-25、オプションが増えたため）
- 「フットプリント」で地図の表示を選ぶ（PC ごとに記憶）: 「枠だけ」（既定。塗らずに枠線だけ、画像 ID は範囲の上端に出して画像の中央を隠さない）・「塗りつぶし」（以前の表示。範囲を薄く塗り、画像 ID は中央）・「非表示」（フットプリントを出さない。「地図で選択」のクリックは効き、描いた範囲は枠で残る）
- 「開く」かダブルクリックでラスターレイヤーに。URL は `/vsicurl/`、ローカルパスは `pathMappings` に従う（`url` があればそれ、なければそのままのパス、だめなら初回にフォルダを選び記憶。メニュー「設定…」の「画像のフォルダの対応」の「対応を消去」で忘れる）。`pattern`・`to` の読み替えがあれば先にその場所を試し、なければ元のパスで開く（[下記](#パスの読み替えpathmappings)）。開けないときは理由を表示。「パスをコピー」で場所をクリップボードへ
- 「フォルダを開く」で、選んだ画像のフォルダをエクスプローラーで開く（Windows。ほかの OS はファイルマネージャー）。パスがファイルのレコードはそのフォルダをファイルを選んだ状態で、フォルダのレコードはそのフォルダを開く。`pattern`・`to` の読み替えがあれば、読み替えた先があるときはそちら（フォルダは中に画像がなくてもよい）、なければ書かれたパス（`prefix` のフォルダ未選択なら「開く」と同じく選ぶ）。URL（COG・`pathMappings` の `url`）の画像は開けるフォルダがないので理由を表示。複数選ぶと、同じフォルダは 1 回、窓は 5 つまで
- レイヤーの名前は画像 ID（1 レコード 1 枚のとき。フォルダのレコードで 1 枚だけ開いたときも）。複数枚のレコードは画像 ID のグループに、各レイヤーはフォルダからのパスの名前で入る
- 「前の画像を閉じる」にチェックすると（PC ごとに記憶）、画像を開くたびに、その前にこのドックから開いた画像のレイヤー（複数枚のレコードはグループごと）をプロジェクトから外す。一覧を上から順に見ていくときに、開いた画像がたまらない。開けなかったとき・取り消したときは外さない。チェックする前に開いた画像・ほかのドックや手で開いた画像はそのまま
  - その画像の AI 結果と、空になったグループも外す（2026-11-26、tsudo「前の画像を消す動作のとき、AI結果レイヤーがある場合は、それも消してほしいのと、グループレイヤーも消してほしい」。`catalog_io.close_layers`、「新着画像」の「前の画像を閉じる」も同じ）:
    - AI 結果: 「AI結果」ドックがサーバーから読んだ結果のレイヤー（「外部AI結果 …」「AI検出結果 …」。また開けば読み直す）と、「物体検出（AI）」「似たものを探す」の結果のレイヤーのうち、中の `image_id` がすべて閉じる画像のもの。外さないもの: 同じ画像のほかのレイヤーがまだ開いている、編集中で保存していない変更がある、ほかの画像の結果も入っている、AI 抽出・土地被覆分類・変化抽出（「AI結果」の結果ではない）。画像 ID はカタログの ID（カタログ外の画像はファイル名。検出の `image_id` と同じ）
    - グループ: 外したレイヤーが入っていたグループのうち、それで空になったもの（レコードのグループも、画像を手で入れたグループも）と、それで空になった上のグループ。ほかのレイヤーやグループが残るもの・もともと空のもの・「一番上に固定」したものは残す
    - 一時レイヤーの検出結果は外すと戻らない（観測記録に取り込んだ記録は残る。検出をやり直せば作り直せる）
    - QGIS は新しいレイヤーを選んでいるレイヤーの上（そのグループの中）に入れるので、複数枚のレコードのグループに AI 結果が入ってグループが空にならず、結果とグループが残っていた。「AI結果」ドックの結果のレイヤーは、その画像のすぐ上（同じグループ）に入れるようにした（画像がまだレイヤー一覧に入っていないときは入ってから。画像がなければこれまでどおり QGIS の入れる場所）
- もう開いている画像（同じ画像 ID の同じファイル。位置ずらし・複素 SAR の変換後も同じ）を「開く」・ダブルクリック・「最近開いた画像」・通知（新着画像）・イベントで開き直すと、レイヤーを足さずにそのレイヤーを選ぶ（2026-11-23、操作性点検 3。それまでは同じレイヤーがもう 1 つ増え、観測記録では「2 ファイル」の画像になっていた）。フォルダのレコードで別のファイルを選んだときは、開いていないファイルだけを足す
- 観測記録の分担を「この画像を担当」「完了」「手放す」で変えると、一覧のその画像の「分担」の列をすぐ読み直す（2026-11-23、操作性点検 7。それまでは再検索か 3 分ごとの読み直しまで古いまま）
- 画像の評価（[`imageReviews`](observations.md#画像の評価imagereviews)）を設定していると、分担の隣（分担がなければ画像 ID の隣）に列「評価」: 画像全体の評価、なければ地名ごとの評価（揃っていればその評価、違えば「一部（使えない 1/3）」）を色付きで。地名ごとの内訳はツールチップ。検索の後・「続きを読む」の分・ドックを表示し直したときに読み、観測記録で評価を保存するとその画像の行をすぐ読み直す
- 「開く」・ダブルクリックで画像を開くと、地図がその画像ファイルの範囲へ移動・ズームする（複数枚のレコード・複数のレコードを開いたときは、開いたファイルすべてを囲む範囲。各画像の座標系から地図の座標系に変換して、少し余白をつける）。開けなかったときは動かさない。「開いた画像へ移動」を外すと移動しない（PC ごとに記憶、既定はオン）。地図を回しているときは、回した画面に画像全体が収まるように合わせる（QGIS の範囲指定は回転を考えないため）。「範囲へ移動」も同じ
- 「投影法を画像に合わせる」（PC ごとに記憶、既定はオフ。2026-11-25）にチェックすると、画像を開くたびに地図（プロジェクト）の座標系をその画像の座標系にする。画像が経緯度（EPSG:4326 など）のとき・GCP や RPC で置かれているときは、画像の中心の UTM 帯（WGS 84 / UTM、EPSG:326xx・327xx）にする（経緯度の地図は東西に伸び、回すと形がゆがむため）。複数の画像を一度に開いて投影法が違うときは、一覧で最初の画像に合わせる。ほかのレイヤー（背景地図・観測記録など）は QGIS がその場で地図の座標系に変換して重ねる（位置はずれない。その分だけ描画が少し重くなることがある）
- 「向き」（PC ごとに記憶、既定は「北が上」。2026-11-25）で、画像を開くたびに地図を回してその向きを上にする: 「北が上」（回さない）・「撮像方向が上（衛星が下）」（衛星から地上を見る向き。光学の斜め撮りではビルが上へ倒れて見える）・「衛星が上（撮像方向が下）」（SAR の影が下へ伸びる）・「進行方向が上（SAR）」。真北を上にするので、地図の座標系の格子の北とのずれ（子午線収差）も入れて回す。地図が経緯度のときは、チェックがなくても画像の中心の UTM 帯にする
  - 衛星の方位は、カタログの方位角（`fields.azimuth`。地上から見た衛星の方位）→ クイック幾何補正で入力した衛星の方角 → 画像のメタデータ（クイック幾何補正と同じ読み方: SICD の AzimAng、進行方向と右／左観測、昇交／降交と緯度、Sentinel-1。光学は簡易オルソ補正と同じ `meanSatAz`・`satellite_azimuth` など、同じ名前の .IMD も）→ GCP で置かれた SAR は画像の列の向き（近いほうが衛星側）の順に探す
  - 進行方向は、画像のメタデータの進行方向（`heading`・`track_angle`、昇交／降交と緯度）→ SAR（センサー名に SAR・レーダー、複素 SAR、SAR のメタデータ）は衛星の方位から観測の側（既定は右、メタデータに左とあれば左）へ 90° → GCP・RPC で置かれた画像は行の向き（行は撮った順）の順に探す
  - 方位がわからないとき、カタログの角度がオフナディア 3° 未満（ほぼ真下から撮った光学画像）のときは北が上のまま。地図の回転・投影法を変えたときと回さなかった理由はドックの状況欄に出る（「地図: WGS 84 / UTM zone 54N、撮像方向が上（回転 80°、カタログの方位角から）」「地図: 北が上のまま（衛星の方位がわからない…）」。開いている画像を選び直したときも、その下の行に）
  - 複数の画像を一度に開いたときは、一覧で最初の画像に合わせる。「前の画像を閉じる」で次々に見るときは、画像ごとに投影法と向きが変わる
  - 向きや投影法を変えた画像がすべて閉じられたら（レイヤーの削除・「前の画像を閉じる」）、最初に変える前の座標系と回転に戻す。その間に自分で座標系や回転を変えたら（QGIS のステータスバー・北の矢印など）、変えたほうは戻さない。プロジェクトを開き直すと戻す情報は忘れる（回したまま保存したプロジェクトは回ったまま開く）
  - 地図が回っている間は、地図の右上に北の矢印が出る（どこから回しても）。クリックすると北が上に戻る（投影法はそのまま）
  - 地図を回していても、観測記録の描画・ドラッグ・2 点で測る・座標の表示と移動は経緯度で扱うので変わらない。記録の「向き（°）」も北基準のまま。フットプリント・観測記録の印・位置ずらし・影から高さ・スワイプは回転にそのまま追従する。範囲「表示範囲」の検索は、回した画面の四角そのもの（画像カタログ。ほかのドックの「表示範囲」は、回した画面を囲む少し広い範囲）。ラスターの背景地図の文字は地図と一緒に回る
- 開いたレイヤーはカタログの属性をカスタムプロパティとメタデータに持つ（`satobs/imageId` は観測記録と AI結果が使う）
- 「レイヤーとして追加」で一覧をフットプリントのメモリレイヤーに（撮像日時で時系列コントローラーが効く）
- 「類似画像の検索」（一覧のボタン、またはカタログから開いたレイヤーの右クリック「類似画像の検索…」）で、同じセンサー・角度 ±5°・方位角 ±20° の画像を重なりの大きい順に。比較元は赤い破線。許容差は記憶。「通常の検索に復帰」で戻る
- パスが画像ではなくフォルダのレコード: フォルダの下（階層は何段でも）のファイルのうち、カタログの `imagePatterns` に合うものをそのレコードの画像とする（下記）。画像が複数なら「開く画像の選択」で選んで（1 列目にファイル名、2 列目にフォルダからのパス。既定は全部。絞り込み（ファイル名・パスの一部）・表示中をすべて選択／解除あり。行をダブルクリックするとその画像だけを開いて閉じる）、レコードの画像 ID の名前のグループにまとめて開く。各レイヤーの名前はフォルダからのパス（1 枚だけ開いたときはグループにせず、レイヤーの名前は画像 ID）、`satobs/imageId` はレコードの ID（観測記録・AI結果はレコード単位で共有）、`satobs/imageFile` にフォルダからのパス。1 枚だけなら聞かずに開く。通知から開くときも同じ
  - 「観測記録」ではレコードの画像をまとめて 1 つの画像として扱う: 画像の一覧に 1 行（名前は画像 ID、「（3 ファイル）」のように開いた数）、どのファイルの上をクリックしてもそのレコードに記録（画像名も画像 ID）。レイヤーパネルで同じレコードの別のファイルを選んでも画像は変わらず、開いているフォームもそのまま。「この画像のみ」はレコードのファイルをすべて表示、◀ ▶ はレコード単位、前後の画像のモノ・「画像全体を確認済み」はファイルをすべて囲む範囲、「似たものを探す」は見本のあるファイルで探す

### フォルダのレコードの画像（`imagePatterns`）

センサーごとにフォルダ構成・ファイル名の規則が違うので、カタログごと・センサー（`fields.sensor` の値。大文字小文字と前後の空白は区別なし）ごとに正規表現を書く。`*` はそれ以外のセンサー。

```jsonc
"imageCatalogs": [
  { "label": "衛星画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0",
    "fields": { "id": "IMG_ID", "sensor": "SENSOR", "source": "PATH" },
    "imagePatterns": {
      "WV03": "-P1BS-[^/]*\\.TIF$",                                   // パンクロだけ
      "SPOT7": ["^IMG_[^/]*_P_[^/]*/.*\\.JP2$", "^IMG_[^/]*_MS_[^/]*/.*\\.JP2$"],  // 配列ならどれかに合うもの
      "*": "\\.tiff?$"
    } }
]
```

- 正規表現（Python の `re`、大文字小文字は区別なし）は、レコードのフォルダからのパス（区切りは `/`。例 `IMG_01_P_001/IMG_01.JP2`）の一部に合えばよい。全体に合わせるなら `^…$`
- 全センサー共通なら文字列か配列だけでも可（`"imagePatterns": "\\.ntf$"`）
- 書かない、または合うセンサーも `*` もないときは、ふつうの画像ファイル（`.tif`・`.tiff`・`.jp2`・`.j2k`・`.ntf`・`.nitf`・`.img`）。`.aux.xml`・`.ovr` などは合わない
- 探すのは QGIS を止めずに裏で行い、少しかかると「取消」できる進み具合の窓が出る。フォルダは 8 階層まで、ファイル・フォルダ 5 万件・60 秒までで打ち切り（理由を表示）。シンボリックリンク・ジャンクションはたどらない。読めないサブフォルダの数も「画像なし」の理由に出す
- 1 フォルダから最大 1000 枚まで（超えたら先頭のみ。選択画面に表示）。フォルダの場所は画像ファイルと同じく `pathMappings` に従う（大文字小文字を区別せずにたどる）。URL（COG・`pathMappings` の `url`）のフォルダは一覧できないので不可
- 正規表現の誤りは設定の問題に表示し、その正規表現だけ使わない

### 画像ファイルのない画像（「ファイルなしで記録」・`imageFiles`）

生データが別システムにしかなく、カタログ（フットプリントと属性）だけがある画像も、画像を開かずに観測記録を作れる。

- 一覧で画像を選び（Ctrl・Shift で複数）「ファイルなしで記録」: その画像を「観測記録」の画像一覧に「ファイルなしの画像」として入れる。画像 ID・名称はカタログの画像 ID、撮像日時はカタログの撮像日時、範囲はフットプリントの外接矩形（前後の画像のモノ＝継続候補をこの範囲に限る）。地図にはフットプリントの形のまま枠のレイヤーが入る（下の「地図の枠のレイヤー」）。手入力の ＋ と違って打ち間違いがなく、開いたときと同じ画像 ID なので、あとで画像を開いても同じ画像の記録になる（分担・イベント・通報も同じ ID で）
- 1 件目の画像に切り替わり、「観測記録」ドックが前に出て、地図がその画像の範囲へ移る。「クリック記録」（R）で背景地図・フットプリントの上をクリックして記録。◀ ▶ でファイルなしの画像に移ると、その範囲が地図の外なら地図も移る
- もう入っている画像は、カタログの値で入れ直す。同じ ID の画像を開いていれば、その画像で記録する
- **「前の画像を閉じる」**（2026-11-25、tsudo「画像ファイルなしの画像カタログの画像も、前の画像を消すを利かしてほしい」）: チェックがあると、「ファイルなしで記録」（ダブルクリック・メッセージバーのボタン・「画像 ID で開く」も）で次の画像を入れたとき、その前にこのドックから（チェックした状態で）入れたファイルなしの画像を「観測記録」の一覧から外し、枠のレイヤーも消す（「一覧から除外」と同じ。記録は残る）。開いた画像とファイルなしの画像は区別せず、どちらも「前の画像」: ファイルなしで入れるとその前に開いた画像のレイヤーを閉じ（同じ画像 ID のものは残す）、画像を開くとその前にファイルなしで入れた画像を一覧から外す。今回入れた画像は外さない（複数選んだときはすべて残る）。入れられなかったとき（画像 ID なし・保存先なし）は何も外さない。チェックする前に入れた画像・＋ で入れた画像・通知やイベントから入れた画像はそのまま。画像ファイルのないカタログ（`imageFiles: false`）でもこのチェックを出す（「ファイルなしで記録」が使えない担当では出さない）
- **地図の枠のレイヤー**（2026-11-18）: ファイルなしの画像は 1 枚ずつ、レイヤー一覧のいちばん上のグループ「ファイルなしの画像」に一時レイヤー（メモリ）として入る。名前は画像の名称（範囲のない画像は「（範囲なし）」付きで形なし）、形はカタログのフットプリント（＋ で「範囲: 地図の表示範囲」にしたものはその矩形）、属性は画像 ID・名称・撮像日時。紫の枠だけ（中はクリックで記録するので塗らない）、名前は枠の外。記録中の画像は太い実線、ほかは細い破線。一覧は QGIS を起動している間だけ（新規プロジェクト・別のプロジェクト・保存先の切り替え・プラグインの再読み込みでは残る）。QGIS を閉じると、開いた画像と同じく次の起動では一覧にもレイヤーにも出ない（記録は残る。2026-11-26、tsudo「画像なしの画像カタログから観測結果を入れたあと、QGIS を落として、また立ち上げると、レイヤーが残っている」）。枠のレイヤーを足しても、プロジェクトは変更ありにならない（QGIS が閉じるとき・次の起動時に「現在のプロジェクトを保存しますか？」と聞かない）
  - レイヤーを選ぶとその画像に切り替わり、◀ ▶ などで画像を替えるとそのレイヤーが選ばれる（開いた画像のレイヤーと同じ）。「この画像のみ」ではほかの画像の枠も隠す
  - **レイヤー（またはグループごと）を削除すると、その画像は「観測記録」の一覧から外れる**（「一覧から除外」と同じ。記録は残る）。開いた画像のレイヤーを閉じると一覧から消えるのと同じ使い方
  - 一覧は今までどおり保存先ごとに QGIS が覚えていて、レイヤーはそれに合わせて作り直す: 保存先を替えるとその保存先の画像の枠に、新しいプロジェクト・別のプロジェクトを開いても（一覧から外さずに）枠がまた入る。プロジェクトを変更したことにはならず、閉じるときに「一時レイヤーを保存しますか」とも聞かない。編集はできない（読み取り専用）
- 画像ファイルのないカタログ（全件が別システム）は `imageFiles: false`。そのカタログでは「開く」「パスをコピー」「フォルダを開く」と一覧の「場所」の列を出さず、「ファイルなしで記録」を常に出す（ダブルクリックも「ファイルなしで記録」）。`fields.source` は不要。通知・イベントからそのカタログの画像を「開く」と、同じくファイルなしで観測記録へ
- ふつうのカタログ（`imageFiles` なし・`true`）では「開く」のまま。画像の場所がない・開けないときは、メッセージバーの理由の横に「ファイルなしで記録」が出る

```jsonc
"imageCatalogs": [
  { "label": "他システムの画像", "url": "https://gis.example/arcgis/rest/services/OtherCatalog/FeatureServer/0",
    "imageFiles": false,
    "fields": { "id": "SCENE_ID", "acquired": "ACQ_TIME", "sensor": "SENSOR" } }
]
```

### 練習モードだけ・本番だけ・両方（`mode`）

画像カタログごとに、どのモードで出すかを選ぶ（tsudo 2026-11-23「練習専用画像カタログを登録できるようにして」）。

| `mode` | 本番 | 練習モード |
|---|---|---|
| `"production"`（既定。書かないとき） | 出す | 出さない |
| `"training"` | 出さない（判読練習の指導者の担当にだけ、画像カタログに「〇〇（練習用）」で出す） | 出す |
| `"both"` | 出す | 出す |

- 本番の「練習モードだけ」のカタログは、画像カタログ・新着画像・監視・撮像結果の照合・イベントの画像のどこにも使わない。判読練習の指導者（担当 `INSTRUCTOR`）には、問題の画像を開くために画像カタログのドックだけに出す（「この条件で監視…」は出さない）。担当をまだ選んでいない人には出さない（`core/roles.CHOSEN_ONLY`）。認証の選択（「設定…」のサービス一覧）には「（練習用）」付きで載る
- 練習モードでは、練習データのカタログ（内蔵の見本か、組織の練習用設定ファイル `training.config` のもの）の後ろに、本番の「練習モードだけ」「両方」のカタログを足す（`mikage/core/training/masters.py` の `with_practice_catalogs`）。`training.fromProduction` にかかわらず足す。練習用の設定ファイルと同じ URL・`where` のカタログは足さない。練習用の設定ファイルの中の `mode` は見ない（その中のカタログはすべて出す）
- 本番のカタログは読むだけ（MIKAGE は画像カタログに書かない）。トークンは練習中もメモリーにだけ持ち、練習用の設定ファイル（ディスク）には書かない。画像ファイルの場所は、練習用の `pathMappings` の後ろに足した本番の `pathMappings` で読み替える。練習中に作った監視と通知は、練習用のローカルのファイルに残る
- 練習モードを始めたときのメッセージに「…画像カタログ 2 件は本番から読み込み（読むだけ）」と出る

```jsonc
"imageCatalogs": [
  { "label": "運用の画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0", "fields": { … } },
  { "label": "練習用の画像", "url": "https://gis.example/arcgis/rest/services/TrainingCatalog/FeatureServer/0",
    "mode": "training", "fields": { … } }
]
```

### パスの読み替え（`pathMappings`）

レコードのパスの読み替え。2 通りの書き方があり、混ぜてよい。

```jsonc
"pathMappings": [
  // 先に試す読み替え: \\(ホスト)\(何階層でも)\(画像 ID) → D:/(画像 ID)。そこになければ元のパスで開く
  { "pattern": "^//[^/]+/(?:[^/]+/)*([^/]+)$", "to": "D:/$1", "label": "手元の複製" },
  // パスの先頭の読み替え（これまでどおり）
  { "prefix": "\\\\nas\\images", "label": "画像サーバー" },
  { "prefix": "\\\\nas\\cog", "url": "https://nas-web/cog/" }
]
```

- `prefix`（・`label`・`url`）: パスの先頭が合えば、`url` があればその URL、なければそのままのパス、なければ各自が選んだフォルダ（初回に聞いて記憶）。いちばん長く合う `prefix` を使う
- `pattern`・`to`（・`label`）: パスが `pattern` に合えば、合った部分を `to` に置き換えた場所を**先に**試す。そこにあれば（フォルダなら `imagePatterns` に合う画像があれば）それを開き、なければ次の `pattern`、どれもなければ読み替え前のパス（上の `prefix` の読み替えも含めて、これまでどおり）で開く。両方ないときは両方の場所を理由に出す
  - `pattern` は Python の `re`（大文字小文字は区別しない）。パスは `\` を `/` にし、末尾の `/` を除いて合わせる（`\\nas\img\2026\WV3_0001` は `//nas/img/2026/WV3_0001`。`file:` の URL はそのパスとして）。全体を置き換えるなら `^…$`
  - `to` の `$1`・`${1}`・`${名前}` は `pattern` のグループ（`(?P<名前>…)`）、`$$` は `$`。それ以外の `$`・`\` は書いたまま（`\\nas\D$\` も可）。`pattern` にないグループは設定の問題に出し、その読み替えは使わない
  - ファイルのパスにもフォルダのパスにも効く。`//ホスト/…` と `/` で書かれたパス（ふだんは URL として開く）にも効き、なければこれまでどおり URL で開く
  - 1 件に `prefix`・`url` と `pattern`・`to` を両方は書けない（設定の問題に出す）

### ピラミッド（.ovr）の自動作成（`overviews`）

- QGIS に追加したローカルの画像（レイヤーの追加・ドラッグ＆ドロップ・プロジェクトを開いたときなど、開き方を問わない。`scope` が `"catalog"` ならカタログ・通知から開いた画像だけ）にピラミッドがなければ、バックグラウンド（QGIS のタスク。ステータスバーで進捗・取消）で外部の `.ovr` を作り、できたらレイヤーを読み直す。**画像本体は書き換えない**（読み取りのみ）。1 枚ずつ順に作り、同じ画像は二重に作らない。内部ピラミッド・既存の `.ovr`・JPEG 2000 などの解像度レベルがあれば作らない。URL（COG）の画像は対象外
- 置き場所（`location`）:
  - `"auto"`（既定）: 画像のフォルダに書き込めれば隣に `画像名.tif.ovr`（一時フォルダで作ってから移すので、作りかけは読まれない）。書き込めなければ PC ごとのキャッシュフォルダ
  - `"cache"`: 書き込めるフォルダでも常にキャッシュフォルダ（画像のフォルダには何も書かない）
  - `"temp"`: 常に PC の一時フォルダ（画像のフォルダには何も書かない）。**QGIS を閉じたら消す**ので、ディスクに溜まらない。次の起動で同じ画像を開くと作り直す（下の「一時フォルダ（`"temp"`）」）
- キャッシュフォルダは GDAL の `GDAL_PAM_PROXY_DIR`。既定は QGIS 自身が設定しているプロファイルの `gdal_pam` フォルダ（読み取り専用フォルダの画像の統計なども GDAL がここに置く）。設定ファイルの `cacheFolder` で別のフォルダに変更できる（GDAL はこの値を最初に使うときに 1 回だけ読むので、**変更は QGIS の再起動後に有効**）
- キャッシュの .ovr は GDAL が画像を開くたびに自分で見つける（レイヤーの参照先は元の画像のまま。RPC・ファイル名のルール・観測記録はそのまま）。このプラグインを入れていない QGIS や他の GIS からは見えない
- `"cache"` のときは、カタログから画像を開く前に、その画像の `.aux.xml` をキャッシュ側に移す（隣にあれば内容を写す。隣のファイルはそのまま）。以後 GDAL はキャッシュ側を読み書きするので、QGIS が計算する統計・ヒストグラムも画像のフォルダには書かれない。キャッシュ側に `.ovr` の場所（`OVERVIEW_FILE`）を書く。**画像の隣の `.aux.xml` をあとで変えても反映されない**（キャッシュを消すと元に戻る）
- `"auto"` で書き込めるフォルダの場合、QGIS は（このプラグインと関係なく）統計を画像の隣の `.aux.xml` に書く
- カタログ以外から開いた画像は、QGIS が開いてからプラグインに知らされるので、`"cache"` でもその回は QGIS が計算した統計を画像の隣の `.aux.xml` に書くことがある（`.ovr` はキャッシュ）。次に開いたときからはキャッシュ側だけを読み書きする
- 起動時に開いたプロジェクトの画像は、設定ファイルを読み終えてから（`location`・`scope` に従って）処理する
- 一時フォルダ（`"temp"`）:
  - 既定は PC の一時フォルダの `%TEMP%\MIKAGE\overviews`。`tempFolder` で別のフォルダにできる。その中に QGIS ごとのフォルダ（`mikage-<プロセス番号>-<8 文字>`）を作り、`.ovr` はそこに置く
  - QGIS を閉じるとき（プラグインを止める・更新するときも）その QGIS のフォルダを消す。使用中で消せなかった分は次に QGIS を起動したときに消す（強制終了した QGIS の分も）。同時に開いている別の QGIS の分は消さない。`tempFolder` のフォルダにあるほかのファイルには触れない
  - `.ovr` の場所はキャッシュ側の `.aux.xml` に書く（`"cache"` と同じ仕組み。キャッシュに残るのは小さな `.aux.xml` だけ）。カタログから開く前に `.aux.xml` をキャッシュ側に移すのも `"cache"` と同じ
  - 次の起動で同じ画像を開くと、前の `.ovr` はもうないので作り直す（作り終わるまで縮小表示は遅い）
  - 設定ダイアログの「ピラミッドのキャッシュ」に、この QGIS の一時フォルダの場所・件数・大きさも出る
- `cacheFolder`・`tempFolder` には `%TEMP%`・`%LOCALAPPDATA%`・`%USERPROFILE%` などの環境変数と先頭の `~` を書ける（PC ごとに展開。設定されていない名前は書いたまま）
- キャッシュの大きさは設定ダイアログの「ピラミッドのキャッシュ」に表示。「キャッシュを消去」で次回起動時に消す（開いている画像が使っているため）。キャッシュは PC ごとなので、人ごとに 1 回ずつ作る。共有フォルダを複数人のキャッシュにするのは、GDAL の索引ファイル（`gdal_pam_proxy.dat`）に同時に書き込むと壊れるおそれがあるので不可
- 長辺が `minSize` 以下の画像は作らない。段は 2・4・8…（最小の段の長辺が 256 ピクセル以下になるまで）
- 作成中も地図の表示がカクつかないように、段は QGIS に付属の GDAL の `gdaladdo` が**別のプロセス**で作る。優先度を下げ（Windows は「通常以下」）、使うコアは `threads`（既定 0 = PC のコアの半分）。QGIS の中で作ると、作成の読み込みが地図の描画に使う GDAL のキャッシュを押し出し、全コアを使うこともあって、作成中は地図の描画が約 2〜3 倍遅くなっていた。`gdaladdo` が見つからない・失敗したときは、これまでどおり QGIS の中で作る（ログメッセージの「MIKAGE」タブに理由）。書き込めないフォルダの画像の `.ovr` は別のプロセスで作ってからキャッシュフォルダに置き、GDAL がキャッシュに置く `.aux.xml` にその場所（`OVERVIEW_FILE`）を書く

```jsonc
"overviews": {
  "location": "auto",          // "auto" | "cache" | "temp"（一時フォルダ。QGIS を閉じたら消す）
  "cacheFolder": "",           // "" = QGIS プロファイルの中
  "tempFolder": "",            // "" = %TEMP%\MIKAGE\overviews（"temp" のとき）
  "resampling": "AVERAGE",     // NEAREST・AVERAGE・BILINEAR・CUBIC・CUBICSPLINE・LANCZOS・GAUSS・MODE・RMS
  "compress": "DEFLATE",       // NONE・DEFLATE・LZW・ZSTD・JPEG（JPEG は 8 ビットの 1・3・4 バンドのみ。ほかは DEFLATE）
  "minSize": 2048,
  "scope": "all",              // "all"（開き方を問わない）| "catalog"（画像カタログから開いた画像だけ）
  "threads": 0                 // 作成に使うコア数。0 = PC のコアの半分（残りは QGIS の描画用）
}
// "overviews": false で作らない（省略時は上の既定値で作る）
```

### 地図の描画を速くする設定（`rasterSpeed`）

大きな画像の地図の描画が速くなるように、プラグインは次の設定を自動で使う。描画の時間の残りの多くは QGIS 自身の色付けで、設定では変わらない（オンにした人は MIKAGE が同じ色で速く描ける。下の「[画像の色付けを MIKAGE が速く描く（試作）](#画像の色付けを-mikage-が速く描く試作)」）。

| 設定 | 変え方 | 効果（測定） |
| --- | --- | --- |
| GDAL の読み込みのスレッド（`GDAL_NUM_THREADS`） | **この QGIS の中だけ**。起動のたび、画像を開く前に PC のコア数 − 1（2 未満なら変えない）。GDAL 3.6 以降で、1 回の読み込みのタイル・ストリップの展開を複数のコアで並列にする | 初めて見る場所の読み込み: タイル化した画像 37〜47 → 25〜34 ミリ秒（最初の表示 90 → 40）、ストリップの画像 270〜530 → 95〜170 ミリ秒。直前に見た場所は数ミリ秒遅くなる（13 → 17〜29） |
| GDAL のブロックキャッシュ（`GDAL_CACHEMAX`） | **この QGIS の中だけ**。RAM の 10 %（最大 2,048 MB。GDAL の既定の 5 % より小さくはしない） | 押し出された場所に戻ると展開し直しになる（1 画面 約 30 ミリ秒、ストリップの画像の最初の表示は約 0.5 秒）。複数の画像を行き来するときに効く |
| QGIS のオプション「複数の CPU コアで並列にレイヤーを描画」「描画に使うコアの最大数」「可能であれば描画キャッシュを使う」 | QGIS の既定より遅い値（オフ・コアを制限）のときだけ、**このプロファイルで 1 回だけ** QGIS の既定に戻す | 並列描画がオフだと 2 枚の画像で約 1.5 倍の時間 |
| QGIS のオプション「早期リサンプリング」（新しいラスターレイヤー） | 既定のリサンプリング（設定 > オプション > レンダリング > ラスター）が最近傍でないのにオフのときだけ、1 回だけオン | 縮小時バイリニア（オーバーサンプリング 2）の縮小表示 577 → 165 ミリ秒 |

- 測定: 16,000 × 16,000 画素・3 バンド・16 ビット・DEFLATE の GeoTIFF（.ovr あり）、QGIS 3.34・GDAL 3.8・4 コア、地図 1,700 × 1,073 画素
- GDAL の 2 つは**どこにも書かない**（QGIS の設定も環境変数も変えない）。プラグインを止める・アンインストールすると元に戻る。環境変数（Windows の環境変数、QGIS の 設定 > オプション > システム > 環境変数）や他のプラグインで決めてあれば、その値のまま
- QGIS のオプションを変えたときは、メッセージバーに「速く描くよう QGIS のオプションを n 件変えました（並列描画・早期リサンプリングなど）」と出る（「詳しく…」「元に戻す」。マウスを載せると変える前と後の値）。変える前の値は覚えておき、「元に戻す」で戻す（その後に QGIS のオプションで変えたものはそのまま）。変えた後に自分で戻したものは、次の起動で変え直さない
- メニュー **設定…** の「地図の描画」に今の値、「詳しく…」で各設定の値と誰が決めたか（MIKAGE・環境変数・既定）、「描画を速くする設定を使う」（外すと GDAL の 2 つと MIKAGE が変えた QGIS のオプションを戻し、次の起動からも使わない）、手動で見直す設定の一覧
- ログメッセージの「MIKAGE」タブに、起動のたび「地図の描画: GDAL のスレッド 3、ブロックキャッシュ 1,600 MB（既定 800 MB）、QGIS の設定の変更 0 件」のように出る

```jsonc
"rasterSpeed": {
  "gdalThreads": "auto",       // "auto"（PC のコア数 − 1）| コア数 | false（変えない）
  "gdalCacheMB": "auto",       // "auto"（RAM の 10 %、最大 2048）| MB（RAM の半分まで）| false（変えない）
  "qgisSettings": true         // false で QGIS のオプションは変えない
}
// "rasterSpeed": false でプラグインは何も変えない（省略時は上の既定値）
```

#### 手動で見直す設定（プラグインからは変えられないもの）

| 項目 | 見直すこと |
| --- | --- |
| 画像の形式（データを用意する側） | タイル化した GeoTIFF（COG。圧縮は DEFLATE か ZSTD、内部ピラミッド付き）にする。ストリップ（横一列ずつ）の圧縮 GeoTIFF は、等倍で初めて見る場所の読み込みが 0.3〜0.5 秒（タイル化なら 0.04〜0.09 秒）。JPEG 2000 は展開が重い。変換例: `gdal_translate -of COG -co COMPRESS=DEFLATE 元.tif 新.tif` |
| 共有フォルダの画像 | 読み込みの速さはネットワークで決まる。`overviews.location` を `"cache"` にすると .ovr をこの PC に置くので、縮小表示は PC のディスクから読む。大きな画像を長く見るときは PC にコピーして開く |
| ウイルス対策ソフト（管理者） | リアルタイム検査が画像やピラミッドを読むたびに走る。画像のフォルダとピラミッドのキャッシュフォルダ（QGIS プロファイルの `gdal_pam`。設定ダイアログの「ピラミッドのキャッシュ」）を検査の除外にする |
| 保存済みプロジェクトのレイヤーのリサンプリング | 早期リサンプリングは新しく追加するレイヤーから。保存済みのレイヤーで縮小時に「バイリニア」などを使っていれば、レイヤーのプロパティ > シンボロジ > リサンプリングで「早期リサンプリング」をオン（または「最近傍」） |
| 16 ビット画像の色付け | 描画の残りの時間の多くは QGIS 自身の色付け（1 画面 約 0.09 秒）で、上の設定では変わらない。「詳しく…」の「画像の色付けを MIKAGE が速く描く（試作）」をオンにすると、MIKAGE が同じ色で速く描く（下）。「画像補正」ドックで補正をオンにした画像は、もともと MIKAGE の色付けで描く |
| 電源の設定 | ノート PC は電源につなぐ。Windows の電源モードを「最適なパフォーマンス」（高パフォーマンス）にする |
| 値を固定したいとき（管理者） | `GDAL_NUM_THREADS`・`GDAL_CACHEMAX` を Windows の環境変数か QGIS の 設定 > オプション > システム > 環境変数 に書くと、プラグインはその値に従って変えない。設定ファイルの `rasterSpeed` で全体を止めることもできる |

#### 画像の色付けを MIKAGE が速く描く（試作）

メニュー **設定…** の「地図の描画」の「詳しく…」で**オンにした人だけ**（このプロファイルの設定。既定はオフ、設定ファイルのキーはない）。QGIS の「マルチバンドカラー」「単バンドグレー」で描く 8・16 ビットの画像の色付けを、QGIS の代わりに MIKAGE が行う。

- **色は QGIS と画素単位で同じ**: QGIS 3.34 の色付けの計算（最小・最大への引き伸ばし、引き伸ばして切り取り、切り取り、引き伸ばしなし、no data の値と画像の外、no data の色、不透明度、アルファバンド、白から黒）をそのまま、値ごとの表の引き当て（NumPy・複数のコア）で行う。QGIS の描画とバイト単位で同じになることをテストで確かめている（`tests/test_qgis_fast_draw.py`。型 4 種 × 引き伸ばし 4 種 × 範囲・不透明度・アルファバンド・no data の組み合わせ、ランダムな 500 通り）
- **速さ**: 地図 1 画面（1,700 × 1,073 画素）で、等倍 127 → 46 ミリ秒、縮小表示 108 → 37 ミリ秒（約 2.8 倍。上の測定と同じ画像、12 か所の中央値）。単バンドグレーは 34 → 19 ミリ秒
- **QGIS の設定のまま**: シンボロジの設定（バンド・最小 / 最大・引き伸ばし・不透明度など）はレイヤーのプロパティでこれまでどおり変えられ、変えた後も MIKAGE が描く。凡例・最小 / 最大の更新・スタイルのコピーも QGIS のまま。プロジェクトには **QGIS の設定として保存**される（MIKAGE のない QGIS でもそのまま開ける）
- 対象: 開いている画像とこれから開く画像のうち、QGIS の「マルチバンドカラー」「単バンドグレー」で、使うバンドが 8・16 ビットの整数のもの。それ以外（浮動小数点・32 ビットの画像、疑似カラー・パレットなど、「画像補正」の画像）はこれまでどおり
- MIKAGE が描かずに QGIS に任せるとき（同じ画素のまま）: 「透過」タブの透過する画素の値の一覧があるとき、最小と最大が同じ引き伸ばし、バンドの型と違う型の引き伸ばし、QGIS の計算が MIKAGE の表と合わないとき（描くたびに QGIS 自身の計算と数か所の値で突き合わせる。QGIS の版で計算が変わったときもここで QGIS に戻る）、思わぬエラー（ログメッセージの「MIKAGE」タブに出る）
- オフにする・プラグインを止めると、各レイヤーは同じ設定の QGIS の描画に戻る。ログメッセージの「地図の描画: …」の行の終わりに「MIKAGE の速い描画（試作）」と出ていればオン

### 複素 SAR 画像（SICD）の表示（`complexImages`）

QGIS だけでは、SICD の実数部（I）と虚数部（Q）は別々のバンドとして読まれ、どちらか一方を灰色で表示するだけなので SAR の画像としては読めない。プラグインは、QGIS に追加した（カタログから開く・レイヤーの追加・ドラッグ＆ドロップなど、開き方を問わない）ローカルの複素 SAR 画像の前に GDAL の VRT を置き、**振幅 √(I² + Q²) を dB（20·log10）で表示**する。

- 対象: SICD など NITF のバンドの `ISUBCAT` が `I`・`Q` の並び、複素数の画素の画像（CInt16・CFloat32 など。Sentinel-1 SLC の TIFF など）、バンドの説明が `I`・`Q`（`real`・`imag`）の 2 バンド。I・Q の組が複数あれば組ごとに 1 バンド。振幅・位相（`ISUBCAT` が `M`・`P`、SICD の AMP8I_PHS8I）は `M` のバンドをそのまま振幅とする（AmpTable は使わない）
- 計算は GDAL の画素関数（`complex`・`dB`・`mod`）で描画のたびに行うので、追加のライブラリは不要。**画像本体は書き換えない**。I = Q = 0 の画素（SICD の余白）は no data
- 表示は灰色の 1 バンドで、値の 2〜98 % を引き伸ばす。色調補正（「画像補正」ドック）もそのまま使える
- VRT は QGIS プロファイルの `mikage/complex-sar` フォルダに、画像のパス・大きさ・更新日時ごとの名前で置く（同じ画像を開き直すと使い回す）。プロジェクトに保存したレイヤーはこの VRT を読む（フォルダを消すとそのレイヤーは開けなくなるので、画像を開き直す）
- レイヤーのファイル名（カタログ外の画像の観測記録の画像 ID・画像名）・NITF のメタデータ（撮像日時）・`imageRules` の照合は元の画像のもの。VRT は元の画像の位置情報（ジオトランスフォーム・GCP・RPC）とメタデータを引き継ぐ
- ピラミッド（`overviews`）は I・Q ではなく振幅（dB）の VRT について作る（I・Q のまま平均すると打ち消し合うため）
- URL（`/vsicurl/`）の画像は対象外。起動時に開いたプロジェクトの画像は設定ファイルを読み終えてから変換する。複数の画像セグメントに分かれた大きな SICD は、GDAL が開く最初のセグメントだけ

```jsonc
"complexImages": "dB"          // "dB"（既定）| "amplitude"（√(I²+Q²)）| false（QGIS のまま I・Q を表示）
```

画像ごとに変えるときは `imageRules` に `complexImages` を書く。ファイル名に最初に合った規則に `complexImages` があればそちらが設定ファイル全体の値より優先する（`false` でその画像だけ変換しない）。同じ規則の補正（`preset`・`enhance`）・`bands`・`noData` は変換後の振幅（dB）のバンドにかかる。`complexImages` だけの規則は、変換時の 2〜98 % の引き伸ばしをそのまま使う。

```jsonc
"imageRules": [
  { "match": "^CSK_.*\\.ntf$", "complexImages": "amplitude", "enhance": { "autoStretch": { "lowPercent": 1 } } },
  { "match": "_raw\\.ntf$", "complexImages": false }
]
```

## 通知

「この条件で監視…」（画像カタログ）か地図の右クリック「この地点の新着画像を監視…」で監視を作る。範囲は表示範囲・描いた範囲・レイヤー・地点・指定なし。地点は既存の監視に足すこともできる。

- 「レイヤー」はベクターレイヤーの地物の形そのもの（外接矩形ではない）と重なる画像を監視する。面・線・点のどれでも使え、「選択地物のみ」で選んだ地物だけにできる。画像カタログの範囲が「レイヤー」のときはそのレイヤーが最初から選ばれる
- 監視の範囲は設定したときの形の写し（WGS 84）をローカルの `observations.gpkg` に保存する。プロジェクトを閉じても、レイヤーを消しても監視は続き、あとでレイヤーを編集しても範囲は変わらない。レイヤーの今の形にしたいときは「監視条件」タブの「範囲の変更…」で取り直す（元のレイヤーが最初から選ばれる。表示範囲・描いた範囲・指定なしにも変えられる）。取り直した範囲（と既存の監視に足した地点）にすでにある画像も、続く確認で一覧に入る（既読。新着としては知らせない）
- 範囲の形は確認のたびにサーバーへ送るので、頂点が 2 万を超える形は設定時に念押しする。サーバーが受け付けないときは「失敗の理由」に出る
- 条件に合う画像は、監視を設定したときにすでにあったものも含めてすべて一覧とカードに出す（tsudo, 2026-11-18）。設定直後の初回の確認で、登録日時にかかわらず条件と範囲に合う画像をすべて読み、既読で入れる（「発見」の欄は「設定前から」。カードでは「監視の設定前から」。登録日時（なければ撮像日時）の順に、時間の流れの中の位置に並ぶ）。新着としては知らせない
- QGIS の起動時と `watchInterval` 分ごと（既定 10 分）に確認。以降に増えた画像を未読で「通知」ドックに新しい順で出す。ツールバーの「通知」に未読数
- 前からある画像はオブジェクト ID を先に聞いてから、`maxRecordCount` 件ずつ地物を読む（ページングや並べ替えのできないサービスでもすべて読める。ID を返さないサービスは 1 回の答えに入る分だけ）。読めなかったときは「失敗の理由」に出て、次の確認で読み直す。この版より前に作った監視は、次の確認で設定前からある画像を一度だけ読む
- 一覧に入れておくのは全部で 5 万件まで（超えると古いものから消える）。1 つの監視の前からある画像が 5 万件を超えるときは新しく登録されたほうから入れ、「最終確認」の欄とメッセージバーに入れなかった件数が出る（範囲や条件で絞ると入る）。通知は画像の地物（属性と形）を持つため、ローカルの `observations.gpkg` が 1 件あたりおよそ 1〜3 KB 大きくなる
- 一覧を開くとき・既読にするときは一覧に出す項目だけを読み、画像の地物はカードを作るとき・開くときに読む（2 万件で 0.15 秒ほど）。「通知」ドックの一覧は新しい 2,000 件まで（すべては「新着画像」の画面で）
- 「開く」「移動」「既読」「すべて既読」「削除」。「監視条件」タブで有効・無効、名前の変更、範囲の変更、削除、最終確認と失敗の理由
- 撮像計画の「予定・通知」もここに「撮像計画」として出る
- 新着画像が見つかると QGIS のメッセージバーに「新着画像 n 件」と「見る」ボタン（押すと下の「新着画像」の画面へ）。前からある画像を入れたときは「監視の設定前からある画像 n 件を一覧に（既読）」

### 新着画像（大きな画面・カード）

日常の業務で入ってきた画像を順に見るための画面。メニュー「画像 ▸ 新着画像（大きな画面）」・ツールバーのボタン・Ctrl+Alt+N・メッセージバーの「見る」で、地図の場所が「新着画像」の画面に切り替わる。地図の上に「地図｜新着画像（未読数）×」のタブが出て、タブで地図と行き来する（同じボタン・キーでも地図に戻る）。× で閉じるとタブも消える。開いていたかどうかは PC ごとに覚え、次に QGIS を起動したときも（地図を前にして）タブが出る。「通知」ドックと中身は同じ（既読・削除はどちらにも効く）で、ドックもそのまま使える。

- 1 行に 1 枚のカードを、見つかった順に上から並べる。いちばん下がいちばん新しい。監視の設定前からある画像は登録日時の順にその前に入る（「監視の設定前から」・既読）。最初に開いたときは最も古い未読のカード（未読がなければいちばん下）を出す
- 新しい画像が来てもスクロールはしない（見ている所が動かない）。画面の右下に「↓ 新着 n 件」が出て、押すとそのカードへ。画面に入ったカードは数から外れる
- カード: 画像 ID、未読の印、見つけた日時、サムネイル（下記。ないときはフットプリントの形）、監視の名前・カタログ・カタログの一覧と同じ列（撮像日時・センサー・`columns` など）、「画像ファイル」（そのレコードから開ける画像ファイルの一覧。フォルダのレコードは `imagePatterns` に合うファイルすべて。ファイル名だけを表示（フォルダからのパスはマウスを置くと出る）。1 つずつチェックボックス付きで、最初はすべてチェック。クリックでチェックを付け外しし、「開く」はチェックしたファイルを開く（「開く画像の選択」は出さない）。ダブルクリックはチェックにかかわらずそのファイルだけ開く。チェックは QGIS を起動している間は覚えておく。見つからないときは理由。フォルダの読み替え先がまだ選ばれていないときは「開く」で選ぶ）、写っている地物（下記。見出しはなく、レイヤーごとの見出しだけ）。広いときは「サムネイル｜属性｜画像ファイル｜写っている地物」の 4 列（カードの幅と列の位置はそろえる）。少し狭いと画像ファイルを写っている地物の上に、もっと狭いとどちらも属性の下にして、サムネイルも小さく。ボタンは「開く」（画像を開いて地図に切り替え、画像の範囲へ移動。既読に。カードのダブルクリックでも）・「地図で見る」（地図に切り替えてフットプリントへ移動して点滅。既読に）・「既読」（カードに「削除」はない。消すときは通知ドックで）。画像ファイルのないカタログ（`imageFiles: false`）は「開く」の代わりに「ファイルなしで記録」
- 上の欄: 監視の絞り込み・「未読のみ」（その間に既読にしたカードは次に切り替えるまで残る）・「前の画像を閉じる」（「開く」のたびに、前にこの画面から開いた画像を閉じる）・「すべて既読」・「今すぐ確認」。「未読のみ」「前の画像を閉じる」は PC ごとに記憶。絞り込みはすべての通知にかかる（表示中のカードの中だけではない）。件数の欄に「（絞り込み n 件）」
- カードは（絞り込みに合うものの）新しい 100 件まで作り、それより前は「さらに前の n 件を表示」で 100 件ずつ足す。絞り込みを切り替えて外れたカードは捨てずにしまっておき、戻したときはすぐ出る。サムネイル・画像ファイル・写っている地物は画面に見えているカードの分だけ、裏で 1 件ずつ調べる（QGIS の操作は止まらない。画像ファイルは QGIS を起動している間は覚えておき、設定ファイルを読み直すと調べ直す）

#### サムネイル（`imageCatalogs[].thumbnail`）

カタログごとに、サムネイルのアドレスを `{…}` を埋め込んだパターンで書く。http(s) の URL（QGIS のネットワーク経由。`authConfigs` の認証も効く）か、共有フォルダなどのファイルのパス。

```jsonc
"imageCatalogs": [
  { "label": "衛星画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0",
    "fields": { "id": "IMG_ID", "acquired": "ACQ", "sensor": "SENSOR", "source": "PATH" },
    // 文字列だけでも可（大きさは 270×200）
    "thumbnail": { "url": "https://ql.example/{sensor}/{acquired:%Y/%m/%d}/{id}.jpg?bbox={bbox}&ur={ur.lat:.6f},{ur.lon:.6f}&w={width}",
                   "width": 270, "height": 200 } }
]
```

| 書き方 | 中身 |
| --- | --- |
| `{id}` `{sensor}` `{angle}` `{azimuth}` | カタログの `fields` の役割の値 |
| `{acquired}` `{registered}` `{systemRegistered}` | 日時。`:` の後に書式（`%Y%m%d` などの strftime、`iso`（既定）・`iso-date`・`unix`・`unixms`）、`@` の後にタイムゾーン（`Asia/Tokyo`・`+09:00`。既定は UTC）。例 `{acquired:%Y%m%d%H@Asia/Tokyo}` |
| `{attr.属性名}` | カタログの任意の属性。数の書式（`{attr.PATH_NO:04d}`）や日時の書式も可 |
| `{xmin}` `{ymin}` `{xmax}` `{ymax}` `{bbox}` | フットプリントの外接矩形（経緯度。`bbox` は `xmin,ymin,xmax,ymax`） |
| `{center.lon}` `{center.lat}`（`{lon}` `{lat}`） | 外接矩形の中心 |
| `{ul.lon}` `{ul.lat}` `{ur.…}` `{lr.…}` `{ll.…}`（`{ulx}` `{uly}` …） | 左上・右上・右下・左下の角。外接矩形の角にいちばん近いフットプリントの頂点（斜めに撮った画像でも画像の本当の角） |
| 座標の書式・座標系 | `{ur.lat:.6f}` で桁数、`@3857` で Web メルカトルのメートル（`{bbox@3857}`） |
| `{width}` `{height}` | `thumbnail` の `width`・`height`（16〜2048、既定 270・200。カードに出す大きさ） |
| `{token}` | カタログの `token` |
| `{{` `}}` | 文字としての `{` `}` |

- URL では値をパーセントエンコードする（空白・`&`・`#` など。`/`・`:`・`,` はそのまま）。ファイルのパスは値をそのまま入れる（設定ファイルでは JSON の文字列なので `\\` を重ねる。例 `"\\\\nas\\ql\\{acquired:%Y}\\{id}.png"`）
- 読んだサムネイルはプロファイルの `mikage/thumbnails` に PNG で残す（アドレスごと。3000 件・300 MB を超えると古く使ったものから消す）。1024 ピクセルより大きい画像は縮めて残す。読めなかったとき（ファイルなし・サーバーの拒否・画像でない）はフットプリントの形と「サムネイルを取得できず」を出し、理由はツールチップ。10 分たつと読み直す
- パターンの誤り（`{` `}` の対応、知らない名前、使えない書式・タイムゾーン・座標系）は設定ファイルの問題としてメッセージバーに出て、そのカタログはサムネイルなしになる

#### 写っている地物（`imageCatalogs[].footprintLayers`）

カタログごとに Esri のレイヤー（複数可）を書くと、カードに「この画像に写っている地物」として、フットプリントと重なる地物の名前を出す（地名・施設のポイントやポリゴンなど。`TBL_PLACE_NAME`・`TBL_NAMED_AREA` も使える）。

```jsonc
"footprintLayers": [
  { "label": "施設", "url": "https://gis.example/arcgis/rest/services/Places/FeatureServer/0",
    "fields": ["NAME", "NAME_EN"], "format": "{NAME}（{NAME_EN}）" },
  { "label": "港", "url": "https://gis.example/arcgis/rest/services/Ports/FeatureServer/0", "fields": "PORT_NAME",
    "where": "KIND = 'port'",
    // 行の背景色を属性から（値ごとの色。当たらない行は default、なければ背景なし）
    "background": { "field": "KIND", "colors": { "fort": "#fde2e2", "port": "#e0f2fe" }, "default": "#f1f5f9" } }
]
```

| 項目 | 中身 |
| --- | --- |
| `label` | カードの見出し（「施設（3 件）」） |
| `url` | レイヤーの URL（`…/FeatureServer/0` か `…/MapServer/0`） |
| `fields` | 出す属性（1 つなら文字列） |
| `format` | 1 件の書き方（`{属性名}`。`fields` にある属性だけ）。値が空なら囲んでいた括弧ごと消える（英語名のない地物は「長浦港」）。省略時は `fields` の値を空白でつなぐ |
| `where` | 絞り込みの条件式（任意） |
| `max` | カードに出す件数の上限（任意。書かなければすべて。書いたときはそれを超えると「（先頭の n 件まで）」と全体の件数） |
| `token` | このレイヤーのトークン（なければカタログの `token`） |
| `background` | 1 件ごとの行の背景色を属性から（任意）。`{ "field", "colors", "default" }`。`colors` は属性の値 → 色（`#rrggbb`・`#rgb`・`pink` などの色の名前）。`colors` を書かないか属性名だけ（`"background": "COLOR"`）なら、属性の値そのものを色として使う（色でない値は背景なし）。どれにも当たらない行は `default`（なければ背景なし）。文字は背景に合わせて黒か白 |

- レイヤーごとに見出し（「施設（3 件）」）、その下に 1 件を 1 行で出す（点などの記号は付けない）
- 略さずにすべて出す（カードは縦に長くなってよい）。サービスの 1 回の上限（`maxRecordCount`）より多ければ何回かに分けて読む。同じ名前の地物は「長浦港 ×2」（`background` の値が違えば別の行）、名前のない地物は「（名前なし ×n）」
- 1 枚につき 1 回だけ問い合わせ、結果は通知と一緒にローカルの `observations.gpkg` に残す（次に開いたときは問い合わせない）。設定ファイルでレイヤー・`fields`・`format`・`where`・`max`・`background.field` を変えると、変わったレイヤーだけ問い合わせ直す（`colors`・`default` を変えただけなら問い合わせない）
- 問い合わせに失敗すると「照合できず: 理由」。10 分たつと問い合わせ直す

#### 個人の関心地域・地点（`interests`）

一人ひとりが自分の関心地点・関心地域を決めておくと、カードの「写っている地物」の**いちばん上**に、その画像に入っているものを出す（地点はフットプリントの中、地域はフットプリントと重なるもの。それぞれの色を行の背景に）。編集はドック「関心地域・地点」（メニュー「画像」）。

置き場所は Esri（どの PC でも同じものが出る）。ポイントのレイヤー（[`TBL_INTEREST_POINT`](../admin/esri-tables.md#tbl_interest_point関心地点)）とポリゴンのレイヤー（[`TBL_INTEREST_AREA`](../admin/esri-tables.md#tbl_interest_area関心地域)）に、持ち主の列（`OWNER_USER`）付きで 1 件 1 行。持ち主は [`editTracking`](../admin/operations.md#作成者更新者の記録edittracking) と同じユーザー名（既定は環境変数 `USERNAME`）で、自分の行だけを読み書きする（大文字・小文字は区別しない）。

設定ファイルは `footprintLayers` とは別の**このレイヤーだけの書き方**で、`interests` に 1 回だけ書く（すべてのカタログのカードに出る）。属性はプラグインが知っているので `fields`・`format` は書かない（名前を変えたときだけ役割ごとに `fields`）。

```jsonc
"interests": {
  "points": "https://gis.example/arcgis/rest/services/MIKAGE/FeatureServer/24",   // 関心地点（ポイント、編集可）
  "areas": "https://gis.example/arcgis/rest/services/MIKAGE/FeatureServer/25",    // 関心地域（ポリゴン、編集可）
  "label": "関心地域・地点",                                                        // カードの見出し（既定）
  "color": "#f97316"                                                               // 新しく作るときの色（既定）
}
```

| 項目 | 中身 |
| --- | --- |
| `points` | 関心地点のレイヤー（ポイント、`…/FeatureServer/n`）。URL か `{ "url", "fields", "where", "token" }`。役割 `id`・`name`・`owner`（以上必須）・`color`・`note` |
| `areas` | 関心地域のレイヤー（ポリゴン）。書き方は `points` と同じ。どちらか一方だけでもよい（そのときはその種類だけ作れる） |
| `label` | カードの見出し（「関心地域・地点（2 件）」） |
| `color` | 新しく作るときの色（`#rrggbb` か色の名前） |

ドック「関心地域・地点」:

- 一覧: 自分の地点・地域（名前・種類・色・メモ・更新日時）。名前・メモで絞り込み。「最新を取得」で Esri から読み直す（別の PC で変えたもの）
- 「地点を追加」: 地図をクリックした所に新しい地点。「地域を追加」: 地図で多角形（クリックで頂点、ダブルクリックか右クリックで確定、Esc でやり直し）。「選んだ地物から」: 作業中のレイヤーで選んだ地物の形で新しく（点は地点、面は地域。名前の属性 `name`・`NAME`・`名前`・`名称` があれば名前に）
- 新しいものは下のフォーム（名前・色・メモ）で名前を入れて「保存」（Enter でも）。保存するまで地図には破線で出る。「取り消し」で捨てる
- 一覧で 1 件選ぶと同じフォームで編集。「形を描き直す」（地点はクリックした所へ、地域は描き直した多角形に）。「取り消し」で保存した状態に戻す
- 「削除」: 選んだもの（複数可）を Esri から消す（確認あり）。「移動」（ダブルクリックでも）: 選んだものへ地図を移動
- 「地図に表示」: レイヤー「関心地点」「関心地域」（一時レイヤー。それぞれの色、名前のラベル。編集はドックで）。オンのままなら QGIS を開いたとき・別のプロジェクトを開いたときもまた出す（1 件もなければ出さない）。レイヤーパネルで消すとオフになる
- 保存・削除はすぐにすべてのカードに出る（カードごとに Esri に問い合わせない。画像のフットプリントとの重なりはプラグインの中で調べる）
- ほかの人の行は出さないが、Esri の上では誰でも見える（分けたいときはサービスの権限で）
- 「組織の地域にする…」: 選んだ自分の地域を組織の関心地域として登録する（「組織」のタブのフォームに形・名前・色・メモが入るので、カテゴリーなどを入れて「保存」。自分の地域は残る）

#### 組織の関心地域（`namedAreas`）

組織で決めた関心地域（2026-11-24 に追加。tsudo「個人のAOIはあるんだけど、組織のAOIを整理したいので、ネームドエリアを拡張する感じで、属性を横展開したい」）。新しいレイヤーは作らず、地名のレイヤー（[`TBL_NAMED_AREA`](../admin/esri-tables.md#tbl_named_area地名のポリゴン)）に属性を足して同じ表に置く。どの行を何に使うかは**用途**（`AREA_USE`）で決める:

| 用途 | 通報・観測記録の場所の名前（`place`） | 新着画像のカード・「組織」の既定の一覧・地図 |
| --- | --- | --- |
| `地名`（空も。前からある行） | 使う | 出さない（「組織」の用途を「地名」「すべて」にすれば一覧には出る） |
| `関心地域` | **使わない**（記録を含むいちばん小さい地名を選ぶときに飛ばす） | 出す |
| `両方` | 使う | 出す |

新着画像のカードの「写っている地物」では、自分の関心地域・地点の次に「組織の関心地域（n 件）」として、画像と重なる有効な関心地域を名前（カテゴリー）で、地域の色（なければカテゴリーの色）を行の背景に出す。

設定ファイルは `namedAreas`（書かなければ `alertReports.namedAreas` の地名のレイヤーを使う。そのときは国も `alertReports.countries`）:

```jsonc
"namedAreas": {
  "url": "https://gis.example/arcgis/rest/services/MIKAGE/FeatureServer/11",          // TBL_NAMED_AREA（編集可）
  "categories": "https://gis.example/arcgis/rest/services/MIKAGE/FeatureServer/33",   // TBL_AREA_CATEGORY（編集可）
  "countries": "https://gis.example/arcgis/rest/services/MIKAGE/FeatureServer/20",    // TBL_COUNTRY（なければ alertReports.countries）
  "idPrefix": "NA-", "idDigits": 6,                                                    // 管理番号の形（既定は NA-000123）
  "label": "組織の関心地域"                                                             // カードの見出し・タブの説明（既定）
}
```

| 項目 | 中身 |
| --- | --- |
| `url` | 地名のレイヤー（ポリゴン、`…/FeatureServer/n`）。`fields`・`where`・`token` も書ける。役割は `name`・`kind`・`active`・`nameEn`・`kindEn`・`id`・`use`・`kana`・`alias`・`country`・`category`・`parent`・`ownerGroup`・`priority`・`color`・`note`。マップサービスなら見るだけ |
| `categories` | カテゴリーの表（[`TBL_AREA_CATEGORY`](../admin/esri-tables.md#tbl_area_category地域のカテゴリー)）。URL か `{ "url", "fields" }` |
| `countries` | 国のレイヤー（国の選択肢と「形から」）。なければ `alertReports.countries` |
| `idPrefix`・`idDigits` | プラグインが付ける管理番号の形（英数字と `-` `_` の 16 文字まで・1〜12 桁）。ジオデータベースの属性ルールで付けるときはその式と同じにする |
| `label` | カードの見出し（「組織の関心地域（2 件）」） |

ドック「関心地域・地点」の「組織」のタブ（**全員が編集できる**。tsudo「すべての人が編集できるように」）:

- 一覧: 名前・管理番号・用途・カテゴリー・国・種類・担当グループ・重要度・依頼（その地域から作った有効な撮像依頼の数。停止・完了もあれば「1（全 3）」。撮像依頼の保存先があるときだけ）・更新日時。並びは「カテゴリー別」（カテゴリーの木の下に地域）・「上位の地域別」（`PARENT_ID` の木）・「一覧」。名前・よみがな・別名・管理番号・メモで絞り込み、用途（既定は関心地域。地名のレイヤーは市町村など何千行にもなるので）と国でも絞る。停止中の行は灰色
- 「新しい地域」: 地図に多角形を描く。「選んだ地物から」: 作業中のレイヤーで選んだ面の地物の形で新しく。新しいものは下のフォームで名前を入れて「保存」
- 一覧で 1 件選ぶと同じフォームで編集: 名前・よみがな・別名（カンマ区切り）・管理番号・用途・種類（都道府県・市町村など階層の管理）・カテゴリー・国（「形から」で国のレイヤーから）・上位の地域・担当グループ（依頼グループから選べる）・重要度（空は 500）・色（なしならカテゴリーの色）・有効・英語名・種類（英語）・メモ。地名のレイヤーにない属性の欄は出さない（ドックの上に足りない属性を出す）
- 形: 「描き直す」（多角形）・「選んだ地物から」・「頂点を直す」（QGIS の頂点ツールで動かす・足す・消す。もう一度押すか「保存」で決まる）。形を変えなければ保存で形は送らない
- 管理番号: 空なら保存のときに付く（ジオデータベースの属性ルール、なければプラグインが `NA-000123` の形でいちばん大きい番号の次）。ほかの行と同じ番号は保存前に止める。前からある空の行は「管理番号のない n 件に付番…」でまとめて（地名だけの行も。付けた番号は通報の `place.id` にも出る）
- 「カテゴリー…」: カテゴリーの木（名前・ID・英語名・地域の数・状態・メモ）。「新規…」（選んでいるものの下に）・「編集…」・「上へ」「下へ」（同じ上位の中で）・「削除…」（地域のないものだけ。使わなくなったものは「編集…」で有効を外す）。ID を変えると、そのカテゴリーの地域も新しい ID に直す
- 「地図に表示」: レイヤー「組織の関心地域」（一時レイヤー。地域の色の破線と名前のラベル）。既定はオフ。オンのままなら QGIS を開いたときもまた出す
- 「移動」（ダブルクリックでも）: 選んだ地域へ地図を移動（地名だけの行は、そのとき形を読む）
- 「撮像依頼…」: 選んだ地域（複数可）の撮像依頼のフォームを「撮像依頼」ドックで開く（名称・範囲・依頼グループ・優先度は地域のもの。[docs/imaging-requests.md](../imaging-requests.md) の「40. 地域から撮像依頼」）。停止中・管理番号のない地域からは作らない。撮像依頼の保存先（`requestStores`）があり、撮像を依頼する人か撮像計画の担当のとき
- 依頼がつながっている地域の管理番号は灰色で変えられない（依頼は管理番号で地域を見つけるため）
- 地名を消すと記録の `NAMED_AREA_OBJECTID` が指す先がなくなるので、ドックから行は消さない（使わなくなったら「有効」を外す）
