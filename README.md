# 衛星撮像計画・観測記録（QGIS プラグイン）

Web 画像ビューア（[browser-image-enhancement](https://github.com/Tosei-sudo/browser-image-enhancement) の `usecase/image-viewer`）の「撮像計画」と「観測記録」と、ビューアの中心機能の画像補正（色調補正）を QGIS プラグイン（Python / PyQGIS）にしたもの。同じ設定ファイル（`config.json`）と同じ ArcGIS フィーチャーサービスを共用する。

- 対応: QGIS 3.34 LTR 以上（Qt5 / Qt6）
- 追加の依存: `sgp4`（任意。なければ同梱の純 Python 版で動く。入れると約 15 倍速い）。numpy は QGIS 付属のもの
- 閉域ネットワークで動作（外部の暦ファイル・地図タイルを使わない）

> 開発中。現在は改訂前の段階 8 までと画像カタログ（骨組み、画像カタログ: 検索・一覧・フットプリント・開く・類似画像の検索・新着画像の通知、撮像計画: 衛星カタログ・撮像モード・衛星ツリー・撮像機会の計算・組み合わせ・優先度・シーンの共有・撮像範囲の移動・タイムライン・一覧と地図・CSV とレイヤー・計画の保存と追跡・予定表と通知・雲量予報・地上局・ステレオペアと干渉ペア・再訪間隔マップ・移動目標撮像計画・衛星パス、観測記録: 記録・継続・同一候補・2 点・確認範囲・モノの流れ・分類体系の編集・報告書・CSV とレイヤー・Python API）。ビューアとの違いは [docs/differences.md](docs/differences.md)。

## ドックの配置

- 初期位置は 3 つのタブのまとまり。撮像系（撮像計画・衛星パス・保存した撮像計画）は右、カタログ系（画像カタログ・通知・画像補正・影から高さ）は左、記録系（観測記録・分類体系の編集）は右の下段
- 最初に開いているのは「画像カタログ」と「撮像計画」だけ。ほかはメニューかツールバーから開く（QGIS が前回の配置を覚えていれば、そちらが優先）
- 浮かせたドックが画面外にある場合（モニターを外したあとなど）、開いたときに元の場所へドッキング
- メニュー「ドックを初期位置に戻す」で、すべてのドックを初期位置のタブに戻す。開いているドックは開いたまま

## 背景地図

- ツールバーの「背景地図」（メニューでは同名のサブメニュー）で、なし・地理院 標準・地理院 淡色・地理院 写真・地理院 ベクトル・OpenStreetMap・OpenStreetMap（Esri ベクトル）を切り替え。表示中のものにチェック
- 一覧はビューアと同じ `config.json` の `baseMaps`（書くとこの一覧で置き換え）。`type` は `xyz`・`mvt`・`style`・`esri`、書かなければ URL から判断。相対 URL は設定ファイルの場所が基準
- 背景地図はプロジェクトのいちばん下のレイヤー 1 枚。切り替えると差し替え、「なし」で削除。ほかのレイヤーはそのまま
- `defaultBaseMap` があれば、空のプロジェクトで起動したときと新規プロジェクトで表示
- 閉域では `baseMaps` を社内のタイルに書き換え（既定の一覧はインターネットの地図）。読み込めない背景地図はメッセージバーに理由
- ArcGIS の VectorTileServer で認証が要るものは「設定…」でそのサービスの認証設定を選択（`token` はレイヤーに書かない）

## 画像カタログ

「画像カタログ」ドックで `imageCatalogs` の画像を検索する。範囲（既定は表示範囲。「範囲を描く」で地図に多角形を描いて「描いた範囲」も。クリックで頂点、ダブルクリックか右クリックで確定、Esc で取消）、撮像日、「詳細条件」で登録日・システム登録日・センサー・角度の上限・方位角・SQL。

- 一覧は新しい順で、見出しのクリックで並べ替え（空の値は常に最後）。地図に全件のフットプリント（青）と選んだもの（橙、画像 ID 付き）。「地図で選択」を押すとフットプリントのクリックで選べる（Ctrl・Shift で追加）
- 「開く」かダブルクリックでラスターレイヤーに。URL は `/vsicurl/`、ローカルパスは `pathMappings` に従う（`url` があればそれ、なければそのままのパス、だめなら初回にフォルダを選び記憶。「フォルダの対応を消去」で忘れる）。開けないときは理由を表示。「パスをコピー」で場所をクリップボードへ
- 開いたレイヤーはカタログの属性をカスタムプロパティとメタデータに持つ（`satobs/imageId` は観測記録と計画の追跡が使う）
- 「レイヤーとして追加」で一覧をフットプリントのメモリレイヤーに（撮像日時で時系列コントローラーが効く）
- 「類似画像の検索」（一覧のボタン、またはカタログから開いたレイヤーの右クリック「類似画像の検索…」）で、同じセンサー・角度 ±5°・方位角 ±20° の画像を重なりの大きい順に。比較元は赤い破線。許容差は記憶。「通常の検索に復帰」で戻る

## 通知

「この条件で監視…」（画像カタログ）か地図の右クリック「この地点の新着画像を監視…」で監視を作る。範囲は表示範囲・描いた範囲・選択中の地物・地点・指定なし。地点は既存の監視に足すこともできる。

- QGIS の起動時と `watchInterval` 分ごと（既定 10 分）に確認。初回は今ある画像を覚えるだけで、以降に増えた画像を「通知」ドックに新しい順で出す。ツールバーの「通知」に未読数
- 「開く」「移動」「既読」「すべて既読」「削除」。「監視条件」タブで有効・無効、名前の変更、削除、最終確認と失敗の理由
- 撮像計画の「予定・通知」もここに「撮像計画」として出る

## 撮像計画

「撮像計画」ドックで、対象（レイヤーの地物・選択中の地物・地図で指定した地点）、開始日時、期間、オフナディア角の上限を選び「計算」（Ctrl+Enter）。衛星の選択・日照・入射角・軌道・向き・TLE の貼り付けは「詳細条件」。

- 一覧の行を選ぶと、地図にその回の地上軌跡（破線）、届く範囲（点線）、撮像範囲（青）、衛星の位置を表示。ダブルクリックか「範囲へ移動」でその場所へ
- 面の対象が 1 回で覆えないときは「組み合わせ（全域を最短で）」で開く。目標の割合まで、複数の衛星のパスを撮像間隔と 1 日の上限を守ってつなぐ
- 「CSV 保存」はビューアと同じ列の CSV（BOM 付き UTF-8）、「レイヤーとして追加」は撮像範囲のメモリレイヤー（撮像日時付き。時系列コントローラーで絞り込み可能）
- 地物ごとに計算するとき、数値の属性を「優先度の属性」に選ぶと、組み合わせで優先度の高い地物から衛星を割り当てる。近い地点は 1 シーンにまとめる（「近い地点を 1 シーンに集約」）
- 「撮像範囲を移動」を押すと、選んだ回の撮像範囲を地図でドラッグできる（衛星が向けられる範囲内。角度と被覆は再計算）
- 「タイムライン」で衛星ごとの撮像を時間軸に表示。棒をクリックするとその回を選択
- 地図の右クリックメニューの「ここを撮像計画」で、その地点をすぐ計算
- 「ステレオペア」「干渉ペア（同じ軌道・SAR）」で同じ対象を 2 回撮る組を、「再訪間隔マップ」で対象のまわりを格子に分けたセルごとの最長の待ちを表示（緑ほど早く、赤ほど長く待つ）
- 「詳細条件」の「雲量予報」をオンにすると、光学衛星の機会に 16 日先までの雲量を付け、「雲量（以下）」で絞り込める。オンにするまで予報サービス（`cloudForecast`、既定は Open-Meteo）には何も送らない。閉域では社内の互換サービスを `cloudForecast` に指定するか `false` に
- 「予定・通知…」で一覧の撮像を予定表（.ics）に保存、または撮像の何分前かに QGIS のメッセージバーで通知（QGIS の起動中のみ）
- 「保存・追跡…」で一覧の撮像を `planStores` のフィーチャーサービスに保存。「保存した撮像計画」ドックで計画を開くと、撮像時刻を過ぎた予定の撮像を画像カタログ（`imageCatalogs`）で確かめ、撮像済み・未撮像にする
- 設定ファイルに `satelliteCatalogs` がなければ、架空のサンプル衛星 2 機（光学・SAR、SAR は 3 モード）で試せる

## 移動目標撮像計画

- メニューの「移動目標撮像計画…」で、航跡・位置報告のポイントレイヤー（AIS の CSV など）を選ぶ。ID・時刻・針路・速力・名前の属性は名前（mmsi・timestamp・cog・sog・heading など）から自動で対応づけ。速力の単位はノット・km/h・m/s
- 目標ごとに最後の報告から針路・速力で将来位置を推測（最大 72 時間）。針路・速力がなければ最後の 2 報告（1 分以上離れたもの）から求め、それもできなければその場に留まるとみなす
- 誤差の円の半径 = 報告時の誤差 + 経過時間 ×（1 時間あたりの増加 + 速力 × 割合）。既定は 0.5 km・0.5 km・10%
- 「存在予測を追加」で、一定間隔（既定 6 時間）の誤差円（時刻・経過時間・半径つき）と予測航跡をメモリレイヤーに追加
- 「撮像計画の作成」で撮像計画ドックへ（最大 50 目標）。1 時間ごとの推測位置でパスを探し、各パスをその時刻の位置で計算し直す。撮像範囲は誤差円に向け、被覆は円のうち撮像範囲に入る割合

## 新規スクラッチレイヤー（テンプレート）

- 「レイヤー」→「レイヤーを作成」の「新規一時スクラッチレイヤー…」のすぐ下と、プラグインのメニューに「新規スクラッチレイヤー（テンプレート）…」
- 「テンプレート」から選ぶと名前・ジオメトリ・属性が入り、そこから自由に変えて「作成」。テンプレートは標準（空のレイヤー・航跡〔生存圏計算用〕・調査地点・目標・物体・関心区域・被害状況・経路・測線・注記）、設定ファイルの `layerTemplates`（「組織の設定」、書き方はビューアの README と同じ）、「テンプレートとして保存」で残したもの（「保存済み」、ユーザープロファイルの `QgsSettings`）
- 属性ごとに名前・エイリアス・型（文字列・整数・小数・日付）・必須・既定値・文字数の上限・最小・最大・候補値（`1=住宅, 2=店舗`）。作るとメモリレイヤーに、エイリアス、必須は非 NULL 制約、候補値は「値マップ」ウィジェットと制約、範囲は「範囲」ウィジェットと制約、既定値は属性の既定値として入る
- 「ほかのレイヤーの属性をコピー…」で開いているベクターレイヤーの属性・ジオメトリ・座標系をひな形に（地物はコピーしない）
- 「作成後すぐ地図に作図開始」で、編集を始めて「地物を追加」の状態に
- 「航跡（生存圏計算用）」の属性名は「移動目標撮像計画…」の自動対応に合うので、描いたらそのまま存在予測を計算できる
- QGIS 標準の「新規一時スクラッチレイヤー」の画面にも「テンプレート」欄が付き、選ぶとこの画面に切り替わる

## 衛星パス

- 選んだ衛星（撮像計画と同じ衛星の一覧）の地上軌跡と撮像可能範囲（最小〜最大オフナディア角の帯、見られる側）を衛星ごとの色で表示
- 「時点」は前後 15 分と衛星の位置、「期間」は最長 7 日を時刻の目盛り付きで。一覧の行をクリックするとその衛星へ移動
- 「詳細」で前後の時間・オフナディア角の上限・光学衛星の日照・目盛り・現在時刻に合わせ続ける（30 秒ごと）・TLE の貼り付け
- 日付変更線で線と面を分割。「レイヤーとして追加」で地上軌跡と撮像可能範囲をメモリレイヤーに

`sgp4` の入れ方（任意）: QGIS の Python コンソールで `import pip; pip.main(["install", "sgp4"])`、または OSGeo4W シェルで `python -m pip install sgp4`。閉域では wheel ファイルを持ち込んで `pip install sgp4-2.*.whl`。

## 観測記録

「観測記録」ドックで、画像ごとに「いつ・どこに・何（モノ）が・何をしていたか（活動）」を記録する。画像はプロジェクトのラスターレイヤー（画像 ID はレイヤーの `satobs/imageId`、なければファイル名。撮像日時はレイヤーの時刻 → GDAL メタデータ → NITF → ファイル名 → TIFF の日時の順、分からなければドックで入力）。キーはドックにフォーカスがあるときだけ効く。

- ◀ ▶（PageUp・PageDown）で撮像日時の順に画像をたどる。「この画像のみ」で他のラスターを隠す。＋ でファイルなしの画像（ID・名称・撮像日時）を追加
- 「クリック記録」（R）で地図をクリックし、モノ・種別（階層のボタンでたどる）・活動（1〜9）・確度・備考を入れて Enter。「2 点」（L）は前端 → 後端のクリックで中心・長さ・向き
- 前後の画像のモノは白抜きの印。クリックか「継続」「不在」、「すべて継続」で一括。新しい記録には近くの「同一候補」（Alt+1〜5）
- 「確認範囲」（A）は対角の 2 点（または表示範囲・画像の範囲）と対象の種別。範囲内で記録のないモノは「確認範囲内 n 件を不在」で一括
- 印はドラッグで場所を直せる。削除は削除日時を入れて残し、「詳細」の「削除済みも表示」から復元
- 「モノ」タブで流れ（帯グラフ・表・地図の軌跡）、名前・種別の変更・統合。「分類」タブで分類体系
- 「詳細」から報告書（HTML 保存・印刷・PDF 保存。地図はキャンバスのレイヤーに記録の印を重ねて描画）、再読み込み、CSV 保存、レイヤー化（記録のポイント・確認範囲のポリゴン・流れのライン。時系列コントローラー対応）
- 保存先は `observationStores` の Esri フィーチャーレイヤー（通信は QgsTask の中）か、常にあるローカル GeoPackage。記録者は「詳細」の名前、なければ保存先の認証設定のユーザー名

## 分類体系の編集

「分類体系の編集」ドック（または「分類」タブの「編集ツール」）でツリーを編集する。ドラッグで移動（行の上で下位、行の間で前後、余白で大分類）、F2・ダブルクリックで名前の変更、＋ 大分類・Insert で追加（「A > B」で階層ごと）、削除は 2 回押す、Alt+↑↓ で並べ替え、検索（名前・既知の個体・諸元）。右側で階層名・個体名の呼称・既知の個体・諸元・参考写真（ファイルはローカル GeoPackage、または URL）、下で「諸元の項目」。JSON の保存・読み込みは `config.json` の `observationVocabulary.taxonomy` と同じ形。名前の変更・移動・削除は配下の記録の種別にも反映する。

## 画像補正

「画像補正」ドックで、アクティブなラスターレイヤーにビューアと同じ補正をかける。計算はビューアのライブラリ（browser-image-enhancement）を NumPy に移したもので、同じ画像・同じ補正なら同じ画素になる（下の「ビューアとの数値比較」）。

- 「補正」をオンにしたレイヤーだけが対象。オフか「QGIS の表示に戻す」で QGIS 標準のレンダラー（同じバンド・同じ引き伸ばし）に戻る
- プリセット: 自動・鮮やか・やわらか・衛星画像・文書・白黒
- DRA（表示範囲で自動レンジ）: 方式（パーセントクリップ・最小〜最大・標準偏差）、クリップ (%)、RGB 連動、範囲を固定。地図を動かすと表示範囲の統計で引き伸ばし直す
- バンド割当: R・G・B に好きなバンド（GDAL のバンド名つき）。3 つとも同じバンドならそのバンドを白黒で表示し、色だけの補正（彩度・色温度・色かぶり）を隠す
- スライダー: 不透明度・露出・明るさ・コントラスト・ガンマ・シャドウ・ハイライト・レベル（黒・白・中間）・色温度・色かぶり・彩度・シャープ（量・半径）。名前のダブルクリックで元の値
- 16bit・float の画像は元の値の統計で 0〜255 に引き伸ばしてから補正する（DRA がオフなら画像全体の 2〜98 %、オンなら表示範囲から DRA の設定で）。8bit の画像はそのまま補正する
- QGIS 標準にない補正: リニア光での計算、露出、色温度・色かぶり・ホワイトバランス、シャドウ・ハイライト、トーンカーブ（チャンネル別）、レベル、シャープ（アンシャープマスク）、RGB 連動・範囲固定の DRA
- 描くのは画面に見えている画素だけ（QGIS が画面に合ったオーバービューを読む）なので、大きな COG でも処理量は画面の大きさ分
- 設定ファイルの `imageRules`（ビューアと同じ書き方）: 開いた画像（カタログから開いたものも）のファイル名に最初に合った規則の補正（`preset`・`enhance`）・バンド（番号か GDAL のバンド名）・ノーデータ（`noData`）を自動でかける。プロジェクトから開いたレイヤーは保存した表示のまま。バンドが足りないときは補正だけかけて理由を表示
- 「ヒストグラム（表示範囲）」: 表示範囲の補正後・補正前の値の分布（R・G・B を加算で重ねる。白黒は輝度）と、チャンネルごとの最小・平均・中央・最大。「対数」で少ない値も表示。グラフを指すとその値の画素数。地図を動かすか補正を変えると取り直す（開いている間だけ、最長 512 px で読んでタスクで計算）
- 「トーンカーブ」: 補正のトーンカーブをグラフで編集（ドラッグで移動、クリックで点の追加、ダブルクリックか枠の外へのドラッグで削除）。RGB 全体と赤・緑・青の別のカーブ（白黒の画像は全体のみ）。背景に表示範囲のヒストグラム（ヒストグラムを開いているとき）。カーブはスライダーの補正のあと、シャープの後ろにかかる
- 「着色（単バンド画像）」: SAR・パンクロなど 1 バンドの画像をカラースケール（赤・緑・青・シアン・マゼンタ・黄・オレンジ・熱・ビリディス・虹・青→白→赤・好きな色）で着色。補正のあとに色を付ける。「反転」「暗い所を透明に」、下のレイヤーとの重ね方（通常・スクリーン・差・比較（明）・比較（暗）・乗算。QGIS のレイヤーの合成モード）
  - 表示方法「区分」（等間隔・分位数・手動）と「値ごとに色分け」（分類画像。64 種類まで）は画像の値で色分けし、補正はかけない。凡例で色・上限・名前を変えられ、画像に占める面積も表示。区分は QGIS のレイヤーの凡例にも出る
  - 「2 時期の色分け重ね合わせ」で前の画像を赤、後の画像をシアン（スクリーン）にして後を前の真上に置く。変化なしは白黒、後で明るくなった所はシアン、暗くなった所は赤。前後は撮像日時の順（日時がなければレイヤー一覧の下から）
  - プロジェクトには QGIS 標準の単バンド疑似カラー（区分は離散・値ごとは完全一致）として書くので、プラグインなしでも色分けが見える
- 補正はレイヤーのカスタムプロパティ `satobs/enhance`（JSON。補正はビューアのプロジェクトと同じ `{"version": 1, "ops": [...]}`）に保存。プロジェクトファイルには QGIS 標準のレンダラーとして書くので、プラグインなしでも普通に開け、プラグインがあれば補正が戻る

### パンシャープン

メニューの「パンシャープン…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ パンシャープン」と同じ）で、高解像度のパンクロ画像の細部を低解像度のマルチスペクトル画像に合成する。計算はビューアのライブラリの `panSharpen` を NumPy に移したもの（下の「ビューアとの数値比較」で一致を確認）。

- 入力: パンクロ画像（とそのバンド）・マルチスペクトル画像。最初は一番細かい 1 バンドの画像と、複数バンドの画像（アクティブなレイヤーを優先）が選ばれた状態
- 方式: Gram-Schmidt（推奨・色を維持）・IHS（くっきり・色が変わることも）・Brovey（コントラスト強め）。詳細設定に再サンプリング（バイリニア・バイキュービック）、強さ（0〜200 %）、輝度の重み（自動（パンクロに合わせて推定）・均等）
- 結果: 2 つの画像の重なる範囲を、パンクロの解像度で、マルチスペクトル画像のバンド・型（16bit は 16bit のまま）・ノーデータ・アルファのままタイル分割の GeoTIFF（DEFLATE 圧縮・オーバービューつき）に出力。レイヤー名は `<マルチスペクトル>_pansharpen`、マルチスペクトル画像の画像補正（バンド割当・補正）を引き継ぐ
- 大きな画像も 2048 px のブロックごとに処理（係数は重なり全体か、2048 × 2048 px を超えるときは全体に散らした 256 px の窓 8 × 8 から 1 回だけ求めるので、ブロックの継ぎ目なし）。処理はバックグラウンドで、中止も可
- 2 つの画像の座標参照系が違っても、マルチスペクトル画像をパンクロの座標参照系に投影し直して合成

Python からは `api.image_enhance.enhance(layer, "satellite", bands=[4, 3, 2])`（補正はプリセット名・`{"version": 1, "ops": [...]}`・`Pipeline`）、着色は `api.image_enhance.colorize(layer, "cyan", blend="screen")`（`reverse`・`fade`・`classes` も）。

### 変化抽出（2 時期）

メニューの「変化抽出（2 時期）…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 変化抽出（2 時期）」と同じ）で、同じ場所の前・後の画像（バンド）を画素ごとに比べ、値が下がった所を青、上がった所を赤（変化なしが白）で塗った 1 バンドの画像（32 bit 浮動小数）を作る。前・後は撮像日時の早い順（分からなければレイヤー一覧の下から）で最初から選ばれる。

- 比べ方は差（後 − 前）・対数比 dB（SAR 向け）・比・正規化差。2 枚は細かいほうの画像の格子にそろえる（重なる範囲。座標系が違えば再投影）
- 大きく変わった所は「変化域」にポリゴンで出し、方向（増加・減少）・面積（m²、楕円体）・画素数を属性に持つ。しきい値は既定で変化の平均 ± 標準偏差の 2 倍。詳細設定で値・向き・最小の大きさ・再サンプリングを変えられる

### 自動位置合わせ

メニューの「自動位置合わせ…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 自動位置合わせ」と同じ）で、合わせる画像（最初はアクティブな画像）と基準の画像（最初はほかで最も細かい画像）の模様を照合（位相相関）して、ずれを自動で求める。重なる範囲全体を粗く照合してから、格子状の数か所（既定 4 × 4）を基準の画像の解像度で照合してタイポイントにし、平行移動（中央値）かアフィン（回転・伸縮も、最小二乗、外れ値は除外）で直す。結果は基準の画像と同じ格子に載せた、すべてのバンドを持つ画像（画像補正は引き継ぎ）。ずれ（東・北）・照合できた数・残差は処理のログに出る。明るさの違う画像どうし（別の日、別のセンサー）でも照合できるが、模様の少ない画像（水面など）は照合できない。

### 簡易オルソ補正

メニューの「簡易オルソ補正…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 簡易オルソ補正」と同じ）で、RPC がなく平らな地面（基準高）に載せてある画像を、標高データ（DEM のラスター）と衛星の方向（方位角・仰角）で地形のずれを直す。基準高より h m 高い所は衛星と反対の向きに h ÷ tan（仰角）m ずれて写るので、その分を戻す。

- 方位角・仰角を空欄にすると画像のメタデータ（`meanSatAz`・`meanSatEl`・`satellite_azimuth`・`off_nadir` など）か、画像と同じ名前の .IMD から読む。基準高を空欄にすると画像の範囲の平均標高
- 標高データのない所は動かさない。結果は元の画像と同じ格子・すべてのバンド（画像補正は引き継ぎ）
- RPC のある画像は QGIS の「ワープ（再投影）」で RPC と DEM を使って補正できるので対象外

### 土地被覆分類

メニューの「土地被覆分類…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 土地被覆分類」と同じ）で、画像の画素を色（バンドの値）の似たものどうしのクラスに分けて色分けし、クラスごとの面積を出す。

- 自動（教師なし）: クラスの数だけ指定。画素の見本（最大 6 万画素）を k-means で分け、クラス 1 が最も暗い。乱数の種が同じなら同じ結果
- 学習ポリゴン（教師あり）: 見本を囲んだポリゴンのレイヤー（「新規スクラッチレイヤー（テンプレート）…」などで作図）と、クラス名を入れた属性を選ぶ。属性の値ごとに 1 クラス（2 クラス以上）。最尤法（平均とばらつき、推奨）か最短距離法（平均のみ）
- 結果はクラス番号の画像（8 ビット、0 はデータなし、クラスの色と名前つき）と「クラスの表」（番号・クラス・色・画素数・面積 km²・割合 %）。「クラスごとにポリゴン化」でクラスの範囲をポリゴンにも（面積は楕円体）。使うバンド・最小の大きさ・乱数の種は詳細設定

## 影から高さ

メニュー・ツールバーの「影から高さ」でドックを開くと、地図のクリックが計測になる（ほかの道具に切り替えたら「計測」で戻す）。建物・塔・木などの根元をクリックし、次にその影の先端をクリックすると、影の長さ（WGS 84 楕円体上の距離）× tan（太陽高度）で高さを出す（地面は平らとみなす）。

- 太陽高度と方位は、根元の下の画像（アクティブなラスターレイヤー、なければその地点の一番上の GDAL 画像）のメタデータ（`SUN_ELEVATION`・`SUN_AZIMUTH`、Maxar の `MEANSUNEL`・`MEANSUNAZ`（.IMD も）、太陽天頂角、NITF の USE00A など）から。なければ撮影日時（レイヤーの時系列・メタデータ・NITF・ファイル名・TIFF の DateTime・観測記録で入力した日時）と根元の位置から計算。どちらもなければドックに太陽高度か撮影日時（UTC）を入力
- 方位が分かるときは影の向きの案内線を出し、2 点目を影の向きに吸着（「影の向きに吸着」で切り替え）。Esc で 1 点目を取り消し
- 測った高さは地図の上に描き、ドックに一覧。「レイヤーとして追加」で線のスクラッチレイヤー（高さ・影の長さ・太陽高度・方位、高さのラベル付き）にする

## スペクトル

メニュー・ツールバーの「スペクトル」でドックを開くと、地図のクリックでアクティブな画像のその点の全バンドの値を、バンドを横軸にした折れ線で表示する（「ドラッグした範囲の平均」にすると、ドラッグした範囲の各バンドの平均と最小〜最大の幅）。植生・水・市街地の違いを見て、バンド演算や RGB の割当を決めるのに使う。

- 値は画面の補正後ではなく、ファイルそのものの値（GDAL で読む）。ノーデータ（ファイルのものとレイヤーに設定したもの）は除く。100 万画素を超える範囲は間引いて読む
- 最大 8 本まで重ね、地図に番号の印を付ける（古いものから消える）。グラフの上にカーソルを置くと、そのバンドの各線の値
- 「CSV 保存」でバンドごとの行・線ごとの列の CSV（範囲は最小・最大・標準偏差も）。アクティブなレイヤーを変えるとグラフは最初から

## スワイプ比較

メニュー・ツールバーの「スワイプ比較」で、アクティブなレイヤー（レイヤーパネルでグループを選んでいればそのグループ）を線の左側だけに表示し、右側には下のレイヤーを表示する（画像同士のほか、ベクターや背景地図とも比較可）。アクティブなレイヤーを変えると、比べるレイヤーも追従。

- 線のドラッグで移動、それ以外のドラッグで地図を移動、ホイールで拡大縮小
- ダブルクリックで縦線（左右で比較）と横線（上下で比較）を切り替え。矢印キー（Shift で大きく）・Home・End でも移動
- Esc か、ほかの地図ツールを選ぶと終了（前の地図ツールに戻る）
- レイヤーの表示・非表示やプロジェクトは変えない（線の反対側に、比べるレイヤーを除いた地図を重ねて描く）

## 位置ずらし

位置情報が数 m〜数十 m ずれた画像を手で合わせる。メニュー・ツールバーの「位置ずらし」で、アクティブな画像（ファイルのラスター）を地図のドラッグで動かす（ドラッグ中は画像の写しがマウスに付いて動き、放すと移動）。矢印キーで画面の 1 画素（Shift で 10 画素）ずつ。ずらし量（東・北、m）はステータスバーに出る。Esc か、ほかの地図ツールを選ぶと終了。

- 画像のファイルは変えない。QGIS のプロファイルのフォルダーに位置情報だけ動かした小さな VRT を作り、レイヤーの参照先をそれに替える（スタイル・画像補正はそのまま）。ずらした画像は Processing・書き出し・このプラグインの道具でもずらした位置で扱われる
- 「位置ずらしの解除」でファイルの位置に戻す

## 座標・地名へ移動

- ツールバー「座標・地名へ移動」の入力欄に座標を入れて Enter（か「移動」）で、その地点へ移動して青い丸の印を付ける。読める表記はビューアと同じ: 緯度経度（`35.6812, 139.7671`、`35°40'52"N 139°46'1"E`、`北緯35度40分52秒 東経139度46分1秒`、`354052N 1394601E`、`lat 35.68 lon 139.77`、`POINT(139.77 35.68)`、全角も可）、MGRS（`54SUE8843349290`、精度は任意）、UTM（`54N 388433 3949290`）
- 設定ファイルに `geocoders` があれば地名・住所も入れられ、打つ途中で見つかった場所が欄の下に並ぶ（↑↓と Enter かクリックで移動）。種類はビューアと同じ `gsi`・`nominatim`・`arcgis`・`features`（Esri の地名レイヤー）・`csv`（名前・緯度・経度の列がある CSV。設定ファイルからの相対パス可）。`geocoders` がなければ地名は検索せず、入力が外へ送られることはない
- カーソル位置の WGS 84 座標をステータスバーの右に表示。表記（10進・度分秒・MGRS・UTM）は地図の右クリックの「ステータスバーの表示」か、表示の右クリックで切り替え
- 地図の右クリック「緯度経度・MGRS・UTM のコピー」で、その地点の座標をコピー

## Python API

Python コンソールから `plugin = qgis.utils.plugins["satellite_observation"]` で取り、`plugin.api` を使う。観測記録はビューアのスクリプトと同じ関数を snake_case で持つ（観測記録ドックで選んだ保存先が対象）。

```python
api = plugin.api
api.observation_images()                                   # 画像の一覧（撮像日時順）
api.observe_image("d2.tif")                                # 記録する画像
rec = api.add_observation(139.7, 35.6, object="あおば", kind="船舶 > 護衛艦", activity="停泊")
api.update_observation(rec["id"], note="直した")
api.observed_things(kind="船舶")                            # モノと流れ
api.observations(start="2026-10-01", end="2026-10-31")     # 記録（時刻は ISO 文字列）
api.observation_candidates(139.7, 35.6, kind="船舶")        # 同一候補
api.add_checked_area(bbox=[139.69, 35.59, 139.72, 35.62], kind="船舶")
api.observation_report(title="週報", save="/tmp/週報.html") # 報告書（地図つき）
```

ほかに `rename_observed_thing`・`delete_observations`・`confidences`・`checked_areas`・`delete_checked_areas`。ドックそのものは `api.observation_dock`（`save_csv(path)`・`to_layers()`・`set_observer(name)`）。画像カタログは `api.image_catalog`（`search()`・`records`・`choose()`・`open_records()`・`find_similar()`・`add_layer()`）、通知は `api.notices`（`check()`・`watch_point(lon, lat)`・`store()`）、座標・地名へ移動は `api.coordinates`（`jump(text)`・`search.search(text)`・`go_to_place(place)`・`set_notation("mgrs")`）、スペクトルは `api.spectral`（`add_point(point)`・`add_box(rect)`・`series`・`save_csv(path)`）、スワイプ比較は `api.swipe`（`set_active(True)`・`set_target(layer)`・`set_position(0.3)`・`set_orientation("horizontal")`）、位置ずらしは `api.shift`（`set_shift_metres(layer, 12, -3)`・`shift_metres(layer)`・`reset()`）、影から高さは `api.shadow_height`（`set_sun(45, 180)`・`set_time(ms)`・`measurements`・`add_layer()`）、新規スクラッチレイヤーは `api.new_scratch_layer("目標・物体")`（組織のものは `api.new_scratch_layer("巡回記録", "config")`。`create()` で作成）。

## 起動時のレイヤー

設定ファイルの `layers`（ビューアの「起動時に読み込むレイヤー」）を、QGIS を空のプロジェクトで起動したときと「新規プロジェクト」のときに追加する。上に書いたものが下になる。メニューの「設定ファイルのレイヤーを追加」でいつでも追加でき、「設定…」の「起動時と新規プロジェクトで、設定ファイルのレイヤー（layers）を追加」で止められる。

| type | QGIS での開き方 |
| --- | --- |
| `cog` | GDAL（URL は `/vsicurl/`） |
| `file` | GeoJSON などは OGR、Shapefile の .zip は `/vsizip/`、画像・GeoTIFF は GDAL。相対パスは設定ファイルの場所から |
| `wms`・`wmts`・`xyz` | WMS プロバイダー（WMTS の `matrixSet` 省略時は GoogleMapsCompatible、XYZ の `#name=`・`zmin`・`zmax` も読む） |
| `wfs`・`ogc-features` | WFS・OAPIF プロバイダー（`filter` はレイヤーのフィルター） |
| `esri` | フィーチャーサービスは ArcGIS フィーチャーサーバー、マップ・イメージサービスは ArcGIS マップサーバーのプロバイダー |
| `wcs`・`ogc-coverage` | WCS プロバイダー・GDAL の OGCAPI ドライバー |
| `ogc-tiles` | XYZ のタイル（ベクタータイルはベクタータイルレイヤー） |

読み込みは QgsTask の中で行い、開けないレイヤーはメッセージバーに理由を出して残りを追加する。サービスの認証は「設定…」で選んだ認証設定を使う。

## 導入

1. `python3 scripts/build_zip.py` で `dist/satellite_observation-<版>.zip` を作る
2. QGIS の「プラグイン」→「プラグインの管理とインストール」→「ZIP からインストール」
3. メニュー「プラグイン」→「衛星撮像計画・観測記録」→「設定…」で設定ファイル（パスか URL）を指定し「読み込み」。問題があれば一覧に出る

### 設定ファイルを同梱して配る

画像ビューアの `config.json`（`public/config.json` など）をそのまま zip に入れて配れる。

```
python3 scripts/build_zip.py --config /path/to/image-viewer/public/config.json
```

- zip の中では `satellite_observation/config.json`（`.jsonc` ならそのまま）になる。`satellite_observation/` に `config.json` を置いて `--config` なしで作っても同じ（この場所は git の対象外）
- 受け取った人が「設定…」で設定ファイルを指定していなければ、同梱のものを読む。指定していればそちらが優先。欄を空にすると同梱のものに戻る。ドック上部の表示は「同梱の設定ファイル読み込み済み」
- 作るときに設定ファイルを読んで確かめ、読めない・問題があるときは zip を作らない。`token` が書いてあれば注意を出す（zip を受け取った人全員に渡るため。サインインが要るサービスは各自の QGIS の認証設定を使う方がよい）
- プラグインを入れ直すと同梱の設定ファイルも新しい zip のものに置き換わる。各自の指定（`QgsSettings`）は残る

## 設定

| 項目 | 保存先 |
| --- | --- |
| 設定ファイルのパス・URL、記録者、サービスごとの認証設定 | `QgsSettings`（`satellite_observation/…`） |
| 同梱の設定ファイル（指定がないときに読む） | プラグインのフォルダーの `config.json`（または `config.jsonc`） |
| 観測記録・確認範囲・分類体系・写真・新着画像の監視と通知（ローカル） | ユーザープロファイルの `satellite_observation/observations.gpkg` |
| `pathMappings` で選んだフォルダ、類似画像の許容差、カーソル位置の表記、新規スクラッチレイヤーの保存済みテンプレート | `QgsSettings` |

設定ファイルはビューアの `config.json` をそのまま読む（コメント付き JSON も可）。読む項目は `satelliteCatalogs`・`sensorCatalogs`・`planStores`・`groundStations`・`cloudForecast`・`imageCatalogs`・`watchInterval`・`pathMappings`・`observationStores`・`observationVocabulary`・`arcgisPortals`・`layers`・`baseMaps`・`defaultBaseMap`・`geocoders`・`layerTemplates`・`imageRules` で、ほかの項目は無視する。

認証: ArcGIS のサービスごとに QGIS の認証設定（OAuth2・ESRI token・Basic など）を「設定…」の表で選ぶ。設定ファイルの `token` も使えるが、認証設定を選んだサービスでは送らない。トークンや認証情報はログ・CSV・レイヤー・プロジェクトファイルに残さない。

## 構成

```
satellite_observation/
  core/      純 Python（Qt / QGIS に依存しない）: 設定・Esri・GeoPackage・撮像計画・観測記録
  qgis_io/   QGIS の通信（QgsNetworkAccessManager）・QgsTask・設定・画像補正のレンダラー・パンシャープンのファイル処理
  processing_provider/  Processing のアルゴリズム（パンシャープン）
  ui/        ドック・ダイアログ
  tests/     pytest
```

画像補正は、ビューアのライブラリのコミット済みの `dist/` を Node で動かして突き合わせる（`npm install` は不要）。

```
python3 scripts/compare_viewer/compare_enhance.py /path/to/browser-image-enhancement/packages/browser-image-enhancement/dist
python3 scripts/compare_viewer/compare_color.py /path/to/browser-image-enhancement/packages/browser-image-enhancement/dist   # 着色（カラースケール・区分）

```

ビューアの `imaging-plan.ts`（移動目標・衛星パスも）を esbuild で束ねて Node で動かし、同じ衛星・対象・条件でプラグインの計算と突き合わせる（時刻 ±1 秒、角度 ±0.05°、被覆 ±1%、組み合わせは同じパス）。ネットワークは `npm install` のときだけ使う。

座標の表記は `python3 coords.py /path/to/browser-image-enhancement/packages/coordinate-notation/src/index.ts` で、ビューアの `coordinate-notation`（mgrs も）と読み取り・書き出しを突き合わせる。
