# 衛星撮像計画・観測記録（QGIS プラグイン）

Web 画像ビューア（[browser-image-enhancement](https://github.com/Tosei-sudo/browser-image-enhancement) の `usecase/image-viewer`）の「撮像計画」と「観測記録」と、ビューアの中心機能の画像補正（色調補正）を QGIS プラグイン（Python / PyQGIS）にしたもの。同じ設定ファイル（`config.json`）と同じ ArcGIS フィーチャーサービスを共用する。

- 対応: QGIS 3.34 LTR 以上（Qt5 / Qt6）
- 追加の依存: `sgp4`（任意。なければ同梱の純 Python 版で動く。入れると約 15 倍速い）、`onnxruntime`（AI の推論だけに必要。AI 学習は追加なし）。numpy は QGIS 付属のもの。Windows 版の zip には両方とも同梱（`timeZone` の IANA 名に使う `tzdata` も）
- 閉域ネットワークで動作（外部の暦ファイル・地図タイルを使わない）

> 開発中。現在は改訂前の段階 8 までと画像カタログ（骨組み、画像カタログ: 検索・一覧・フットプリント・開く・類似画像の検索・新着画像の通知、撮像計画: 衛星カタログ・撮像モード・衛星ツリー・撮像機会の計算・組み合わせ・優先度・シーンの共有・撮像範囲の移動・タイムライン・一覧と地図・CSV とレイヤー・計画の保存と追跡・予定表と通知・雲量予報・地上局・ステレオペアと干渉ペア・再訪間隔マップ・移動目標撮像計画・衛星パス、観測記録: 記録・継続・同一候補・2 点・確認範囲・モノの流れ・分類体系の編集・報告書・CSV とレイヤー・Python API）。ビューアとの違いは [docs/differences.md](docs/differences.md)。

## ドックの配置

- 初期位置は 3 つのタブのまとまり。撮像系（撮像計画・衛星パス・保存した撮像計画・撮像依頼・撮像計画ファイル出力）は右、カタログ系（画像カタログ・通知・画像補正・影から高さ）は左、記録系（観測記録・分類体系の編集・移動体・AI結果）は右の下段
- 最初に開いているのは「画像カタログ」と「撮像計画」だけ。ほかはメニューかツールバーから開く（QGIS が前回の配置を覚えていれば、そちらが優先）
- 浮かせたドックが画面外にある場合（モニターを外したあとなど）、開いたときに元の場所へドッキング
- メニュー「ドックを初期位置に戻す」で、すべてのドックを初期位置のタブに戻す。開いているドックは開いたまま

## 背景地図

- ツールバーの「背景地図」（メニューでは同名のサブメニュー）で、なし・地理院 標準・地理院 淡色・地理院 写真・地理院 ベクトル・OpenStreetMap・OpenStreetMap（Esri ベクトル）を切り替え。表示中のものにチェック
- 一覧はビューアと同じ `config.json` の `baseMaps`（書くとこの一覧で置き換え）。`type` は `xyz`・`mvt`・`style`・`esri`、書かなければ URL から判断。相対 URL は設定ファイルの場所が基準
- 背景地図はプロジェクトのいちばん下のレイヤー 1 枚。切り替えると差し替え、「なし」で削除。ほかのレイヤーはそのまま
- `defaultBaseMap` があれば、空のプロジェクトで起動したときと新規プロジェクトで表示
- 閉域では `baseMaps` を社内のタイルに書き換え（既定の一覧はインターネットの地図）。読み込めない背景地図はメッセージバーに理由
- ArcGIS の VectorTileServer で認証が要るものは「設定…」でそのサービスの認証設定を選択（`token` はレイヤーに書かない）

## 画像カタログ

「画像カタログ」ドックで `imageCatalogs` の画像を検索する。範囲（既定は表示範囲。「範囲を描く」で地図に多角形を描いて「描いた範囲」も。クリックで頂点、ダブルクリックか右クリックで確定、Esc で取消）、「レイヤー」でベクターレイヤーを選ぶとその地物の形そのもの（外接矩形ではなく。ポリゴンは結合、ラインはライン、ポイントは複数点として。「選択地物のみ」も可）と重なる画像）、撮像日、「詳細条件」で登録日・システム登録日・センサー・角度の上限・方位角・SQL。

- 一覧は新しい順で、見出しのクリックで並べ替え（空の値は常に最後）。地図に全件のフットプリント（青）と選んだもの（橙、画像 ID 付き）。「地図で選択」を押すとフットプリントのクリックで選べる（Ctrl・Shift で追加）
- 「開く」かダブルクリックでラスターレイヤーに。URL は `/vsicurl/`、ローカルパスは `pathMappings` に従う（`url` があればそれ、なければそのままのパス、だめなら初回にフォルダを選び記憶。「フォルダの対応を消去」で忘れる）。開けないときは理由を表示。「パスをコピー」で場所をクリップボードへ
- 開いたレイヤーはカタログの属性をカスタムプロパティとメタデータに持つ（`satobs/imageId` は観測記録と計画の追跡が使う）
- パスが画像ではなくフォルダのレコード: フォルダの下（階層は何段でも）のファイルのうち、カタログの `imagePatterns` に合うものをそのレコードの画像とする（下記）。画像が複数なら「開く画像の選択」で選んで（既定は全部。絞り込み・表示中をすべて選択／解除あり）、レコードの画像 ID の名前のグループにまとめて開く。各レイヤーの名前はフォルダからのパス、`satobs/imageId` はレコードの ID（観測記録・AI結果・計画の追跡はレコード単位で共有）、`satobs/imageFile` にフォルダからのパス。1 枚だけなら聞かずに開く。通知・保存した撮像計画から開くときも同じ

### フォルダのレコードの画像（`imagePatterns`）

センサーごとにフォルダ構成・ファイル名の規則が違うので、カタログごと・センサー（`fields.sensor` の値。大文字小文字と前後の空白は区別なし）ごとに正規表現を書く。`*` はそれ以外のセンサー。

```jsonc
"imageCatalogs": [
  { "label": "衛星画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0",
    "fields": { "id": "IMG_ID", "sensor": "SENSOR", "source": "PATH" },
    "imagePatterns": {
      "WV03": "-P1BS-[^/]*\\.TIF$",                                   // パンクロだけ
      "SPOT7": ["^IMG_[^/]*_P_[^/]*/.*\\.JP2$", "^IMG_[^/]*_MS_[^/]*/.*\\.JP2$"],  // 配列ならどれかに合うもの
      "*": "\\.tiff?$"
    } }
]
```

- 正規表現（Python の `re`、大文字小文字は区別なし）は、レコードのフォルダからのパス（区切りは `/`。例 `IMG_01_P_001/IMG_01.JP2`）の一部に合えばよい。全体に合わせるなら `^…$`
- 全センサー共通なら文字列か配列だけでも可（`"imagePatterns": "\\.ntf$"`）
- 書かない、または合うセンサーも `*` もないときは、ふつうの画像ファイル（`.tif`・`.tiff`・`.jp2`・`.j2k`・`.ntf`・`.nitf`・`.img`）。`.aux.xml`・`.ovr` などは合わない
- 1 フォルダから最大 1000 枚まで（超えたら先頭のみ。選択画面に表示）。フォルダの場所は画像ファイルと同じく `pathMappings` に従う（大文字小文字を区別せずにたどる）。URL（COG・`pathMappings` の `url`）のフォルダは一覧できないので不可
- 正規表現の誤りは設定の問題に表示し、その正規表現だけ使わない

### ピラミッド（.ovr）の自動作成（`overviews`）

- QGIS に追加したローカルの画像（レイヤーの追加・ドラッグ＆ドロップ・プロジェクトを開いたときなど、開き方を問わない。`scope` が `"catalog"` ならカタログ・通知・保存した撮像計画から開いた画像だけ）にピラミッドがなければ、バックグラウンド（QGIS のタスク。ステータスバーで進捗・取消）で外部の `.ovr` を作り、できたらレイヤーを読み直す。**画像本体は書き換えない**（読み取りのみ）。1 枚ずつ順に作り、同じ画像は二重に作らない。内部ピラミッド・既存の `.ovr`・JPEG 2000 などの解像度レベルがあれば作らない。URL（COG）の画像は対象外
- 置き場所（`location`）:
  - `"auto"`（既定）: 画像のフォルダに書き込めれば隣に `画像名.tif.ovr`（一時フォルダで作ってから移すので、作りかけは読まれない）。書き込めなければ PC ごとのキャッシュフォルダ
  - `"cache"`: 書き込めるフォルダでも常にキャッシュフォルダ（画像のフォルダには何も書かない）
- キャッシュフォルダは GDAL の `GDAL_PAM_PROXY_DIR`。既定は QGIS 自身が設定しているプロファイルの `gdal_pam` フォルダ（読み取り専用フォルダの画像の統計なども GDAL がここに置く）。設定ファイルの `cacheFolder` で別のフォルダに変更できる（GDAL はこの値を最初に使うときに 1 回だけ読むので、**変更は QGIS の再起動後に有効**）
- キャッシュの .ovr は GDAL が画像を開くたびに自分で見つける（レイヤーの参照先は元の画像のまま。RPC・ファイル名のルール・観測記録はそのまま）。このプラグインを入れていない QGIS や他の GIS からは見えない
- `"cache"` のときは、カタログから画像を開く前に、その画像の `.aux.xml` をキャッシュ側に移す（隣にあれば内容を写す。隣のファイルはそのまま）。以後 GDAL はキャッシュ側を読み書きするので、QGIS が計算する統計・ヒストグラムも画像のフォルダには書かれない。キャッシュ側に `.ovr` の場所（`OVERVIEW_FILE`）を書く。**画像の隣の `.aux.xml` をあとで変えても反映されない**（キャッシュを消すと元に戻る）
- `"auto"` で書き込めるフォルダの場合、QGIS は（このプラグインと関係なく）統計を画像の隣の `.aux.xml` に書く
- カタログ以外から開いた画像は、QGIS が開いてからプラグインに知らされるので、`"cache"` でもその回は QGIS が計算した統計を画像の隣の `.aux.xml` に書くことがある（`.ovr` はキャッシュ）。次に開いたときからはキャッシュ側だけを読み書きする
- 起動時に開いたプロジェクトの画像は、設定ファイルを読み終えてから（`location`・`scope` に従って）処理する
- キャッシュの大きさは設定ダイアログの「ピラミッドのキャッシュ」に表示。「キャッシュを消去」で次回起動時に消す（開いている画像が使っているため）。キャッシュは PC ごとなので、人ごとに 1 回ずつ作る。共有フォルダを複数人のキャッシュにするのは、GDAL の索引ファイル（`gdal_pam_proxy.dat`）に同時に書き込むと壊れるおそれがあるので不可
- 長辺が `minSize` 以下の画像は作らない。段は 2・4・8…（最小の段の長辺が 256 ピクセル以下になるまで）

```jsonc
"overviews": {
  "location": "auto",          // "auto" | "cache"
  "cacheFolder": "",           // "" = QGIS プロファイルの中
  "resampling": "AVERAGE",     // NEAREST・AVERAGE・BILINEAR・CUBIC・CUBICSPLINE・LANCZOS・GAUSS・MODE・RMS
  "compress": "DEFLATE",       // NONE・DEFLATE・LZW・ZSTD・JPEG（JPEG は 8 ビットの 1・3・4 バンドのみ。ほかは DEFLATE）
  "minSize": 2048,
  "scope": "all"               // "all"（開き方を問わない）| "catalog"（画像カタログから開いた画像だけ）
}
// "overviews": false で作らない（省略時は上の既定値で作る）
```
- 「レイヤーとして追加」で一覧をフットプリントのメモリレイヤーに（撮像日時で時系列コントローラーが効く）
- 「類似画像の検索」（一覧のボタン、またはカタログから開いたレイヤーの右クリック「類似画像の検索…」）で、同じセンサー・角度 ±5°・方位角 ±20° の画像を重なりの大きい順に。比較元は赤い破線。許容差は記憶。「通常の検索に復帰」で戻る

## 通知

「この条件で監視…」（画像カタログ）か地図の右クリック「この地点の新着画像を監視…」で監視を作る。範囲は表示範囲・描いた範囲・選択中の地物・地点・指定なし。地点は既存の監視に足すこともできる。

- QGIS の起動時と `watchInterval` 分ごと（既定 10 分）に確認。初回は今ある画像を覚えるだけで、以降に増えた画像を「通知」ドックに新しい順で出す。ツールバーの「通知」に未読数
- 「開く」「移動」「既読」「すべて既読」「削除」。「監視条件」タブで有効・無効、名前の変更、削除、最終確認と失敗の理由
- 撮像計画の「予定・通知」もここに「撮像計画」として出る

## 撮像計画

「撮像計画」ドックで、対象（レイヤーの地物・選択中の地物・地図で指定した地点）、開始日時、期間、オフナディア角の上限を選び「計算」（Ctrl+Enter）。衛星の選択・日照・入射角・軌道・向き・TLE の貼り付けは「詳細条件」。

- 一覧の行を選ぶと、地図にその回の地上軌跡（破線）、届く範囲（点線）、撮像範囲（青）、衛星の位置を表示。ダブルクリックか「範囲へ移動」でその場所へ
- 面の対象が 1 回で覆えないときは「組み合わせ（全域を最短で）」で開く。目標の割合まで、複数の衛星のパスを撮像間隔と 1 日の上限を守ってつなぐ
- 「CSV 保存」はビューアと同じ列の CSV（BOM 付き UTF-8）、「レイヤーとして追加」は撮像範囲のメモリレイヤー（撮像日時付き。時系列コントローラーで絞り込み可能）
- 地物ごとに計算するとき、数値の属性を「優先度の属性」に選ぶと、組み合わせで優先度の高い地物から衛星を割り当てる。近い地点は 1 シーンにまとめる（「近い地点を 1 シーンに集約」）
- 「撮像範囲を移動」を押すと、選んだ回の撮像範囲を地図でドラッグできる（衛星が向けられる範囲内。角度と被覆は再計算）
- 「タイムライン」で衛星ごとの撮像を時間軸に表示。棒をクリックするとその回を選択
- 地図の右クリックメニューの「ここを撮像計画」で、その地点をすぐ計算
- 「ステレオペア」「干渉ペア（同じ軌道・SAR）」で同じ対象を 2 回撮る組を、「再訪間隔マップ」で対象のまわりを格子に分けたセルごとの最長の待ちを表示（緑ほど早く、赤ほど長く待つ）
- 「詳細条件」の「雲量予報」をオンにすると、光学衛星の機会に 16 日先までの雲量を付け、「雲量（以下）」で絞り込める。オンにするまで予報サービス（`cloudForecast`、既定は Open-Meteo）には何も送らない。閉域では社内の互換サービスを `cloudForecast` に指定するか、外部で毎日作った GFS の雲量ファイルを `{"folder": "…"}`（フォルダ内の最新）か `{"file": "….tif"}` で読む（ファイルの仕様は `docs/cloud-forecast-file.md`）。使わないなら `false`。ステータスに予報の初期時刻と何日前かを表示
- 「予定・通知…」で一覧の撮像を予定表（.ics）に保存、または撮像の何分前かに QGIS のメッセージバーで通知（QGIS の起動中のみ）
- 「保存・追跡…」で一覧の撮像を `planStores` のフィーチャーサービスに保存。「保存した撮像計画」ドックで計画を開くと、撮像時刻を過ぎた予定の撮像を画像カタログ（`imageCatalogs`）で確かめ、撮像済み・未撮像にする
- 設定ファイルに `satelliteCatalogs` がなければ、架空のサンプル衛星 2 機（光学・SAR、SAR は 3 モード）で試せる

### 衛星名の対応表（`satelliteAliases`）

衛星カタログと画像カタログで衛星の名前が違う（衛星カタログは「WorldView-3」、画像カタログのセンサーは「WV03」など）ときは、Esri のテーブルに対応を書き、設定ファイルにはそのテーブルの場所と属性名だけを書く（名前の一覧は設定ファイルに持たない）。

```jsonc
"satelliteAliases": {
  "label": "衛星名の対応表",
  "url": "https://gis.example/arcgis/rest/services/Satellites/FeatureServer/2",
  "fields": { "satellite": "SAT_NAME", "alias": "ALIAS" }   // 衛星カタログの名前（か ID）・画像カタログでの名前
}
```

| SAT_NAME | ALIAS |
| --- | --- |
| WorldView-3 | WV03, WV3 |
| SkySat-C12 | SkySat |
| SkySat-C13 | SkySat |

- 1 行に別名 1 つでも、カンマ（`,`・`、`）区切りで複数でも可。同じ衛星の行はまとめる。テーブルを複数使うなら配列。`where`・`token` も書ける
- 名前は英数字だけを大文字小文字の区別なく比べる（`WorldView-3` = `worldview3`、`WV-3` = `WV3`）
- 使うところ: 保存した撮像計画の追跡と撮像依頼の撮像済みの確認（画像のセンサーが衛星の名前・ID・別名と同じ画像を優先し、次に一方が他方を含む画像、なければ従来どおり時刻と範囲が合う最初の画像）、撮像依頼の衛星の指定と `requestExports` の `satellites`、フォルダのレコードの `imagePatterns`（センサーの別名のキーでも合う）
- 1 つの別名を同じシリーズの複数の衛星に付けてよい（画像カタログが号機を区別しない場合）。SkySat-C12 と SkySat-C13 は互いの別名にはならない。号機の区別は撮像時刻（`matchMinutes`）と範囲による
- テーブルは使うとき（衛星カタログの読み込み・画像カタログの検索・追跡）に一度読み、設定ファイルを読み直すまで使い回す。読めなければ別名なしで続ける

## 撮像依頼（定点・臨時）と日次出力

設計と設定の書き方は [docs/imaging-requests.md](docs/imaging-requests.md)。

- 「撮像依頼」ドックで、いつからいつまで・どこを・どの条件で撮るかを登録する（保存先は `requestStores` の Esri フィーチャーサービス）。区分は定点（毎日・曜日・N 日ごとの繰り返し）と臨時、達成条件は毎回と期間内1回
- 優先度は 5 段階（最優先〜最低）から選ぶ。「詳細」で 1〜1000 を直接指定（1 ほど高い）
- 条件: 種別（光学・SAR）、衛星シリーズ、衛星、センサー・モード、オフナディア角・入射角の範囲、観測方向、軌道方向、分解能、時間帯、実施しない雲量、優先するシステム。空欄は問わない
- 範囲は地図で矩形・点（一辺の長さ指定）、または選択中の地物から
- 「レイヤーから取り込み」で作業中のレイヤーの地物を定点の依頼として登録（依頼ID が同じものは上書き）。属性は台帳と同じ名前（`REQ_NAME`・`START_AT` …）か、名称・開始・終了・優先度 などの見出しで対応づけ。「レイヤーへ書き出し」で一覧の依頼を一時レイヤーに
- ファイルの出力は別のドック「撮像計画ファイル出力」（依頼を登録する人と出力する人が別のため、撮像依頼ドックとは分けている）。対象日（日本時間）を選んで「計算」で依頼を集め、衛星システム（`requestExports`）ごとの CSV（キー指定）・JSON（JSON Schema）を書き出す
  - 光学の依頼は日中（地方時 9〜15 時）の雲量予報を見て、10% ごとの段階を優先度の 1 の位に入れる。実施しない雲量以上なら見送り（期間内1回で期限まで 2 日以内なら警告付きで出す）
  - 優先度順に、システムの 1 日の件数・枚数の上限、区分ごとの枠、衛星ごとの 1 日の上限（`maxPerDay`）に詰める。衛星を指定した依頼はその衛星に、指定がなければ分解能の細かい衛星から。入らなければ次のシステムへ
  - 衛星とシステムの対応は、衛星カタログの `system` 属性（`fields.system`）があればそれ、なければ `requestExports` の `series`・`satellites`
  - 前回までに出した依頼は画像カタログで撮像済みか確かめ、撮れていなければ（または期間内1回で期限まで 2 日以内なら）優先度を 100 繰り上げる候補として出す（最優先の帯に入ったら止まる）
  - 確認画面で採用・見送りの切り替え、順番の入れ替え、繰り上げの取り消しをしてから書き出す。出力した内容は出力履歴（`requestStores` の `history`）に残る
  - 「上限シミュレーション…」で、システムごとの 1 日の件数・枚数・区分の上限や使うシステムを変えた場合に、今後の日数（1〜60 日）で何件が枠超過・次のシステムへ回送・欠測（毎回）・期限切れ（期間内1回）になるかを、設定の値と並べて試算する。台帳・出力履歴には書き込まない（採用した依頼は撮像できたものとして計算）
  - 「照合…」で計画と実績の照合。対象日の範囲を選び、出力した依頼が撮れたかを画像カタログと突き合わせて、システムごとの撮像済み・未撮像・未判定と撮像率を出す。衛星を指定した依頼は、その衛星（衛星名の対応表 `satelliteAliases` の別名も）の画像だけを撮像済みとする。指定のない依頼はどの衛星の画像でもよい
  - 未撮像の依頼は次回の「計算」に持ち越す（曜日・N 日ごとの定点も、その日が繰り返しの日でなくても候補に入る。期間内に限る）。繰り上げの候補にもなる
  - カタログへの登録が遅れたときなどは、照合の一覧で「撮像済みにする」「未撮像にする」で直せる（台帳の繰り上げ・完了も合わせて直る）

## 移動目標撮像計画

- メニューの「移動目標撮像計画…」で、航跡・位置報告のポイントレイヤー（AIS の CSV など）を選ぶ。ID・時刻・針路・速力・名前の属性は名前（mmsi・timestamp・cog・sog・heading など）から自動で対応づけ。速力の単位はノット・km/h・m/s
- 目標ごとに最後の報告から針路・速力で将来位置を推測（最大 72 時間）。針路・速力がなければ最後の 2 報告（1 分以上離れたもの）から求め、それもできなければその場に留まるとみなす
- 誤差の円の半径 = 報告時の誤差 + 経過時間 ×（1 時間あたりの増加 + 速力 × 割合）。既定は 0.5 km・0.5 km・10%
- 「存在予測を追加」で、一定間隔（既定 6 時間）の誤差円（時刻・経過時間・半径つき）と予測航跡をメモリレイヤーに追加
- 「撮像計画の作成」で撮像計画ドックへ（最大 50 目標）。1 時間ごとの推測位置でパスを探し、各パスをその時刻の位置で計算し直す。撮像範囲は誤差円に向け、被覆は円のうち撮像範囲に入る割合

## 新規スクラッチレイヤー（テンプレート）

- 「レイヤー」→「レイヤーを作成」の「新規一時スクラッチレイヤー…」のすぐ下と、プラグインのメニューに「新規スクラッチレイヤー（テンプレート）…」
- 「テンプレート」から選ぶと名前・ジオメトリ・属性が入り、そこから自由に変えて「作成」。テンプレートは標準（空のレイヤー・航跡〔生存圏計算用〕・調査地点・目標・物体・関心区域・被害状況・経路・測線・注記）、設定ファイルの `layerTemplates`（「組織の設定」、書き方はビューアの README と同じ）、「テンプレートとして保存」で残したもの（「保存済み」、ユーザープロファイルの `QgsSettings`）
- 属性ごとに名前・エイリアス・型（文字列・整数・小数・日付）・必須・既定値・文字数の上限・最小・最大・候補値（`1=住宅, 2=店舗`）。作るとメモリレイヤーに、エイリアス、必須は非 NULL 制約、候補値は「値マップ」ウィジェットと制約、範囲は「範囲」ウィジェットと制約、既定値は属性の既定値として入る
- 「ほかのレイヤーの属性をコピー…」で開いているベクターレイヤーの属性・ジオメトリ・座標系をひな形に（地物はコピーしない）
- 「作成後すぐ地図に作図開始」で、編集を始めて「地物を追加」の状態に
- 「航跡（生存圏計算用）」の属性名は「移動目標撮像計画…」の自動対応に合うので、描いたらそのまま存在予測を計算できる
- QGIS 標準の「新規一時スクラッチレイヤー」の画面にも「テンプレート」欄が付き、選ぶとこの画面に切り替わる

## 衛星パス

- 選んだ衛星（撮像計画と同じ衛星の一覧）の地上軌跡と撮像可能範囲（最小〜最大オフナディア角の帯、見られる側）を衛星ごとの色で表示
- 「時点」は前後 15 分と衛星の位置、「期間」は最長 7 日を時刻の目盛り付きで。一覧の行をクリックするとその衛星へ移動
- 「詳細」で前後の時間・オフナディア角の上限・光学衛星の日照・目盛り・現在時刻に合わせ続ける（30 秒ごと）・TLE の貼り付け
- 日付変更線で線と面を分割。「レイヤーとして追加」で地上軌跡と撮像可能範囲をメモリレイヤーに

`sgp4` の入れ方（任意）: QGIS の Python コンソールで `import pip; pip.main(["install", "sgp4"])`、または OSGeo4W シェルで `python -m pip install sgp4`。閉域では wheel ファイルを持ち込んで `pip install sgp4-2.*.whl`。

## 観測記録

「観測記録」ドックで、画像ごとに「いつ・どこに・何（モノ）が・何をしていたか（活動）」を記録する。画像はプロジェクトのラスターレイヤー（画像 ID はレイヤーの `satobs/imageId`、なければファイル名。撮像日時はレイヤーの時刻 → GDAL メタデータ → NITF → ファイル名 → TIFF の日時の順、分からなければドックで入力）。キーはドックにフォーカスがあるときだけ効く。

- ◀ ▶（PageUp・PageDown）で撮像日時の順に画像をたどる。「この画像のみ」で他のラスターを隠す。＋ でファイルなしの画像（ID・名称・撮像日時）を追加
- 「クリック記録」（R）で地図をクリックし、モノ・種別（階層のボタンでたどる）・活動（1〜9）・確度・備考を入れて Enter。クリック数（L で 1 → 2 → 3 → 4 点と切り替え）は「2 点」で後端 → 前端（船首・機首）のクリックで中心・長さ・向き、「3 点」でさらに片側の側面（舷側）をクリックして幅（中心線から左右同じ幅）、「4 点」でさらに両側の側面をクリックして幅（中心は両側面の中間）。測る間は外形の矩形が地図に出て、Esc で最後の 1 点を取り消し。幅は保存先の `WIDTH_M`（`fields.width`。Esri のレイヤーに属性がなければ保存しない）、CSV の「幅（m）」、レイヤー化の `width_m` に出る。幅のある記録は地図に向き付きの矩形で描き、「レイヤー化」で「観測の外形」（ポリゴン）にもなる
- 前後の画像のモノは白抜きの印。クリックか「継続」「不在」、「すべて継続」で一括。新しい記録には近くの「同一候補」（Alt+1〜5）
- 「確認範囲」（A）は対角の 2 点（または表示範囲・画像の範囲）と対象の種別。範囲内で記録のないモノは「確認範囲内 n 件を不在」で一括
- 印はドラッグで場所を直せる。削除は削除日時を入れて残し、「詳細」の「削除済みも表示」から復元
- 記録の削除: 印をクリックして開いたフォームの「削除」、「この画像」タブの行の「削除」、「モノ」タブの「このモノの記録を削除」（2 回押し）
- 「詳細」の「ローカル記録の消去…」でローカル GeoPackage の記録・確認範囲・ファイルなしの画像の一覧を完全に消去（確認あり。「削除済みのみ消去」も可。分類体系・参考写真は残す。Esri の保存先では使用不可）
- 「モノ」タブで流れ（帯グラフ・表・地図の軌跡）、名前・種別の変更・統合。「分類」タブで分類体系
- 「詳細」から報告書（HTML 保存・印刷・PDF 保存。地図はキャンバスのレイヤーに記録の印を重ねて描画）、再読み込み、CSV 保存、レイヤー化（記録のポイント・確認範囲のポリゴン・流れのライン。時系列コントローラー対応）
- 保存先は `observationStores` の Esri フィーチャーレイヤー（通信は QgsTask の中）か、ローカル GeoPackage。記録者は「詳細」の名前、なければ保存先の認証設定のユーザー名
- 設定ファイルに `"localObservations": false` と書くとローカル GeoPackage を保存先にしない（選べるのは `observationStores` だけ。どれもなければ記録不可）。省略時は `true`

### 活動（大分類ごとの切り替え）

活動のボタン（1〜9）と入力候補は、フォームの種別の分類によって切り替わる。種別の分類から上へたどって最初に「活動」を持つ分類のもの（ふつうは大分類に設定）、どれも持たなければ既定の活動（`observationVocabulary.activities`、保存先ごとの `activities` が優先）。その分類以下の記録で使った活動も後ろに並ぶ。種別を別の大分類に切り替えたとき、入力済みの活動が新しい候補になければ空欄に戻す（既存の記録を開いたときはそのまま）。

- 既定の分類体系では大分類ごとに活動を持つ（船舶: 停泊・航行・入港・出港・荷役・活動なし、航空機: 駐機・移動・離陸準備・整備・活動なし、車両: 駐車・移動・集積・活動なし、建物: 工事・使用中・活動なし、構造物: 工事・集積・活動なし。その他は既定の活動）。分類体系を書かずに `activities` だけ書いたときは、その活動をすべての分類で使う
- 変更は「分類体系の編集」ドック・「分類」タブの「活動」欄（読点区切り。空欄なら上位の分類、なければ既定の活動）
- 設定ファイルでは分類ごとの `activities`:

```jsonc
"observationVocabulary": {
  "taxonomy": [
    { "name": "船舶", "activities": ["停泊", "航行", "入港", "出港"], "children": [
      { "name": "潜水艦", "activities": ["浮上", "潜航"] }   // 下位で上書きも可
    ] },
    { "name": "航空機", "activities": ["駐機", "移動", "整備"] }
  ]
}
```

- Esri の分類テーブル（保存先の `taxonomyTable`）では属性 `ACTIVITIES`（文字列。活動を読点かカンマ区切り。`fields.activities` で別名可）に保存し、同じテーブルを使う人と共有する。テーブルに属性がなければ活動は保存されず、変更時にその旨を表示（追加するフィールドの例: 名前 `ACTIVITIES`、文字列、長さ 1000）。他の人の変更は「更新」で読み直す
- ローカル GeoPackage の分類体系（`taxonomy` テーブル）にも `ACTIVITIES` 列を自動で追加

## 分類体系の編集

「分類体系の編集」ドック（または「分類」タブの「編集ツール」）でツリーを編集する。ドラッグで移動（行の上で下位、行の間で前後、余白で大分類）、F2・ダブルクリックで名前の変更、＋ 大分類・Insert で追加（「A > B」で階層ごと）、削除は 2 回押す、Alt+↑↓ で並べ替え、検索（名前・既知の個体・諸元）。右側で階層名・個体名の呼称・既知の個体・諸元・参考写真（ファイルはローカル GeoPackage、または URL）、下で「諸元の項目」。JSON の保存・読み込みは `config.json` の `observationVocabulary.taxonomy` と同じ形。名前の変更・移動・削除は配下の記録の種別にも反映する。共有の保存先（`taxonomyTable`）を他の人が編集したときは「更新」（ドック上部、または「分類」タブ）で分類体系と諸元の項目を読み直す（記録はそのまま、選択中の分類は残っていれば保持）。

## 画像補正

「画像補正」ドックで、アクティブなラスターレイヤーにビューアと同じ補正をかける。計算はビューアのライブラリ（browser-image-enhancement）を NumPy に移したもので、同じ画像・同じ補正なら同じ画素になる（下の「ビューアとの数値比較」）。

- 「補正」をオンにしたレイヤーだけが対象。オフか「QGIS の表示に戻す」で QGIS 標準のレンダラー（同じバンド・同じ引き伸ばし）に戻る
- プリセット: 自動・鮮やか・やわらか・衛星画像・文書・白黒
- DRA（表示範囲で自動レンジ）: 方式（パーセントクリップ・最小〜最大・標準偏差）、クリップ (%)、RGB 連動、範囲を固定。地図を動かすと表示範囲の統計で引き伸ばし直す
- バンド割当: R・G・B に好きなバンド（GDAL のバンド名つき）。3 つとも同じバンドならそのバンドを白黒で表示し、色だけの補正（彩度・色温度・色かぶり）を隠す
- スライダー: 不透明度・露出・明るさ・コントラスト・ガンマ・シャドウ・ハイライト・レベル（黒・白・中間）・色温度・色かぶり・彩度・シャープ（量・半径）。名前のダブルクリックで元の値
- 16bit・float の画像は元の値の統計で 0〜255 に引き伸ばしてから補正する（DRA がオフなら画像全体の 2〜98 %、オンなら表示範囲から DRA の設定で）。8bit の画像はそのまま補正する
- QGIS 標準にない補正: リニア光での計算、露出、色温度・色かぶり・ホワイトバランス、シャドウ・ハイライト、トーンカーブ（チャンネル別）、レベル、シャープ（アンシャープマスク）、RGB 連動・範囲固定の DRA
- 描くのは画面に見えている画素だけ（QGIS が画面に合ったオーバービューを読む）なので、大きな COG でも処理量は画面の大きさ分
- 設定ファイルの `imageRules`（ビューアと同じ書き方）: 開いた画像（カタログから開いたものも）のファイル名に最初に合った規則の補正（`preset`・`enhance`）・バンド（番号か GDAL のバンド名）・ノーデータ（`noData`）を自動でかける。プロジェクトから開いたレイヤーは保存した表示のまま。バンドが足りないときは補正だけかけて理由を表示
- 「ヒストグラム（表示範囲）」: 表示範囲の補正後・補正前の値の分布（R・G・B を加算で重ねる。白黒は輝度）と、チャンネルごとの最小・平均・中央・最大。「対数」で少ない値も表示。グラフを指すとその値の画素数。地図を動かすか補正を変えると取り直す（開いている間だけ、最長 512 px で読んでタスクで計算）
- 「トーンカーブ」: 補正のトーンカーブをグラフで編集（ドラッグで移動、クリックで点の追加、ダブルクリックか枠の外へのドラッグで削除）。RGB 全体と赤・緑・青の別のカーブ（白黒の画像は全体のみ）。背景に表示範囲のヒストグラム（ヒストグラムを開いているとき）。カーブはスライダーの補正のあと、シャープの後ろにかかる
- 「着色（単バンド画像）」: SAR・パンクロなど 1 バンドの画像をカラースケール（赤・緑・青・シアン・マゼンタ・黄・オレンジ・熱・ビリディス・虹・青→白→赤・好きな色）で着色。補正のあとに色を付ける。「反転」「暗い所を透明に」、下のレイヤーとの重ね方（通常・スクリーン・差・比較（明）・比較（暗）・乗算。QGIS のレイヤーの合成モード）
  - 表示方法「区分」（等間隔・分位数・手動）と「値ごとに色分け」（分類画像。64 種類まで）は画像の値で色分けし、補正はかけない。凡例で色・上限・名前を変えられ、画像に占める面積も表示。区分は QGIS のレイヤーの凡例にも出る
  - 「2 時期の色分け重ね合わせ」で前の画像を赤、後の画像をシアン（スクリーン）にして後を前の真上に置く。変化なしは白黒、後で明るくなった所はシアン、暗くなった所は赤。前後は撮像日時の順（日時がなければレイヤー一覧の下から）
  - プロジェクトには QGIS 標準の単バンド疑似カラー（区分は離散・値ごとは完全一致）として書くので、プラグインなしでも色分けが見える
- 補正はレイヤーのカスタムプロパティ `satobs/enhance`（JSON。補正はビューアのプロジェクトと同じ `{"version": 1, "ops": [...]}`）に保存。プロジェクトファイルには QGIS 標準のレンダラーとして書くので、プラグインなしでも普通に開け、プラグインがあれば補正が戻る

### パンシャープン

メニューの「パンシャープン…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ パンシャープン」と同じ）で、高解像度のパンクロ画像の細部を低解像度のマルチスペクトル画像に合成する。計算はビューアのライブラリの `panSharpen` を NumPy に移したもの（下の「ビューアとの数値比較」で一致を確認）。

- 入力: パンクロ画像（とそのバンド）・マルチスペクトル画像。最初は一番細かい 1 バンドの画像と、複数バンドの画像（アクティブなレイヤーを優先）が選ばれた状態
- 方式: Gram-Schmidt（推奨・色を維持）・IHS（くっきり・色が変わることも）・Brovey（コントラスト強め）。詳細設定に再サンプリング（バイリニア・バイキュービック）、強さ（0〜200 %）、輝度の重み（自動（パンクロに合わせて推定）・均等）
- 結果: 2 つの画像の重なる範囲を、パンクロの解像度で、マルチスペクトル画像のバンド・型（16bit は 16bit のまま）・ノーデータ・アルファのままタイル分割の GeoTIFF（DEFLATE 圧縮・オーバービューつき）に出力。レイヤー名は `<マルチスペクトル>_pansharpen`、マルチスペクトル画像の画像補正（バンド割当・補正）を引き継ぐ
- 大きな画像も 2048 px のブロックごとに処理（係数は重なり全体か、2048 × 2048 px を超えるときは全体に散らした 256 px の窓 8 × 8 から 1 回だけ求めるので、ブロックの継ぎ目なし）。処理はバックグラウンドで、中止も可
- 2 つの画像の座標参照系が違っても、マルチスペクトル画像をパンクロの座標参照系に投影し直して合成

Python からは `api.image_enhance.enhance(layer, "satellite", bands=[4, 3, 2])`（補正はプリセット名・`{"version": 1, "ops": [...]}`・`Pipeline`）、着色は `api.image_enhance.colorize(layer, "cyan", blend="screen")`（`reverse`・`fade`・`classes` も）。

### 変化抽出（2 時期）

メニューの「変化抽出（2 時期）…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 変化抽出（2 時期）」と同じ）で、同じ場所の前・後の画像（バンド）を画素ごとに比べ、値が下がった所を青、上がった所を赤（変化なしが白）で塗った 1 バンドの画像（32 bit 浮動小数）を作る。前・後は撮像日時の早い順（分からなければレイヤー一覧の下から）で最初から選ばれる。

- 比べ方は差（後 − 前）・対数比 dB（SAR 向け）・比・正規化差。2 枚は細かいほうの画像の格子にそろえる（重なる範囲。座標系が違えば再投影）
- 大きく変わった所は「変化域」にポリゴンで出し、方向（増加・減少）・面積（m²、楕円体）・画素数を属性に持つ。しきい値は既定で変化の平均 ± 標準偏差の 2 倍。詳細設定で値・向き・最小の大きさ・再サンプリングを変えられる

### 自動位置合わせ

メニューの「自動位置合わせ…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 自動位置合わせ」と同じ）で、合わせる画像（最初はアクティブな画像）と基準の画像（最初はほかで最も細かい画像）の模様を照合（位相相関）して、ずれを自動で求める。重なる範囲全体を粗く照合してから、格子状の数か所（既定 4 × 4）を基準の画像の解像度で照合してタイポイントにし、平行移動（中央値）かアフィン（回転・伸縮も、最小二乗、外れ値は除外）で直す。結果は基準の画像と同じ格子に載せた、すべてのバンドを持つ画像（画像補正は引き継ぎ）。ずれ（東・北）・照合できた数・残差は処理のログに出る。明るさの違う画像どうし（別の日、別のセンサー）でも照合できるが、模様の少ない画像（水面など）は照合できない。

### 簡易オルソ補正

メニューの「簡易オルソ補正…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 簡易オルソ補正」と同じ）で、RPC がなく平らな地面（基準高）に載せてある画像を、標高データ（DEM のラスター）と衛星の方向（方位角・仰角）で地形のずれを直す。基準高より h m 高い所は衛星と反対の向きに h ÷ tan（仰角）m ずれて写るので、その分を戻す。

- 方位角・仰角を空欄にすると画像のメタデータ（`meanSatAz`・`meanSatEl`・`satellite_azimuth`・`off_nadir` など）か、画像と同じ名前の .IMD から読む。基準高を空欄にすると画像の範囲の平均標高
- 標高データのない所は動かさない。結果は元の画像と同じ格子・すべてのバンド（画像補正は引き継ぎ）
- RPC のある画像は QGIS の「ワープ（再投影）」で RPC と DEM を使って補正できるので対象外

### 土地被覆分類

メニューの「土地被覆分類…」（Processing ツールボックスの「衛星撮像計画・観測記録 ▸ 土地被覆分類」と同じ）で、画像の画素を色（バンドの値）の似たものどうしのクラスに分けて色分けし、クラスごとの面積を出す。

- 自動（教師なし）: クラスの数だけ指定。画素の見本（最大 6 万画素）を k-means で分け、クラス 1 が最も暗い。乱数の種が同じなら同じ結果
- 学習ポリゴン（教師あり）: 見本を囲んだポリゴンのレイヤー（「新規スクラッチレイヤー（テンプレート）…」などで作図）と、クラス名を入れた属性を選ぶ。属性の値ごとに 1 クラス（2 クラス以上）。最尤法（平均とばらつき、推奨）か最短距離法（平均のみ）
- 結果はクラス番号の画像（8 ビット、0 はデータなし、クラスの色と名前つき）と「クラスの表」（番号・クラス・色・画素数・面積 km²・割合 %）。「クラスごとにポリゴン化」でクラスの範囲をポリゴンにも（面積は楕円体）。使うバンド・最小の大きさ・乱数の種は詳細設定

## 測地線バッファ・正距方位での重心

メニューの「測地線バッファ…」「正距方位での重心…」（Processing ツールボックスの「衛星撮像計画・観測記録」にも）で、アクティブなベクターレイヤーを WGS 84 楕円体上で処理する。QGIS 本体の「バッファ」「重心」はレイヤーの座標系の単位で計算する（経緯度のレイヤーなら度、Web メルカトルなら高緯度ほど伸びた距離）のに対し、こちらは座標系によらず地上の m で計算する。

- 測地線バッファ: 距離（m、負でポリゴンを縮小）・円弧の細かさ・線の端（丸・平ら・四角）・融合。点の丸いバッファは本当の測地線の円、線とポリゴンは地物ごとにその中心の正距方位図法で拡張して戻す
- 正距方位での重心: 地物の中心の正距方位図法で重心を求めて戻す。ポリゴンは面積、線は長さ、点は等しく重み付け。パートごと・重心が外に出る形は内側の点、も選べる

## 影から高さ

メニュー・ツールバーの「影から高さ」でドックを開くと、地図のクリックが計測になる（ほかの道具に切り替えたら「計測」で戻す）。建物・塔・木などの根元をクリックし、次にその影の先端をクリックすると、影の長さ（WGS 84 楕円体上の距離）× tan（太陽高度）で高さを出す（地面は平らとみなす）。

- 太陽高度と方位は、根元の下の画像（アクティブなラスターレイヤー、なければその地点の一番上の GDAL 画像）のメタデータ（`SUN_ELEVATION`・`SUN_AZIMUTH`、Maxar の `MEANSUNEL`・`MEANSUNAZ`（.IMD も）、太陽天頂角、NITF の USE00A など）から。なければ撮影日時（レイヤーの時系列・メタデータ・NITF・ファイル名・TIFF の DateTime・観測記録で入力した日時）と根元の位置から計算。どちらもなければドックに太陽高度か撮影日時（UTC）を入力
- 方位が分かるときは影の向きの案内線を出し、2 点目を影の向きに吸着（「影の向きに吸着」で切り替え）。Esc で 1 点目を取り消し
- 測った高さは地図の上に描き、ドックに一覧。「レイヤーとして追加」で線のスクラッチレイヤー（高さ・影の長さ・太陽高度・方位、高さのラベル付き）にする

## スペクトル

メニュー・ツールバーの「スペクトル」でドックを開くと、地図のクリックでアクティブな画像のその点の全バンドの値を、バンドを横軸にした折れ線で表示する（「ドラッグした範囲の平均」にすると、ドラッグした範囲の各バンドの平均と最小〜最大の幅）。植生・水・市街地の違いを見て、バンド演算や RGB の割当を決めるのに使う。

- 値は画面の補正後ではなく、ファイルそのものの値（GDAL で読む）。ノーデータ（ファイルのものとレイヤーに設定したもの）は除く。100 万画素を超える範囲は間引いて読む
- 最大 8 本まで重ね、地図に番号の印を付ける（古いものから消える）。グラフの上にカーソルを置くと、そのバンドの各線の値
- 「CSV 保存」でバンドごとの行・線ごとの列の CSV（範囲は最小・最大・標準偏差も）。アクティブなレイヤーを変えるとグラフは最初から

## ダッシュボード

メニュー・ツールバーの「ダッシュボード」でドックを開くと、プロジェクトのレイヤーの概要と、1 つのベクターレイヤー（アクティブなレイヤー、または一覧で選んだもの）の集計を表示する。QGIS 本体の統計パネルは 1 つの属性の数値だけで、グラフで絞り込む仕組みはない。

- 件数: 地物・表示範囲内・期間内（時系列コントローラーが有効なとき）・絞り込み後・選択中
- 属性別: 属性の値ごとの件数（数値の属性の合計・平均も）。多い順に 15 件まで、残りは「その他」
- 数値の分布: 20 区間のヒストグラムと件数・最小・平均・最大
- 時間の推移: レイヤーのプロパティの「時系列」で設定した開始日時ごとの件数
- 値をクリックすると（Ctrl / Shift で複数）、その値の地物だけを地図と属性テーブルに表示。ヒストグラムの区間も同じ（Shift で範囲を広げる）。各グラフは、ほかのグラフの絞り込みが残す地物を数える。「絞り込みを解除」で元に戻り、「地物を選択」で絞り込んだ地物を選択
- 時間の推移の区間をクリックすると、時系列コントローラーをその期間に設定
- 「ヒートマップ」で、表示中の地物のヒートマップレイヤーを一番上に追加（半径は変更可）
- 絞り込みはレイヤーのフィルター（サブセット）にダッシュボードの条件を足して行い、ドックを閉じると元のフィルターに戻す。プロジェクトにはレイヤー本来のフィルターと、ダッシュボードの状態（集計するレイヤー・属性・絞り込み・ヒートマップ）を保存する

## スワイプ比較

メニュー・ツールバーの「スワイプ比較」で、アクティブなレイヤー（レイヤーパネルでグループを選んでいればそのグループ）を線の左側だけに表示し、右側には下のレイヤーを表示する（画像同士のほか、ベクターや背景地図とも比較可）。アクティブなレイヤーを変えると、比べるレイヤーも追従。

- 線のドラッグで移動、それ以外のドラッグで地図を移動、ホイールで拡大縮小
- ダブルクリックで縦線（左右で比較）と横線（上下で比較）を切り替え。矢印キー（Shift で大きく）・Home・End でも移動
- Esc か、ほかの地図ツールを選ぶと終了（前の地図ツールに戻る）
- レイヤーの表示・非表示やプロジェクトは変えない（線の反対側に、比べるレイヤーを除いた地図を重ねて描く）

## 位置ずらし

位置情報が数 m〜数十 m ずれた画像を手で合わせる。メニュー・ツールバーの「位置ずらし」で、アクティブな画像（ファイルのラスター）を地図のドラッグで動かす（ドラッグ中は画像の写しがマウスに付いて動き、放すと移動）。矢印キーで画面の 1 画素（Shift で 10 画素）ずつ。ずらし量（東・北、m）はステータスバーに出る。Esc か、ほかの地図ツールを選ぶと終了。

- 画像のファイルは変えない。QGIS のプロファイルのフォルダーに位置情報だけ動かした小さな VRT を作り、レイヤーの参照先をそれに替える（スタイル・画像補正はそのまま）。ずらした画像は Processing・書き出し・このプラグインの道具でもずらした位置で扱われる
- 「位置ずらしの解除」でファイルの位置に戻す

## ArcGIS Web マップ

メニューの「ArcGIS Web マップを開く…」「ArcGIS Web マップとして保存…」で、ArcGIS Online・Enterprise のポータルの Web マップ（バージョン 2.x）をそのまま開き、QGIS のプロジェクトを Web マップとして書き出す。QGIS 本体は ArcGIS のサービスを 1 つずつ開けるが、Web マップのアイテムは開けない。

- 開く: アイテムのページ（`…/home/item.html?id=…`）、Map Viewer の URL、REST の URL、または 32 桁のアイテム ID（ポータルを選択）。JSON ファイルからも開ける。非公開のアイテムは「認証設定」で QGIS の認証設定（OAuth2・ESRI token など）を選ぶ（ポータルごとに記憶し、そのポータルのホストと、ArcGIS Online なら `*.arcgis.com` のサービスにだけ使う）
- 読めるレイヤー: フィーチャー（定義式・シンボル・ラベル・ポップアップの属性名も）、マップ・イメージ・タイルのサービス、ベクタータイル、WMS（名前ごとに 1 レイヤー）、WMTS、WFS、Web タイル、地図に保存されたフィーチャーコレクション（メモリレイヤーに）。グループは平らにして、表示・不透明度・縮尺の範囲を引き継ぐ。読めないもの（KML・CSV・シーンなど）は理由とともに一覧
- Web マップ名のグループをレイヤーパネルの一番上に作って並べ、初期表示範囲へ移動し、ブックマークを追加（グループは Web マップ名）。背景地図は設定ファイルの `baseMaps` に同じものがあれば「背景地図」で切り替え、なければグループの一番下にレイヤーとして追加
- 保存: レイヤーパネルの順に、サービスのレイヤーはサービスとして、ファイル・メモリのベクターレイヤーはフィーチャーコレクション（5,000 件まで）として書き込む。シンボル（単一・分類・段階のシンプルな点・線・面）とラベル（属性 1 つ）は Web マップの形に変換。画像ファイルなど書き込めないものは理由とともに一覧。表示範囲・背景地図・ブックマークも書き込む
- 「JSON として保存…」でファイルに、「ポータルに保存…」で新しいアイテムとして（開いたアイテムへの上書きも可、確認あり）

## サーバ処理

メニューの「サーバ処理…」で、ArcGIS のジオプロセシングサービス（GPServer）や OGC API – Processes のサーバの処理を、QGIS の Processing のアルゴリズムとして実行する。QGIS 本体にはどちらも呼び出す仕組みがない。

- サービスは設定ファイルの `gpServices` から選ぶか、GPServer・GP タスク・OGC API のトップページ・`/processes`・1 つの処理の URL を入れて「読み込み」。処理を選んで「開く」（タスクや処理の URL なら読み込むとすぐ開く）
- 非公開のサービスは「認証設定」で QGIS の認証設定を選ぶ（サービスごとに記憶）。設定ファイルの `token` も、そのサービスにだけ使う
- 処理は Processing の「衛星撮像計画・観測記録 › サーバ処理」のアルゴリズムになり、入力（文字・選択肢・数値・距離と単位・真偽・日時・地物・表）を Processing のダイアログで入れて実行。地物はどのベクターレイヤーからでも送れ、Esri には Web メルカトルの Esri JSON、OGC には WGS 84 の GeoJSON で送る
- ジョブは完了まで追跡（進行とメッセージを表示、取り消すとサーバ側も取り消し）。結果の地物はメモリレイヤー、画像はラスターレイヤー、ジョブの結果の地図はマップサービスのレイヤーとして追加し、値とリンクはログに表示

## 移動体（AIS・ADS-B）

メニュー・ツールバーの「移動体」でドックを開き、船舶（AIS）・航空機（ADS-B）の位置をライブのフィードか履歴ファイルから地図に重ねる。フィードごとに点（向きで回る船・航空機の記号、ラベル付き）と航跡の 2 つのメモリレイヤーを作る。

- ライブ: 設定ファイルの `movingFeeds` を「登録済み」から選ぶか、URL と種類（WebSocket・Server-Sent Events・定期取得・ArcGIS のストリームサービス）を入れて「接続」。読める形はビューアと同じ（GeoJSON、配列、`mmsi`・`icao24`・`lat`・`lon` などの列名を自動で判別、`fields` で指定も可）。切れたら間隔を空けて再接続
- 履歴: 「履歴ファイルを開く…」で CSV・GeoJSON。QGIS の時系列コントローラーの時刻の位置を、前後の報告から補間して表示（間が空きすぎたら最後の位置で止め、古いものは薄く）
- 「撮影時刻に同期」で、アクティブな画像の撮影時刻までの 30 分に時系列コントローラーを合わせる。「ライブに復帰」で最新の位置へ
- 「詳細」で種類・取得間隔・航跡の長さ・古いとみなす時間・消すまでの時間（−1 か 0 で自動）、列の割当を変更
- メニュー「移動体と検出の照合…」（Processing の「衛星撮像計画・観測記録」にも）で、検出のレイヤー（点・ポリゴン）の各地物の撮影時刻に最も近い位置の移動体を探し、`ais_status`（一致・なし・時刻なし）・`ais_id`・`ais_name`・`ais_dist_m`・`ais_dt_s` を付けたレイヤーにする。時刻は属性・画像の撮影時刻・入力から選ぶ

## 座標・地名へ移動

- ツールバー「座標・地名へ移動」の入力欄に座標を入れて Enter（か「移動」）で、その地点へ移動して青い丸の印を付ける。読める表記はビューアと同じ: 緯度経度（`35.6812, 139.7671`、`35°40'52"N 139°46'1"E`、`北緯35度40分52秒 東経139度46分1秒`、`354052N 1394601E`、`lat 35.68 lon 139.77`、`POINT(139.77 35.68)`、全角も可）、MGRS（`54SUE8843349290`、精度は任意）、UTM（`54N 388433 3949290`）
- 設定ファイルに `geocoders` があれば地名・住所も入れられ、打つ途中で見つかった場所が欄の下に並ぶ（↑↓と Enter かクリックで移動）。種類はビューアと同じ `gsi`・`nominatim`・`arcgis`・`features`（Esri の地名レイヤー）・`csv`（名前・緯度・経度の列がある CSV。設定ファイルからの相対パス可）。`geocoders` がなければ地名は検索せず、入力が外へ送られることはない
- カーソル位置の WGS 84 座標をステータスバーの右に表示。表記（10進・度分秒・MGRS・UTM）は地図の右クリックの「ステータスバーの表示」か、表示の右クリックで切り替え
- 地図の右クリック「緯度経度・MGRS・UTM のコピー」で、その地点の座標をコピー

## AI（物体検出・クリック抽出）

ビューアと同じ ONNX のモデルで、画像から物を見つけてポリゴンにする。QGIS 本体にはない。モデルはプラグインに入っていない（設定ファイルの `aiModels` か、ONNX ファイルを指定）。

- メニュー・ツールバーの「物体検出（AI）…」（Processing の「衛星撮像計画・観測記録」にも）: レイヤー・モデル・範囲・解析の画素の大きさ（0 で元の解像度。地図の表示から始まる）を選んで実行し、見つかった物を `class`・`class_id`・`score`（回転矩形なら `angle`）と画像の情報（`image`・`image_id`・`image_time`・`model`・`detected_at`・`note`）付きのポリゴンレイヤーにする。読めるモデルはビューアと同じ（YOLOv8/11 の検出・回転矩形・セグメンテーション、YOLOX、RT-DETR、Detectron2 など。入力の大きさとクラスはモデルの情報から読み、`aiModels` の値が優先）。レイヤーは表示のとおり（補正・スタイル込み）に描いて解析し、大きい範囲は区切って重なりを付けて解析する。詳細設定で確信度・重なり（IoU）・タイルの重なり・クラスの絞り込み
- メニューの「クリック抽出（AI）」（地図ツール）: Segment Anything（SAM・MobileSAM など）のエンコーダーとデコーダーで、クリックした物の輪郭を描く。Shift+クリックで同じ物に足す点、Alt+クリックで除く点。地図の左上のパネルで、モデルの選択・「元に戻す」・「レイヤーにする」（一時レイヤー「AI 抽出」）。表示を動かすと次のクリックで描き直して解析する
- `aiModels`: ビューアと同じ形。検出は `{"label", "url", "task", "inputSize", "classes", "mean", "std", "channels", "format", "maxDetections", …}`（プラグインだけの `kinds` で、観測記録へ取り込むときのクラス → 種別の対応も）、SAM は `{"label", "encoder", "decoder", "inputSize", "mean", "std"}`。`url`・`encoder`・`decoder` は URL か、設定ファイルからの相対パス・絶対パス。URL のモデルは初回に読み込んでプロファイルの `ai_models` に保存する（「設定…」の認証設定を使う）
- メニューの「検出結果を DB へ転記…」: AI のレイヤー（`class` の属性があるポリゴン・ポイントのレイヤー）の地物を、設定ファイルの `detectionOutputs` の Esri フィーチャーレイヤーへ書き込む。属性は役割ごとの対応（画像ID・ファイル名・撮像日時・検出日時・転記日時・クラス・クラス番号・確信度・モデル・状態・経度・緯度・面積・長辺・短辺・向き・備考）で、型に合わせて変換。状態はモデルのまま（AI）・人が直した（修正: 形かクラスを変更）・人が加えた（手動）。新しい地物は追加、転記後に変えた地物は更新、残りは送らない（何を送ったかはレイヤーに記録し、プロジェクトと一緒に保存）。「選択中の地物だけ」も可。ポイントのレイヤーへはポリゴンの中の点を送る。`detectionOutputs` の形はビューアと同じ（`{"label", "url", "fields": {役割: 属性名}, "statusValues", "constants", "token"}`）
- 実行に `onnxruntime` が要る。Windows 版の zip（下の「導入」）には同梱。ほかは QGIS の Python に入れる: OSGeo4W シェルで `python -m pip install onnxruntime`、macOS は `/Applications/QGIS.app/Contents/MacOS/bin/python3 -m pip install onnxruntime`、Linux は `python3 -m pip install onnxruntime`。GPU 版（`onnxruntime-gpu`・`onnxruntime-directml`）を入れれば GPU で動く

## AI 学習（物体検出）

ビューアにはない機能。観測記録（または点・ポリゴンのレイヤー）を教師に、QGIS の中で物体検出のモデルを学習して ONNX で保存する。保存したモデルは「物体検出（AI）…」でそのまま使える。追加のライブラリは不要（QGIS 付属の NumPy だけで学習。通常の zip でも Windows 版でも同じ）。ネットワークは自作で 2 種類: 「高精度」（既定。残差ブロックとバッチ正規化の ResNet 型の本体、1/32 から 1/4 へ戻る FPN、クラスと枠の分離ヘッド、枠はセルからの距離で GIoU 損失、スコアは IoU を学ぶ品質フォーカル損失）と「軽量」（最初の版の小さなネットワーク）。どちらも CPU で学習し、重みの移動平均（EMA）・拡大縮小・回転・反転・明るさの揺らぎで学習する。

- メニュー・ツールバーの「AI 学習（物体検出）…」（Processing の「衛星撮像計画・観測記録」にも）: 学習する画像（複数可）・教師データ・クラス・バンド・エポック数などを選んで実行。保存したモデルは「物体検出（AI）」のモデルの一覧に「学習済み: 〈ファイル名〉」で並ぶ（詳細設定で外せる）。「学習に使った枠」を出力すると、教師の枠をポリゴンで確認できる
- 教師データ「観測記録」: 観測記録パネルで開いている保存先の記録のうち、各画像の記録（画像 ID が同じもの。不在・削除済みは除く）。枠の大きさは、記録の長さ（2 点で測った m）と向き（3 点・4 点で測った幅があればその幅、なければ分類体系の全幅 / 全長の比） → 分類体系の諸元の「全長」「全幅」 → 詳細設定の既定の大きさ（m）の順。向きが分からなければ、どの向きでも収まる正方形。その画像の確認範囲は「範囲内はすべて記録済み」とみなし、記録のない所を背景として学習する（種別を指定した確認範囲は、学習するクラスがすべてその配下のときだけ）
- 教師データ「ベクタレイヤー」: 点・ポリゴンのレイヤーとクラスのフィールド（空なら `class`・`KIND`・`種別` を探す）。ポリゴンは外接矩形、点は分類の諸元（なければ既定の大きさ）の正方形。`image_id` の属性がある地物はその画像だけに使う（「物体検出（AI）」の結果を手で直したレイヤーをそのまま教師にできる）。「選択した地物のみ」も可
- クラス: 分類体系の種別（`船舶 > 支援船 > 〇〇級`）。分類の深さを指定すると上位にまとめる（1 で `船舶`、2 で `船舶 > 支援船`）。対象の種別（カンマ区切り）を指定するとその配下だけ。分類の名前・別名・英名だけの値（`〇〇級`）も分類体系から種別に直す。検出結果の `class` も種別なので、そのまま観測記録に取り込める
- バンド: 空なら表示のまま（RGB。補正・スタイル込みで「物体検出（AI）」と同じに描く）。番号を指定するとバンドの値で学習する: `4` で単バンド、`1,2,3,4` や `1-4` でマルチバンド。値は学習した画素の平均・標準偏差で正規化し、その値をモデルに保存。「物体検出（AI）」はこのモデルでは表示ではなくバンドの値を読む（バンドが足りない画像は実行しない）
- 追加学習: 「追加学習の元のモデル」にこのプラグインで学習した ONNX を指定すると、その重みから学習を続ける。新しい種別はクラスとして後ろに追加（以前のクラスの番号は変わらない）。入力の大きさ・モデルの大きさ・バンドと正規化は元のまま。以前のクラスを忘れないよう、以前の画像も一緒に指定すると効果的。学習の履歴（日時・画像・クラスごとの件数・検証の結果）はモデルのメタデータ `satobs` に積み上がる
- ネットワーク: 「高精度」（既定）か「軽量」。1 回の更新は軽量が高精度の 2/3 ほどの時間。合成画像（船・航空機・車両と紛らわしい白点、学習 32 枚・評価 12 枚、入力 256・バッチ 8）での比較: 最初の版（軽量、600 回更新、約 11 分）は mAP50 0.652・mAP50-95 0.329、軽量に新しい学習法（1000 回、約 19 分）は 0.932・0.507、高精度（600 回、約 17 分）は 0.961・0.598。`scripts/ai_bench/bench.py --arch res|fpn4` で再現できる
- 学習の進め方: 物体のある所の周り（入力の 1.5 倍の範囲）と確認範囲から無作為な範囲を読み、毎回ランダムな位置で切り出し、0.75〜1.33 倍の拡大縮小・90° 回転・反転・明るさとコントラストの揺らぎを加える。重みは移動平均を保存。15 %（詳細設定）を検証に取り分け、mAP50-95 が最もよいエポックの重みを保存（ログに mAP50・mAP50-95・適合率・再現率）。中止するとそこまでの結果を保存
- 目安: 入力 256・モデル「小」・バッチ 8 で、1 回の更新が CPU で 0.3〜1 秒。1 エポックは最低 20 回の更新。小さな物体は画素を小さく（拡大）、入力の 9 割を超える物体は学習から外れるので画素を大きく

### 教師データセット（カタログにない画像と注釈）

カタログにない画像とその注釈（アノテーション）を、学習に使う「教師データセット」にまとめる。データセットは画像と注釈のファイルの場所（絶対パス）と対応を書いた小さな JSON（`*.json`）で、画像は複製しない。

- メニューの「教師データセットの作成…」（Processing の `satobs:make_dataset` にも）: 画像のフォルダーと、注釈のフォルダー（空なら画像と同じ）または全画像の注釈ファイルを指定して、保存先の JSON に書く。下のフォルダーも含める（既定）。保存先に既存のデータセットを指定すると追記（フォルダーごとにグループ、同じ画像は追加しない）
- 注釈の形式（「自動」でファイルから判定）: YOLO（画像ごとの `.txt`、`class cx cy w h` の割合。8 値の OBB も可。クラス名は `classes.txt`・`obj.names`・`data.yaml` から、なければ欄で指定）、DOTA（`.txt`）、Pascal VOC（`.xml`、`robndbox` も可）、COCO（全画像で 1 つの `.json`、`file_name` で対応）、ベクタ（GeoJSON・GeoPackage・Shapefile など地図座標。画像ごと、または全画像で 1 つ。クラスのフィールドは空なら `class`・`種別` などを探す）。回転した枠は外接する枠で学習
- 画像と注釈の対応: 同じ名前のファイル。`images/train/a.tif` と `labels/train/a.txt` のような YOLO の並びも対応する。注釈のない画像は除く（「背景として含める」で、何もない画像として学習）
- クラスの対応: `ship=船舶, plane=航空機 > 輸送機` のように、注釈のクラス名を分類体系の種別に。書かない名前はそのまま種別（分類の名前・別名でも可）。その後は観測記録と同じく、分類の深さ・対象の種別で学習するクラスが決まる
- 「AI 学習（物体検出）」の「教師データセット」でデータセットの JSON を選ぶ（複数のフォルダーは 1 つのデータセットに追記してまとめる。Processing のスクリプトからは `;` 区切りで複数も可）。地図上の画像（カタログの画像と観測記録など）と一緒にも、データセットだけでも学習できる。データセットの画像は「すべて注釈済み」とみなし、注釈のない所を背景として学習する。画素は画像のまま（地図上の位置がある画像なら「画素の大きさ」も適用）。見つからないファイルは警告して除外。学習の履歴には「データセット「名前」」と画像名が残る

## AI結果（外部AI・プラグイン内の物体検出）

ほかの AI の処理系が Esri フィーチャーサービスに書いた結果と、プラグインの「物体検出（AI）」で見つけた物を、画像ごとに表示し、選んだものを観測記録に取り込む。ビューアにはない（ビューアの AI は書き出しの「DB へ転記」だけ）。

- プラグイン内の検出: 「物体検出（AI）」を実行して検出結果のレイヤーがプロジェクトに入ると、ドック「AI結果」にその画像（`image_id`）の結果が出る（`aiResultSources` は不要）。地図のレイヤーは検出結果のレイヤーそのもの（複製しない）で、一覧と選択が連動する。レイヤーでクラスを直す・誤検出を消す・輪郭を直すと一覧に反映され、その内容で記録する。検出した画像（またはその検出レイヤー）をアクティブにすると、その画像の結果に切り替わる。種別は `aiModels` のそのモデルの `kinds`（`{"boat": "船舶"}`）→ 分類体系の同じ名前・別名・英名の分類（このプラグインで学習したモデルはクラスが分類体系の種別）→ クラスのまま。備考は「AI検出: 〈クラス〉 〈確信度〉 〈モデル〉 [AI:検出@〈検出日時〉#〈地物ID〉]」で、二度は取り込まない。長さ・幅はポリゴンの最小の回転矩形の長辺と短辺、継続の自動判定も外部AIと同じ（下記）
- ドック「AI結果」（観測記録と同じ右側のタブ）: 画像カタログから画像を開くと、設定ファイルの `aiResultSources` の各レイヤーから、その画像 ID の結果を読んで一覧と地図に出す（結果があればドックを表示）。カタログから開いた別の画像をアクティブにすると切り替わり、前の画像の結果レイヤーは消える（一度読んだ画像は読み直さない。「再読み込み」で読み直す）
- 結果はポイントでもポリゴンでもよい（ライン・マルチポイントも可）。レイヤーは出どころごとに一時レイヤー「外部AI結果 〈名前〉（〈画像ID〉）」で、クラスと確信度のラベル付き。「確信度の下限」より低い結果は一覧と地図から除く
- 一覧と地図の選択は連動。「選択を観測記録へ取り込み」「未取込をすべて取り込み」で、その画像の観測記録（ポイント）として記録する。ポイントはその位置、ポリゴンは内側の点で、長さと幅は最小の回転矩形の長辺と短辺（m。`length`・`width` の属性があればそちら）。種別は `kind` の属性 → `kinds` の対応 → クラスの順、名前は `name` の属性（なければ「船舶-1」のように自動）。備考に「外部AI 〈出どころ〉: 〈クラス〉 〈確信度〉 [AI:〈出どころ〉#〈結果ID〉]」を書き、この印がある結果は「済」として二度は取り込まない
- 取り込みには、その画像が観測記録の画像一覧にあること（開いていること）が要る。保存先は観測記録ドックで選んでいる保存先
- 継続の自動判定: 未取込の結果ごとに、前後の画像のモノ（観測記録ドックの白抜きの印）と 1 対 1 で照らし合わせ、一覧の「継続」列に出す。近い（`continueRadius` m 以内か長さの半分以内）・分類が同じか上下・長さの差 30% 以内・ほかに紛らわしいモノがない、のすべてを満たすと「継続: 〈名前〉」が選ばれた状態になり、取り込むとそのモノの継続として記録する（備考に `[自動継続]`）。`candidateRadius` m 以内だが確かでないもの（近いモノが複数・分類表にないクラス・同じ大分類の別の分類・長さが違う）は「新規（候補あり）」で、列のリストから選ぶと継続として記録（備考に `[選択継続]`）。大分類が違うもの（船舶と航空機）は候補にしない。クラスが分類体系にないとき（`kinds` で対応づけていない `ship` など）は、近さと長さだけで候補にする
- 継続として記録するときの種別は前のモノの種別（AI の種別がそれと同じか下位ならそちら）、活動・長さ・向きは AI 結果になければ前のモノのもの。位置は AI 結果の位置

```jsonc
"aiResultSources": [
  { "label": "船舶検出（外部）",
    "url": "https://example.com/arcgis/rest/services/AI/FeatureServer/0", // ポイントかポリゴンのレイヤー
    "fields": {
      "imageId": "IMAGE_ID",      // 必須。画像カタログの画像IDと同じ値の属性
      "id": "DET_ID",             // 結果ID（なければ OBJECTID）
      "class": "CLASS", "score": "SCORE", "model": "MODEL", "detectedAt": "DETECTED_AT",
      "name": "NAME", "kind": "KIND", "activity": "ACTIVITY", "length": "LENGTH_M", "heading": "HEADING", "width": "WIDTH_M", "note": "NOTE"
    },
    "where": "STATUS <> 'rejected'",       // 画像 ID の条件に AND で足す
    "minScore": 0.3,                       // 確信度の下限の初期値（0〜1。百分率の値は 100 で割る）
    "kinds": { "ship": "船舶", "plane": "航空機" }, // クラス → 種別
    "activity": "停泊", "confidence": "推定",       // 結果にないときの活動・確度（確度は保存先の段階にあるときだけ）
    "continueRadius": 50,                  // これより近い（m）前後の画像のモノは確かなら自動で継続（0 で自動にしない）
    "candidateRadius": 300,                // これより近い（m）ものを継続の候補に（0 で照合しない）
    "maxResults": 2000, "token": "…" }
]
```

## 日時のタイムゾーン（`timeZone`・`timeZones`）

サービスの設定（Esri の `dateFieldsTimeReference`、文字列の `Z`・`+09:00`）と、データに実際に入っている日時のタイムゾーンがずれているときに、外部ソースごとに本当のタイムゾーンを書ける。書いたソースの日時は「そのタイムゾーンの時計の時刻」として読み書きし、サービス側の宣言は無視する。書かないソースはこれまでどおり。ビューアと同じ書き方・同じ意味。

```jsonc
"imageCatalogs": [
  { "label": "衛星画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0",
    "timeZone": "Asia/Tokyo", "fields": { … } }
],
"observationStores": [
  { "label": "観測記録", "url": "https://gis.example/…/Obs/FeatureServer/0", "timeZone": "+09:00" }
],
"layers": [
  // サービス全体（その下のレイヤー・テーブルすべて）
  { "type": "esri", "url": "https://gis.example/…/Ships/FeatureServer", "layer": "0", "timeZone": "Asia/Tokyo" }
],
// URL の正規表現ごと（大文字小文字は区別なし）。上から最初に合うもの
"timeZones": [
  { "match": "gis\\.example/.*/Legacy/", "timeZone": "Asia/Tokyo", "serviceTimeZone": "UTC" }
]
```

- `timeZone`: データの日時が記録されているタイムゾーン。IANA 名（`Asia/Tokyo`・`UTC`）、時差（`+09:00`・`+0900`・`UTC+9`）、Windows 名（`Tokyo Standard Time`）のいずれか
- `serviceTimeZone`（任意）: サービスが日時を解釈しているタイムゾーン。Esri の日付型は、省略するとレイヤーの説明の `dateFieldsTimeReference`（`timeZoneIANA` か `timeZone`）、それもなければ UTC
- 書ける項目: `layers`・`imageCatalogs`・`planStores`・`observationStores`（`areas`・`taxonomyTable` も含む）・`detectionOutputs`・`aiResultSources`・`satelliteCatalogs`・`sensorCatalogs`・`movingFeeds`・`gpServices`（ビューアの `stacCatalogs` も読むが、このプラグインに STAC はない）。項目の中の URL すべてと、その下の URL（`…/FeatureServer` なら `…/FeatureServer/0` も）が対象
- 優先順位: 各項目の `timeZone` → `timeZones` の上から最初に合うもの。`serviceTimeZone` は同じ項目・規則のものだけを使い、なければレイヤーの説明 → UTC
- 変換する範囲: プラグインが送る Esri の要求すべて（画像カタログ・新着の監視・衛星カタログ・撮像計画の保存先・観測記録の保存先・確認範囲・分類体系・DB へ転記・外部AI結果）の日付型（`esriFieldTypeDate`）の属性の読み込み、保存（`applyEdits` の追加・更新）、検索条件の `TIMESTAMP '…'`。移動体のフィードは時刻、サーバ処理（`gpServices`）は日時の入力
- QGIS が自分で開くレイヤー（`layers` の `esri`・`wfs`・`ogc-features`、データソースマネージャーで追加したもの）: 日時は QGIS が読むので値は変えず、日時型の属性ごとに補正した仮想フィールド「〈属性名〉（Asia/Tokyo）」を足す（式は `satobs_time_zone("属性", 'Asia/Tokyo', 'UTC')`、関数は式ビルダーの「衛星観測」）。プロジェクトに保存され、開き直しても二重には足さない。Esri のレイヤーで `serviceTimeZone` がないときはレイヤーの説明を読んでから足す
- 対象外: 日付だけの型（`esriFieldTypeDateOnly`）・時刻だけの型・時差を持つ型（`esriFieldTypeTimestampOffset`）、日時を文字列型に入れた Esri の属性、検索条件の `DATE '…'`、QGIS が開くレイヤーの文字列型の属性
- 読み込めないタイムゾーン・正規表現は「設定…」の問題の一覧に出して無視する
- 閉域でも動く: IANA 名は Python の zoneinfo（OS のデータベース）で読む。Windows には OS のデータベースがないため Windows 版の zip に `tzdata` を同梱。どちらもないときも、夏時間のないタイムゾーン（`Asia/Tokyo`・`Asia/Seoul`・`Asia/Shanghai`・`Asia/Singapore`・`Asia/Kolkata` など）と時差の書き方は読める

## 作成者・更新者の記録（`editTracking`）

プラグインが書き込む Esri のレイヤー・テーブルすべて（撮像計画の保存先・撮像依頼台帳と出力履歴・観測記録・確認範囲・分類テーブル・DB へ転記）と、QGIS で直接編集した ArcGIS フィーチャサービスのレイヤー（`layers` の `esri`、Web マップ、データソースマネージャーで追加したもの）に、作成日時・作成者・更新日時・更新者を書き込む。

- 追加: 4 つとも書く。更新（削除の印を付けるのも含む）: 更新日時・更新者だけ書く
- 作成者・更新者は ArcGIS の認証（サインインしたユーザー）ではなく、PC の環境変数 `USERNAME`（Windows のログオン名）。`userVariable` で別の環境変数に、`user` で固定の名前にできる。環境変数がないときは OS のログイン名
- 書くのはレイヤーにその属性があるときだけ（属性名の大文字小文字は区別しない）。ないレイヤーはこれまでどおり。属性はサービス側で足す（日時は日付型、作成者・更新者は文字列型。日時を文字列型にすると ISO 8601 の UTC で書く）
- 既定の属性名 `CREATED_DATE`・`CREATED_USER`・`UPDATED_DATE`・`UPDATED_USER` は、Esri の編集者トラッキングの属性（`CreationDate`・`Creator`・`EditDate`・`Editor`、`created_user`・`last_edited_user` など）とは別。編集者トラッキングを有効にした属性はサーバが認証のユーザーで上書きするので、ここには使わない
- 観測記録の `recordedBy`（記録者、`OBSERVER`）・`updatedBy`・`created`・`updated`、撮像依頼台帳の `created`・`updated` は記録の中身としてこれまでどおり別に書く
- 日時の書き方は他の属性と同じ（`timeZone` を書いたサービスはそのタイムゾーンで書く）

```jsonc
"editTracking": {
  "userVariable": "USERNAME",            // 作成者・更新者を読む環境変数（既定 USERNAME）
  "user": "",                             // 書くと環境変数より優先（任意）
  "fields": {                             // 役割 → 属性名。"" か null でその役割は書かない
    "createdAt": "CREATED_DATE", "createdBy": "CREATED_USER",
    "updatedAt": "UPDATED_DATE", "updatedBy": "UPDATED_USER"
  }
}
// "editTracking": false で何も書かない
```

## Python API

Python コンソールから `plugin = qgis.utils.plugins["satellite_observation"]` で取り、`plugin.api` を使う。観測記録はビューアのスクリプトと同じ関数を snake_case で持つ（観測記録ドックで選んだ保存先が対象）。

```python
api = plugin.api
api.observation_images()                                   # 画像の一覧（撮像日時順）
api.observe_image("d2.tif")                                # 記録する画像
rec = api.add_observation(139.7, 35.6, object="あおば", kind="船舶 > 護衛艦", activity="停泊")
api.update_observation(rec["id"], note="直した")
api.observed_things(kind="船舶")                            # モノと流れ
api.observations(start="2026-10-01", end="2026-10-31")     # 記録（時刻は ISO 文字列）
api.observation_candidates(139.7, 35.6, kind="船舶")        # 同一候補
api.add_checked_area(bbox=[139.69, 35.59, 139.72, 35.62], kind="船舶")
api.observation_report(title="週報", save="/tmp/週報.html") # 報告書（地図つき）
```

ほかに `rename_observed_thing`・`delete_observations`・`clear_observations(deleted_only=False)`（ローカルのみ、完全に消去）・`confidences`・`checked_areas`・`delete_checked_areas`。ドックそのものは `api.observation_dock`（`save_csv(path)`・`to_layers()`・`set_observer(name)`）。画像カタログは `api.image_catalog`（`search()`・`records`・`choose()`・`open_records()`・`find_similar()`・`add_layer()`）、通知は `api.notices`（`check()`・`watch_point(lon, lat)`・`store()`）、座標・地名へ移動は `api.coordinates`（`jump(text)`・`search.search(text)`・`go_to_place(place)`・`set_notation("mgrs")`）、スペクトルは `api.spectral`（`add_point(point)`・`add_box(rect)`・`series`・`save_csv(path)`）、ダッシュボードは `api.dashboard`（`figures`・`categories`・`click_value(value)`・`click_bin(i)`・`click_step(i)`・`set_heatmap(True)`・`clear_filter()`）、スワイプ比較は `api.swipe`（`set_active(True)`・`set_target(layer)`・`set_position(0.3)`・`set_orientation("horizontal")`）、位置ずらしは `api.shift`（`set_shift_metres(layer, 12, -3)`・`shift_metres(layer)`・`reset()`）、影から高さは `api.shadow_height`（`set_sun(45, 180)`・`set_time(ms)`・`measurements`・`add_layer()`）、AI結果は `api.ai_results`（`load(image_id)`・`rows`・`selected_rows()`・`import_rows(rows)`・`zoom_to(rows)`）、新規スクラッチレイヤーは `api.new_scratch_layer("目標・物体")`（組織のものは `api.new_scratch_layer("巡回記録", "config")`。`create()` で作成）。

## 起動時のレイヤー

設定ファイルの `layers`（ビューアの「起動時に読み込むレイヤー」）を、QGIS を空のプロジェクトで起動したときと「新規プロジェクト」のときに追加する。上に書いたものが下になる。メニューの「設定ファイルのレイヤーを追加」でいつでも追加でき、「設定…」の「起動時と新規プロジェクトで、設定ファイルのレイヤー（layers）を追加」で止められる。

| type | QGIS での開き方 |
| --- | --- |
| `cog` | GDAL（URL は `/vsicurl/`） |
| `file` | GeoJSON などは OGR、Shapefile の .zip は `/vsizip/`、画像・GeoTIFF は GDAL。相対パスは設定ファイルの場所から |
| `wms`・`wmts`・`xyz` | WMS プロバイダー（WMTS の `matrixSet` 省略時は GoogleMapsCompatible、XYZ の `#name=`・`zmin`・`zmax` も読む） |
| `wfs`・`ogc-features` | WFS・OAPIF プロバイダー（`filter` はレイヤーのフィルター） |
| `esri` | フィーチャーサービスは ArcGIS フィーチャーサーバー、マップ・イメージサービスは ArcGIS マップサーバーのプロバイダー |
| `wcs`・`ogc-coverage` | WCS プロバイダー・GDAL の OGCAPI ドライバー |
| `ogc-tiles` | XYZ のタイル（ベクタータイルはベクタータイルレイヤー） |

読み込みは QgsTask の中で行い、開けないレイヤーはメッセージバーに理由を出して残りを追加する。サービスの認証は「設定…」で選んだ認証設定を使う。

## 導入

1. `python3 scripts/build_zip.py` で `dist/satellite_observation-<版>.zip` を作る
2. QGIS の「プラグイン」→「プラグインの管理とインストール」→「ZIP からインストール」
3. メニュー「プラグイン」→「衛星撮像計画・観測記録」→「設定…」で設定ファイル（パスか URL）を指定し「読み込み」。問題があれば一覧に出る。設定ファイルの指定はこのメニューだけで、各ドックには出さない。読み込んだ設定ファイルに問題があると、QGIS のメッセージバーに「問題 n 件」と「設定…」ボタンを出す（同じファイル・同じ問題では繰り返さない）

### Windows 版（onnxruntime・sgp4・tzdata を同梱）

```
python3 scripts/build_zip.py --win64
```

- `dist/satellite_observation-<版>-win64.zip` を作る。中の `satellite_observation/ext/win64/` に ONNX Runtime（AI の道具用、QGIS の Python 3.12 向け）と `sgp4`（C++ 版、軌道計算が約 15 倍速い）と `tzdata`（タイムゾーンのデータベース、設定ファイルの `timeZone` 用）が入り、QGIS 側に入っていなければこちらを使う。pip を入れられない閉域の Windows でもそのまま動く
- 3 つの wheel は pip で取得して `dist/wheels` に置く（2 回目からは再利用）。閉域では `--onnxruntime-wheel onnxruntime-*-cp312-cp312-win_amd64.whl --sgp4-wheel sgp4-*-win_amd64.whl --tzdata-wheel tzdata-*-py2.py3-none-any.whl` で持ち込んだものを指定
- ONNX Runtime は推論の本体（`capi`）だけを入れ、変換・量子化の道具は除く（約 15 MB）。ライセンス文書（`LICENSE`・`ThirdPartyNotices.txt`）は同梱
- `--config` と併用可
- DLL を含む onnxruntime と sgp4 は、プラグインのフォルダーからではなく `%LOCALAPPDATA%\satellite_observation\win64\<名前>-<内容のハッシュ>` に写したものを読み込む。Windows は読み込み中の DLL を QGIS を閉じるまで掴み続けるため、プラグインのフォルダーから読むと「ZIP からインストール」での更新（Failed to unzip the plugin package）やアンインストール（Failed to remove the directory）が失敗するため。写しは中身が変わったときだけ作り直し、使われていない古い写しは消す
- この修正より前の Windows 版から更新するときは一度だけ、プラグインを無効にして QGIS を再起動してから ZIP を入れる（または QGIS を閉じて `python/plugins/satellite_observation` を消す）

### 設定ファイルを同梱して配る

画像ビューアの `config.json`（`public/config.json` など）をそのまま zip に入れて配れる。

```
python3 scripts/build_zip.py --config /path/to/image-viewer/public/config.json
```

- zip の中では `satellite_observation/config.json`（`.jsonc` ならそのまま）になる。`satellite_observation/` に `config.json` を置いて `--config` なしで作っても同じ（この場所は git の対象外）
- 受け取った人が「設定…」で設定ファイルを指定していなければ、同梱のものを読む。指定していればそちらが優先。欄を空にすると同梱のものに戻る。「設定…」の表示は「同梱の設定ファイルを使用」
- 作るときに設定ファイルを読んで確かめ、読めない・問題があるときは zip を作らない。`token` が書いてあれば注意を出す（zip を受け取った人全員に渡るため。サインインが要るサービスは各自の QGIS の認証設定を使う方がよい）
- プラグインを入れ直すと同梱の設定ファイルも新しい zip のものに置き換わる。各自の指定（`QgsSettings`）は残る

#### 同梱の設定ファイルに固定する（`--lock-config`）

```
python3 scripts/build_zip.py --config /path/to/config.json --lock-config
python3 scripts/build_zip.py --config /path/to/config.json --lock-config --win64
```

- 受け取った人は同梱の設定ファイルしか使えない。「設定…」の設定ファイル欄は同梱のファイルを表示するだけで変えられず（「参照…」は押せない、「読み込み」は同梱のものを読み直す）、前に指定したパス・URL があっても無視する。「設定…」の表示は「同梱の設定ファイルに固定」
- 記録者とサービスごとの認証設定はこれまでどおり各自で選べる
- 仕組み: zip に設定ファイルと並べて `satellite_observation/config.lock` を入れる。プラグインは `config.lock` と `config.json`（または `config.jsonc`）が両方あるときだけ固定する（`config.lock` だけなら何もしない）。`satellite_observation/` に `config.json` と `config.lock` を置いて `--config` なしで作っても固定になる（どちらも git の対象外）
- 設定ファイルなしで `--lock-config` を付けると zip を作らない
- 固定を外すには `--lock-config` なしで作った zip を入れ直す（またはプラグインのフォルダの `config.lock` を消す）。各自が前に指定していたファイルがあれば、またそちらを読む

## 設定

| 項目 | 保存先 |
| --- | --- |
| 設定ファイルのパス・URL、記録者、サービスごとの認証設定 | `QgsSettings`（`satellite_observation/…`） |
| 同梱の設定ファイル（指定がないときに読む） | プラグインのフォルダーの `config.json`（または `config.jsonc`） |
| 同梱の設定ファイルへの固定（`--lock-config`） | プラグインのフォルダーの `config.lock` |
| 観測記録・確認範囲・分類体系・写真・新着画像の監視と通知（ローカル） | ユーザープロファイルの `satellite_observation/observations.gpkg` |
| URL で指定した AI のモデル | ユーザープロファイルの `ai_models/` |
| `pathMappings` で選んだフォルダ、類似画像の許容差、カーソル位置の表記、新規スクラッチレイヤーの保存済みテンプレート、Web マップのポータル | `QgsSettings` |

設定ファイルはビューアの `config.json` をそのまま読む（コメント付き JSON も可、ほかの項目は無視）。読む項目と書き方は[設定ファイルの書き方](#設定ファイルの書き方)。

認証: ArcGIS のサービスごとに QGIS の認証設定（OAuth2・ESRI token・Basic など）を「設定…」の表で選ぶ。設定ファイルの `token` も使えるが、認証設定を選んだサービスでは送らない。トークンや認証情報はログ・CSV・レイヤー・プロジェクトファイルに残さない。

## 設定ファイルの書き方

プラグインが読む設定ファイル（`config.json`）の書き方。ビューアの `config.json` と共用できるが、プラグインだけの項目・読み方の違いが増えたので、**プラグインが実際に読む項目**をここにまとめる（`satellite_observation/core/config.py` の `KEYS` と各項目の読み込み処理が元）。各機能の細かい動きは、表の「詳しく」の節を参照。

### 設定ファイル作成ツール（`tools/config_builder.html`）

ブラウザで開くだけで使える設定ファイルの作成・編集ツール（サーバー・ネットワーク・インストール不要、閉じたネットワークでも動く）。

- 左の項目を選んで入力すると、右に `config.json` ができていく。「config.json を保存」で書き出し、プラグインのメニュー「設定…」で読み込む
- 「開く…」で既存の設定ファイル（JSONC も可）を読み込んで直せる。保存するとコメントは消える。プラグインが読まない項目（ビューアだけの項目）はそのまま残す
- 必須の項目・属性名の形・数の範囲・重複などを「確認」に出す（最後はプラグインの「設定…」の問題の一覧で確かめる）
- 撮像依頼の日次出力（`requestExports`、オーダー用ファイル）: CSV の列（`columns`）を表で、JSON の JSON Schema（`x-source` など）を木で組める。システムから受け取ったスキーマを読み込んで `x-source` を書き添え、`.schema.json` として保存もできる。架空の依頼 2 件での出力の見本と、スキーマでの検査結果を出す
- 入力途中の内容はブラウザに残り、次に開いたとき続きから
- 項目の役割・選択肢はプラグインの定数の写し。プラグインを変えたら `python3 -m satellite_observation.tests.test_config_builder` で更新する（テストが食い違いを見つける）

### 読み込みと基本の決まり

- 指定: メニュー「プラグイン」→「衛星撮像計画・観測記録」→「設定…」で、設定ファイルのパスか URL を選んで「読み込み」。問題があれば一覧に出る。指定がなければプラグインのフォルダーに同梱の `config.json`（または `config.jsonc`）を読む（[設定ファイルを同梱して配る](#設定ファイルを同梱して配る)、固定するなら [`--lock-config`](#同梱の設定ファイルに固定する--lock-config)）
- 形式: UTF-8 の JSON。コメント（`//`・`/* */`）と末尾のカンマも可（JSONC）。いちばん外はオブジェクト
- 知らない項目は無視する（ビューアだけの項目があってもよい）。項目の値が誤っていればその項目（配列なら誤った要素だけ）を既定に戻し、理由を問題の一覧に出す。設定ファイルが壊れていてもプラグインは起動する
- 相対パス・相対 URL（`./`・`../`）は設定ファイルの場所が基準（`layers`・`baseMaps`・`movingFeeds`・`aiModels` など）
- `label`（画面に出す名前）は省略可。省略すると「カタログ 1」のような名前

多くのサービスの項目に共通する書き方:

| 項目 | 内容 |
| --- | --- |
| `label` | 一覧・メニューに出す名前 |
| `url` | ArcGIS のレイヤーかテーブルの URL（`…/FeatureServer/0` など） |
| `fields` | `{ 役割: 属性名 }`。属性名は英数字と `_`。書かない役割は既定の属性名（既定のある項目）か、使わない |
| `where` | 対象を絞る SQL の条件（任意） |
| `token` | ArcGIS のトークン（任意）。各自の QGIS の認証設定を「設定…」で選んだサービスには送らない。配る設定ファイルには書かない方がよい |
| `timeZone`・`serviceTimeZone` | そのサービスの日時の本当のタイムゾーン（[日時のタイムゾーン](#日時のタイムゾーンtimezonetimezones)） |

### 最小の例

```jsonc
{
  // 画像カタログ（必須なのは url・fields.source）
  "imageCatalogs": [
    { "label": "衛星画像", "url": "https://gis.example/arcgis/rest/services/Catalog/FeatureServer/0",
      "fields": { "id": "IMG_ID", "acquired": "ACQ_TIME", "sensor": "SENSOR", "source": "PATH" } }
  ],
  // 衛星（TLE）。撮像計画に必要
  "satelliteCatalogs": [
    { "label": "衛星", "url": "https://gis.example/arcgis/rest/services/Sat/FeatureServer/0",
      "fields": { "name": "NAME", "tle1": "TLE1", "tle2": "TLE2", "swath": "SWATH_KM" } }
  ],
  // 観測記録を Esri に保存（書かなければローカルの GeoPackage だけ）
  "observationStores": [
    { "label": "共有の観測記録", "url": "https://gis.example/arcgis/rest/services/Obs/FeatureServer/0" }
  ]
}
```

### 設定ファイルに書かないもの

- 設定ファイルのパス・URL、記録者、サービスごとの認証設定、`pathMappings` で選んだフォルダなどは各自の QGIS に保存する（下の[設定](#設定)の表）
- ZIP に同梱・固定するかどうかは設定ファイルの項目ではなく、ZIP を作るときの `--config`・`--lock-config`（[導入](#導入)）
- 増えたり変わったりする対応表などのデータは、設定ファイルではなく Esri のテーブル・レイヤーに置き、設定ファイルには属性名・テーブルの URL だけを書く（分類体系の `taxonomyTable` など）

ビューアとの違い（プラグインだけの項目、ビューアと読み方が違う項目）は [docs/differences.md](docs/differences.md)。

## 構成

```
satellite_observation/
  core/      純 Python（Qt / QGIS に依存しない）: 設定・Esri・GeoPackage・撮像計画・観測記録・AI の前後処理（NumPy）
  ext/       同梱の純 Python 版 sgp4（Windows 版の zip では win64/ に onnxruntime と C++ 版 sgp4 と tzdata も）
  qgis_io/   QGIS の通信（QgsNetworkAccessManager）・QgsTask・設定・画像補正のレンダラー・パンシャープンのファイル処理
  processing_provider/  Processing のアルゴリズム（パンシャープン・物体検出・AI 学習・教師データセットほか）
  ui/        ドック・ダイアログ
  tests/     pytest
tools/
  config_builder.html  設定ファイル作成ツール（ブラウザで開く）
```
